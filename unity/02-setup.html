    02 · 环境搭建与第一个项目

    这一章的目标只有一个：让你在 2 小时内跑起来一个能玩的东西。 听起来简单，但新手在这一步卡住的比例高得惊人——不是因为你笨， 而是因为版本选择、IDE 配置、包管理这三件事上，官方文档和网上教程给的建议经常互相矛盾。

    阶段目标 约 1 天，6–8 小时。结束时你能：独立创建一个 URP 项目、配置好 IDE 智能提示、 用脚本控制一个物体移动、在 Console 看到自己的日志、并知道出问题时该去哪里找原因。

    一、先定版本：别用最新版

    这是第一个反直觉的建议。做商业项目，永远选 LTS（长期支持版），不要选 Tech Stream（技术预览版）。

    版本类型命名规律该不该用原因
    LTS 2022.3.x 用这个 两年支持周期，只修 bug 不加特性，第三方插件都适配过
    Tech Stream 2023.1 / 2023.2 项目别用 新特性尝鲜，但 API 会变、插件可能不兼容、有未知 bug
    Unity 6 6000.x 看情况 已成为新的 LTS 主线，新项目可用；但要注意大量 API 改名
    怎么选，一句话 2025 年新开项目：Unity 6000.x LTS 或 2022.3 LTS 都可以。 接手已有项目：必须用项目原本的版本，不要升级——升版本是独立的、有风险的工作。 跟着某个教程学：用它指定的版本，否则你会把大量时间花在"为什么我的界面和他不一样"上。

    二、安装：Unity Hub 是唯一入口

    现在装 Unity 必须通过 Unity Hub，官网不再提供独立的安装包。 这是好事——Hub 能让你同时管理多个版本，而你迟早会需要这个能力（不同项目锁不同版本）。

    安装步骤

    安装时必须勾选的模块

    ① Documentation：离线文档。断网或网络差时能救命，体积不大，勾上。

    ② 目标平台支持：你要发布到哪个平台就勾哪个。做手游勾 Android Build Support（含 SDK/NDK/JDK）， 做 PC 勾 Windows Build Support。注意：漏勾平台支持，后期补装要重新下载整个模块。

    ③ 不要勾 Visual Studio（如果你已经装了的话）。Hub 会装一个捆绑版 VS，版本旧、还可能和你现有的冲突。 单独去官网下最新版 VS Community 更省事。

    三、IDE 配置：让智能提示真正可用

    这一步没配好，你后面写代码的效率会低一半。 常见症状是：Unity 里能跑的代码，IDE 里全是红波浪线；或者按下"跳转到定义"没反应。

    方案 A：Visual Studio（Windows 首选）

    红波浪线的三种常见原因 ① 没生成 .csproj：点一下上面的 "Regenerate project files" 通常就好了。
    ② IDE 打开了错误的 .sln：项目根目录有多个 .sln 时，认准和项目同名的那个。
    ③ Unity 正在编译：等编译完成（右下角转圈结束）再切回 IDE，否则看到的是过期快照。

    方案 B：JetBrains Rider（强烈推荐）

    Rider 对 Unity 的支持明显好于 VS：能识别 Unity 特有 API、内联显示 SerializeField 的值、 直接提示"这个字段在 Inspector 里没赋值"、Profiler 深度集成。 对个人开发者有免费许可（非商业用途），公司使用需要付费。

    四、创建项目：选哪个模板

    Unity 的项目模板决定了初始配置。选错了后期改起来很麻烦（尤其是渲染管线，迁移成本高）。

    模板渲染管线适用说明
    Universal 2D URP 2D 游戏 正交相机、2D 光照、Sprite 工具链已配好
    Universal 3D URP 手游 / 中低配 3D 性能友好，跨平台好，移动端首选
    3D (Built-in) Built-in 老教程 / 简单项目 官方已不推荐新项目使用，但大量老教程基于它
    HDRP HDRP PC / 主机高画质 画面上限高，但配置复杂、移动端基本用不了
    渲染管线选型是没有回头路的 Built-in 和 URP 之间的迁移不是改个设置就完事——材质、Shader、后处理全都要重做。 新项目一律用 URP（除非你明确要做 PC 高画质，那就 HDRP）， 学教程时如果教程用 Built-in，注意区分哪些代码是通用的、哪些是管线相关的。

    五、跑通第一个可玩场景

    不要一上来就学理论。先做出一个能动的东西，再回头理解原理—— 这样学到的每个概念都有具体的挂靠点。

    30 分钟做出一个"能玩"的场景

    关于"亲手敲一遍" 下面的代码请手敲，不要复制粘贴。 手敲的过程中你会遇到编译错误、拼写错误、忘记分号——这些错误正是学习的一部分。 而且要建立"先看 IDE 报什么错、再看 Unity Console 报什么错"的条件反射。

    你的第一个脚本

    using UnityEngine;

// 类名必须和文件名完全一致（区分大小写）
public class PlayerMove : MonoBehaviour
{
    // [SerializeField] 让 private 字段显示在 Inspector 里
    // 这是 Unity 的最佳实践：既保持封装，又能让策划调参
    [SerializeField] private float _moveSpeed = 5f;

    // 缓存组件引用：绝不在 Update 里反复调 GetComponent
    private Rigidbody _rb;

    // Awake 在对象创建时调用一次，适合做自身初始化
    private void Awake()
    {
        _rb = GetComponent<Rigidbody>();
    }

    // Update 每帧调用一次，适合读输入
    private void Update()
    {
        // GetAxisRaw 返回 -1 / 0 / 1，不做平滑；用 GetAxis 会有缓动
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");

        // 组合成方向向量，ClampMagnitude 防止斜向移动更快
        Vector3 dir = Vector3.ClampMagnitude(new Vector3(h, 0f, v), 1f);

        if (dir.sqrMagnitude > 0.001f)
        {
            // 让物体朝向移动方向
            transform.forward = dir;

            // 用 MovePosition 而不是直接改 position：
            // 前者走物理系统，能正确触发碰撞；后者会"穿模"
            Vector3 next = _rb.position + dir * (_moveSpeed * Time.fixedDeltaTime);
            _rb.MovePosition(next);
        }
    }
}
    三个新手必踩的坑 ① 文件名和类名不一致 → Unity 报 "Can't add script component"， 这是最常见的新手错误。
    ② 忘记挂脚本 → 代码没错，但没有任何反应。检查 Inspector 上真的有这个组件。
    ③ 直接改 transform.position → 物体能穿过墙壁。用 MovePosition + Rigidbody 才走物理。

    六、出问题时的排查顺序

    这一节比前面所有内容都重要。 新手和熟手的差距，很大程度上体现在"遇到问题时知道去哪看"。

    按这个顺序排查，能解决 90% 的问题

    第 1 步：看 Unity Console（Ctrl+Shift+C）
    红色是错误（必须解决，代码根本不会运行），黄色是警告（可以运行，但可能出问题）， 白色是普通日志。点开错误信息，双击能直接跳到出错的代码行。

    第 2 步：看 IDE 的错误列表
    Unity Console 有时只报"脚本编译失败"，具体原因要去 IDE 的 Error List 看。 两边都看，才不容易漏。

    第 3 步：确认脚本真的挂上去了
    选中目标对象，看 Inspector 里有没有你的组件。 "代码没问题但没效果"十有八九是这个问题。

    第 4 步：加日志确认代码真的执行了
    在方法开头加 Debug.Log("到这里了")。 没打印出来说明方法根本没被调用——那问题就不在方法内部，而在调用时机或对象状态上。

    第 5 步：用断点单步调试
    在 IDE 里给行号左边点一下打断点，然后在 Unity 里点 Play → 在 IDE 里点"附加到 Unity"（Attach to Unity）。这是唯一能看清"变量到底是多少"的方法。

    一个能省下大量时间的习惯 遇到问题时，先读完整条错误信息，再搜索。 很多人看到红色就慌了，直接复制一半去搜。
    Unity 的错误信息通常写得很清楚，包含文件名、行号、错误类型、原因。 把 CS 开头的错误码（如 CS0103）连同错误信息一起搜，命中率最高。

    七、本章动手任务

    本章过关标准：
    ① 能不看文档说清楚 LTS 和 Tech Stream 的区别，以及为什么项目要用 LTS；
    ② 遇到"红波浪线 / 脚本无响应 / 物体穿墙"这三类问题时，知道各自的排查入口；
    ③ 能在 IDE 里成功附加调试器并单步执行；
