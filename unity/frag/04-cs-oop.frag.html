04 · 面向对象与接口

面向对象不是"把代码写进类里"。它的真正价值是控制变化的传播范围——改一个需求，你希望只动一个文件，而不是全局搜索替换 50 处。这一页讲的是怎么用 OOP 的四个工具（封装、继承、多态、接口）来实现这件事。

阶段目标 约 1.5 周，35 小时。结束时你能：解释 virtual/override/new 的区别、说清接口和抽象类各自的适用场景、知道 Unity 为什么推崇"组合优于继承"、能自己设计一个可扩展的模块结构。

一、封装的真实价值

教科书说封装是"隐藏内部实现"。这没说错，但太抽象。封装的实际收益是：把"可能变化的东西"和"不该受影响的东西"隔开。

using UnityEngine;

// ============================================================
//  反例：所有状态都是 public，外部可以任意修改
// ============================================================
public class PlayerBad : MonoBehaviour
{
    public float hp = 100f;
    public float maxHp = 100f;
    public int level = 1;
}

// 问题：
// 1) 外部可以写 player.hp = 99999f;   绕过所有规则
// 2) 血条 UI 无法知道"血量什么时候变了"，只能每帧轮询
// 3) 想加"血量变化时播特效"，得去改所有修改 hp 的地方

// ============================================================
//  正例：用属性把规则集中到一处
// ============================================================
public class PlayerGood : MonoBehaviour
{
    [SerializeField] private float _maxHp = 100f;
    [SerializeField] private float _hp = 100f;
    [SerializeField] private int _level = 1;

    // 血量变化时通知外部，而不是让外部轮询
    public event System.Action<float, float> HpChanged;   // (current, max)
    public event System.Action<int> LevelChanged;

    public float Hp
    {
        get { return _hp; }
        set
        {
            // 规则集中在这里：钳制、去重、发通知
            float clamped = Mathf.Clamp(value, 0f, _maxHp);
            if (Mathf.Approximately(clamped, _hp)) return;   // 值没变就不通知

            _hp = clamped;
            HpChanged?.Invoke(_hp, _maxHp);

            if (_hp <= 0f) OnDeath();
        }
    }

    public float MaxHp
    {
        get { return _maxHp; }
        set
        {
            _maxHp = Mathf.Max(1f, value);
            Hp = _hp;   // 触发一次钳制，防止当前血量超过新上限
        }
    }

    public int Level
    {
        get { return _level; }
        set
        {
            int v = Mathf.Max(1, value);
            if (v == _level) return;
            _level = v;
            LevelChanged?.Invoke(_level);
        }
    }

    private void OnDeath() { Debug.Log("死亡"); }
}
Unity 的序列化与封装的平衡 Unity 只序列化字段，不序列化属性。所以你会看到上面的写法：[SerializeField] private 字段 + 公开属性。
这样既能在 Inspector 里调参，又能保证外部只能通过属性修改——这是 Unity 项目的标准范式。
不要为了方便就把字段写成 public。Inspector 可见和 public 是两件事，用 [SerializeField] 就能兼得。

二、继承与多态

virtual / override / new 的区别（高频面试题）

这三个关键字看起来相似，但行为完全不同。搞混它们会导致"调用了错误的实现"这种极难排查的 bug。

using UnityEngine;

public class Animal
{
    public virtual void Speak() { Debug.Log("..."); }
}

public class Dog : Animal
{
    public override void Speak() { Debug.Log("Woof"); }
}

public class Cat : Animal
{
    public new void Speak() { Debug.Log("Meow"); }   // new：隐藏，不是多态
}

public class PolyDemo : MonoBehaviour
{
    private void Start()
    {
        Animal a1 = new Dog();
        a1.Speak();          // Woof  <- 虚方法表动态派发，走 Dog 的实现

        Animal a2 = new Cat();
        a2.Speak();          // ...   <- new 只做静态隐藏，仍走 Animal 的实现！

        Cat c = new Cat();
        c.Speak();           // Meow  <- 静态类型是 Cat，走 Cat 的实现
    }
}
对比项overridenew
机制虚方法表（vtable）动态派发编译期按变量的静态类型解析
基类引用调用执行子类实现执行基类实现
Unity 中的使用覆盖 Update 逻辑、AI 状态基类几乎不用，容易埋 bug
编译警告无无。但不写 new 时会报 CS0114 警告
上面代码的输出是反直觉的 Animal a2 = new Cat(); a2.Speak(); 输出的是 "..."，不是 "Meow"。
因为 new 只做静态隐藏：编译器看变量的声明类型是 Animal，就绑定到 Animal.Speak。
这就是为什么实战中几乎不用 new 来"覆盖"方法。要覆盖就用 override。
CS0114 与 CS0108：两个容易搞混的警告 这两个警告都与「子类成员隐藏了基类同名成员」有关，但触发条件不同：
写法编译器行为
public override void F()正常，无警告
public new void F()正常，无警告（显式声明了隐藏意图）
public void F()（不写任何关键字）warning CS0114：提示「隐藏了继承的成员，请添加 override 或 new」
所以：
• 写了 new 就不会有警告——因为编译器认为你是故意的；
• 只有忘记写关键字时才会得到 CS0114。

CS0108 是另一个场景：当基类成员不是 virtual 时，子类写同名成员会产生 CS0108。
本页的对比表针对的是 override 与 new 的语义差异，不是警告本身。

抽象类：定义"必须实现什么"

using UnityEngine;

// ============================================================
//  抽象基类：不能实例化，可以有实现
// ============================================================
public abstract class Actor : MonoBehaviour
{
    public string ActorName { get; protected set; }
    public float Hp { get; protected set; }

    public abstract void Tick(float dt);          // 必须被子类实现

    public virtual void TakeDamage(float dmg)     // 可以被子类覆盖
    {
        Hp -= dmg;
        if (Hp <= 0f) OnDeath();
    }

    protected virtual void OnDeath()
    {
        Debug.Log(ActorName + " died");
    }
}

// ============================================================
//  派生类
// ============================================================
public sealed class PlayerActor : Actor        // sealed：不能再被继承
{
    [SerializeField] private float _moveSpeed = 5f;

    private void Awake()
    {
        ActorName = "Player";
        Hp = 100f;
    }

    public override void Tick(float dt)
    {
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");
        transform.Translate(new Vector3(h, 0f, v) * (_moveSpeed * dt), Space.World);
    }

    public override void TakeDamage(float dmg)
    {
        base.TakeDamage(dmg * 0.8f);              // 调用基类实现（减伤 20%）
    }
}
Unity 的一个限制：抽象 MonoBehaviour 不能挂载 继承自 MonoBehaviour 的抽象类不能直接挂到 GameObject 上（Unity 会拒绝）。
但它可以作为 [SerializeField] 字段的类型来接收子类实例——这是 Unity 里"多态序列化"的标准做法。
不过要注意：普通 [SerializeField] 用在抽象类字段上，Unity 会按声明的类型序列化，子类新增字段会丢失。需要真正的多态序列化要用 [SerializeReference]（Unity 2019.3+）。

三、接口：能力契约

using UnityEngine;

public interface IDamageable
{
    float CurrentHp { get; }
    bool IsDead { get; }
    void TakeDamage(float amount);
}

public class Crate : MonoBehaviour, IDamageable
{
    [SerializeField] private float _hp = 30f;

    public float CurrentHp { get { return _hp; } }
    public bool IsDead { get { return _hp <= 0f; } }

    public void TakeDamage(float amount) { _hp -= amount; }
}

// ============================================================
//  用接口解耦（Unity 核心技巧）
// ============================================================
public class Weapon : MonoBehaviour
{
    [SerializeField] private float _damage = 10f;

    public void Fire(Vector3 origin, Vector3 dir)
    {
        // TryGetComponent 支持接口类型 T，且不产生 GC（Unity 2019.2+）
        if (Physics.Raycast(origin, dir, out RaycastHit hit, 100f))
        {
            if (hit.collider.TryGetComponent(out IDamageable target))
            {
                target.TakeDamage(_damage);
            }
        }
    }
}
维度 接口 interface 抽象类 abstract class
多重实现 可以 一个类能实现多个接口 不行 只能继承一个类
实例字段 不能有 可以有
构造函数 没有 有
方法实现 C# 8 默认接口实现 Unity 不支持 可以 有默认实现
Inspector 引用 不能直接序列化 可以 拖入子类实例
适用场景 能力契约：可被伤害、可交互、可存档 同类事物的公共基类：敌人、UI 面板
C# 8 的默认接口实现在 Unity 中不可用 这是Unity 的硬限制：Mono 运行时没有实现这个特性，即使 Unity 支持 C# 8 语法。
语法能编译，但运行时会报错。所以：不要在 Unity 里给接口写默认方法实现——需要共享代码逻辑就用抽象类或扩展方法。

四、组合优于继承 ★

这是 Unity 最核心的设计哲学，也是从"会写代码"到"会设计"的分水岭。

继承方案（会爆炸） 组合方案（Unity 的方式）
结构 Enemy → FlyingEnemy → FlyingEnemyWithShield → … GameObject 挂多个独立组件
新增能力 要新建一个子类，继承链越拉越长 挂一个新组件，不影响其他
能力组合 会飞的、有盾的、会治疗的 → 需要 2^n 个子类 任意组合，各组件独立工作
代码复用 靠基类，父类一改所有子类受影响 靠组合，组件之间解耦
调试 要沿着继承链向上找 看 Inspector 就知道这个对象有什么能力 
using UnityEngine;

// ============================================================
//  反例：用继承实现敌人（很快会失控）
// ============================================================
public class EnemyBase : MonoBehaviour { }
public class FlyingEnemy : EnemyBase { }
public class ShieldFlyingEnemy : FlyingEnemy { }
public class HealingShieldFlyingEnemy : ShieldFlyingEnemy { }
// 每加一种能力就多一层。
// 想要"会治疗的陆地敌人"？再开一条继承链。

// ============================================================
//  正例：用组件组合（Unity 的方式）
// ============================================================
// GameObject "FlyingShieldEnemy" 上挂：
//   - Health.cs        负责血量与受伤
//   - FlyMover.cs      负责飞行移动
//   - Shield.cs        负责护盾减伤
//   - Healer.cs        负责治疗队友
//
// 想要"会治疗的陆地敌人"？挂 Health + WalkMover + Healer 就行，零新增代码。

// ============================================================
//  组件之间怎么通信？用接口而不是具体类型
// ============================================================
public interface IMover
{
    void Move(Vector3 direction, float deltaTime);
}

public interface IDamageable
{
    float CurrentHp { get; }
    void TakeDamage(float amount);
}

// 具体组件实现接口
public class WalkMover : MonoBehaviour, IMover
{
    [SerializeField] private float _speed = 3f;

    public void Move(Vector3 direction, float deltaTime)
    {
        transform.position += direction * (_speed * deltaTime);
    }
}

public class FlyMover : MonoBehaviour, IMover
{
    [SerializeField] private float _speed = 5f;
    [SerializeField] private float _hoverAmplitude = 0.3f;

    private float _phase;

    public void Move(Vector3 direction, float deltaTime)
    {
        _phase += deltaTime * 2f;
        Vector3 offset = direction * (_speed * deltaTime);
        offset.y += Mathf.Sin(_phase) * _hoverAmplitude * deltaTime;
        transform.position += offset;
    }
}

// 使用者只依赖接口，不关心具体是走还是飞
public class EnemyController : MonoBehaviour
{
    private IMover _mover;

    private void Awake()
    {
        // 这两个组件挂哪个都行，控制器代码完全不用改
        _mover = GetComponent<IMover>();
    }

    private void Update()
    {
        if (_mover != null)
        {
            Vector3 dir = new Vector3(Input.GetAxisRaw("Horizontal"), 0f, Input.GetAxisRaw("Vertical"));
            _mover.Move(dir.normalized, Time.deltaTime);
        }
    }
}
判断该用继承还是组合的三个问题 ① 是"是一种"还是"有一个"？狗"是一种"动物 → 继承；狗"有一个"项圈 → 组合。实战中"有一个"的情况占绝大多数。
② 这个能力需要和别的能力自由组合吗？需要 → 组合。继承的致命弱点是组合爆炸。
③ 我需要复用代码还是复用接口？只想约定"能做什么" → 接口；想共享实现 → 抽象类或组合。
经验法则：继承链不要超过两层。超过两层就该考虑改成组合了。

五、扩展方法：给 Unity 类型加功能

Unity 的很多内置类型（Vector3、Transform）你无法修改源码。但你可以用扩展方法给它们"添加"方法——这是让代码更易读的高性价比技巧。

using UnityEngine;

public static class TransformExtensions
{
    // 扩展方法：静态类 + 静态方法 + 第一个参数带 this
    public static Vector3 Flat(this Vector3 v)
    {
        return new Vector3(v.x, 0f, v.z);
    }

    public static float SqrDistanceTo(this Vector3 a, Vector3 b)
    {
        return (a - b).sqrMagnitude;
    }

    // 递归查找子物体
    public static Transform FindRecursive(this Transform parent, string name)
    {
        for (int i = 0; i < parent.childCount; i++)
        {
            Transform child = parent.GetChild(i);
            if (child.name == name) return child;

            Transform result = child.FindRecursive(name);
            if (result != null) return result;
        }
        return null;
    }

    // 清空所有子物体
    public static void DestroyAllChildren(this Transform parent)
    {
        for (int i = parent.childCount - 1; i >= 0; i--)
        {
            Object.Destroy(parent.GetChild(i).gameObject);
        }
    }
}

public class ExtDemo : MonoBehaviour
{
    private void Start()
    {
        Vector3 flat = transform.position.Flat();
        float d2 = transform.position.SqrDistanceTo(Vector3.zero);
        Transform t = transform.FindRecursive("Head");
        Debug.Log(flat + " " + d2 + " " + t);
    }
}
扩展方法的三个限制 ① 不能访问私有成员：它本质是静态方法，只是语法上像实例方法。
② 不能参与多态：它不会"覆盖"实例方法。如果与实例方法同名同签名，实例方法优先，扩展方法被忽略。
③ 必须放在静态类里：方法必须是 static，第一个参数前加 this。
实践建议：把扩展方法按用途分组放不同文件（VectorExtensions.cs、TransformExtensions.cs），避免一个文件里堆几百个方法。
