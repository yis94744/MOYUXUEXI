这一页在路线中的位置 上一页（11）的生命周期告诉你物理回调什么时候触发。这一页告诉你为什么会触发、什么时候不该触发。
关键衔接：页 09 学的 向量运算在这里大量使用——射线方向、力的大小、法线反弹都是向量。

一、Rigidbody 与力的四种模式 ★

物理系统里最容易搞混的就是 ForceMode。很多人只知道默认的 AddForce，不知道还有三种模式，结果做出来的手感总是差一点。

using UnityEngine;

// ============================================================
//  物理系统基础：Rigidbody 与力的三种施加方式
// ============================================================
public class PhysicsBasic : MonoBehaviour
{
    [SerializeField] private float _moveForce = 10f;
    [SerializeField] private float _jumpForce = 5f;

    private Rigidbody _rb;
    private bool _grounded;

    private void Awake()
    {
        _rb = GetComponent<Rigidbody>();

        // 【必改项】消除视觉抖动
        // FixedUpdate 的频率与渲染帧率不同步，
        // 不做插值的话物体看起来会一顿一顿
        _rb.interpolation = RigidbodyInterpolation.Interpolate;

        // 高速物体防穿透
        _rb.collisionDetectionMode = CollisionDetectionMode.ContinuousDynamic;
    }

    // ============================================================
    //  物理操作必须在 FixedUpdate
    // ============================================================
    private void FixedUpdate()
    {
        // ---------- 方式 1：AddForce（施加力，有惯性和质量感）----------
        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");

        Vector3 force = new Vector3(h, 0f, v) * _moveForce;

        // ForceMode 的四种模式（这是物理题的高频考点）
        _rb.AddForce(force);                                  // 默认：持续力，受质量影响
        _rb.AddForce(force, ForceMode.Force);                 // 同上，显式写法
        // _rb.AddForce(force, ForceMode.Acceleration);       // 不受质量影响
        // _rb.AddForce(force, ForceMode.Impulse);            // 瞬时冲量，受质量影响
        // _rb.AddForce(force, ForceMode.VelocityChange);     // 瞬时速度变化，不受质量影响
    }

    // ============================================================
    //  方式 2：直接设置 velocity（可控、即时响应）
    // ============================================================
    private void SetVelocityDemo()
    {
        // 水平速度直接设定，垂直速度保留（防止影响下落）
        Vector3 vel = _rb.velocity;
        vel.x = Input.GetAxis("Horizontal") * 5f;
        vel.z = Input.GetAxis("Vertical") * 5f;
        _rb.velocity = vel;
    }

    // ============================================================
    //  方式 3：MovePosition（Kinematic 刚体的标准做法）
    // ============================================================
    private void MovePositionDemo()
    {
        // 【重要】isKinematic 开启后 velocity 不再驱动移动，必须用 MovePosition
        if (_rb.isKinematic)
        {
            _rb.MovePosition(_rb.position + Vector3.forward * (Time.fixedDeltaTime * 3f));
        }
    }

    // ---------- 跳跃：用 Impulse 模式 ----------
    public void Jump()
    {
        if (!_grounded) return;

        // Impulse 是瞬时冲量，适合跳跃、爆炸
        _rb.AddForce(Vector3.up * _jumpForce, ForceMode.Impulse);
        _grounded = false;
    }

    // ---------- 旋转：用 Torque 或 MoveRotation ----------
    public void Spin(float degreesPerSecond)
    {
        // 角速度（弧度/秒）
        _rb.angularVelocity = Vector3.up * (degreesPerSecond * Mathf.Deg2Rad);
    }

    public void ResetMotion()
    {
        // 停止所有运动
        _rb.velocity = Vector3.zero;
        _rb.angularVelocity = Vector3.zero;
    }
}

// ============================================================
//  ForceMode 四种模式的完整对比
// ============================================================
//                  受 mass 影响   持续时间
//  Force              是          持续
//  Acceleration       否          持续
//  Impulse            是          瞬时
//  VelocityChange     否          瞬时
//
//  选择依据：
//    持续推力（火箭、风）        -> Force
//    想忽略质量做统一加速        -> Acceleration
//    跳跃、爆炸、击退            -> Impulse
//    想直接设定速度变化量        -> VelocityChange
//
//  公式关系：
//    Impulse = Force * fixedDeltaTime
//    VelocityChange = Impulse / mass
ForceMode 的四个模式，一次说清
模式受 mass 影响持续时间典型用途
Force是持续火箭推力、风力、持续加速
Acceleration否持续想让所有物体产生同样加速度
Impulse是瞬时跳跃、爆炸、击退
VelocityChange否瞬时直接设定速度变化量
记忆方法：带 Acceleration 和 VelocityChange 的不受质量影响（因为它们描述的是"加速度"和"速度变化"，本质与质量无关）。
公式关系：Impulse = Force x fixedDeltaTime，VelocityChange = Impulse / mass。
velocity 与 AddForce 怎么选 用 velocity：需要精确控制和即时响应（角色移动、平台跳跃）。缺点是会覆盖物理计算，失去部分物理感。
用 AddForce：需要物理感和惯性（爆炸冲击、被击退、载具）。缺点是难以精确控制最终位置。
不要混用：同时用两者会互相干扰，导致行为难以预测。按模块统一选一种。

二、射线检测 ★

射线检测是游戏里使用频率最高的物理功能——射击、点击拾取、AI 视线、地面检测、寻路障碍判断都靠它。也因此，它是性能优化的重点区域。

using UnityEngine;
using System.Collections.Generic;

// ============================================================
//  射线检测：从基础到零分配
// ============================================================
public class RaycastDemo : MonoBehaviour
{
    [SerializeField] private float _maxDistance = 100f;
    // 默认值 -1 等于「所有层」，实际项目在 Inspector 里指定具体层
    [SerializeField] private LayerMask _groundMask = ~0;

    // 预分配缓冲区，全程复用（零分配的关键）
    private readonly RaycastHit[] _hits = new RaycastHit[16];
    private readonly RaycastHit[] _sphereHits = new RaycastHit[8];

    private void Update()
    {
        // ---------- 基础射线：返回最近的命中 ----------
        // 这是最常用的形式，本身就是零分配的
        Ray ray = new Ray(transform.position, transform.forward);

        if (Physics.Raycast(ray, out RaycastHit hit, _maxDistance, _groundMask,
                            QueryTriggerInteraction.Ignore))
        {
            Debug.Log("命中 " + hit.collider.name +
                      " 距离 " + hit.distance +
                      " 点 " + hit.point +
                      " 法线 " + hit.normal);
        }

        // 等价写法：直接传起点和方向
        if (Physics.Raycast(transform.position, Vector3.down, out RaycastHit ground, 10f))
        {
            Debug.Log(ground.point);
        }

        // ---------- 多次命中：用 NonAlloc ----------
        int count = Physics.RaycastNonAlloc(
            transform.position, Vector3.forward, _hits, _maxDistance, ~0,
            QueryTriggerInteraction.Ignore);

        if (count == _hits.Length)
        {
            // 【重要】缓冲区满了说明结果被截断
            Debug.LogWarning("射线缓冲已满，结果可能不完整");
        }

        // NonAlloc 不保证排序，需要自己排
        System.Array.Sort(_hits, 0, count,
            Comparer<RaycastHit>.Create((a, b) => a.distance.CompareTo(b.distance)));

        for (int i = 0; i < count; i++)
        {
            Debug.Log(i + ": " + _hits[i].collider.name);
        }
    }

    // ============================================================
    //  其他检测方式
    // ============================================================
    private void OtherChecks()
    {
        // ---------- 球形投射：适合有体积的物体（子弹、角色）----------
        // 参数：起点、半径、方向、结果、距离
        if (Physics.SphereCast(transform.position, 0.5f, Vector3.forward,
                               out RaycastHit sph, 50f))
        {
            Debug.Log("球形投射命中 " + sph.collider.name);
        }

        int sphCount = Physics.SphereCastNonAlloc(
            transform.position, 0.5f, Vector3.forward, _sphereHits, 50f);

        // ---------- 盒形投射：适合方形物体 ----------
        // 参数：起点、半尺寸、方向、结果、旋转、距离
        if (Physics.BoxCast(transform.position, new Vector3(0.5f, 0.5f, 0.5f),
                            Vector3.forward, out RaycastHit box, Quaternion.identity, 50f))
        {
            Debug.Log("盒形投射命中 " + box.collider.name);
        }

        // ---------- 线段检测：判断两点之间是否有遮挡 ----------
        if (Physics.Linecast(transform.position, Vector3.zero, out RaycastHit line,
                             _groundMask))
        {
            Debug.Log("视线被挡住：" + line.collider.name);
        }

        // ---------- 范围检测：不发射射线，直接查某个区域 ----------
        Collider[] overlaps = new Collider[32];
        int overlapCount = Physics.OverlapSphereNonAlloc(transform.position, 5f, overlaps);

        for (int i = 0; i < overlapCount; i++)
        {
            Debug.Log("范围内：" + overlaps[i].name);
        }

        Debug.Log(sphCount);
    }

    // ============================================================
    //  准星检测：从屏幕中心发射射线（FPS 常用）
    // ============================================================
    public bool CheckCrosshair(Camera cam, out RaycastHit hit)
    {
        // 从屏幕中心发射射线
        Ray ray = cam.ScreenPointToRay(new Vector3(Screen.width * 0.5f, Screen.height * 0.5f, 0f));
        return Physics.Raycast(ray, out hit, _maxDistance, ~0, QueryTriggerInteraction.Ignore);
    }
}

// ============================================================
//  射线调试：在 Scene 视图里画出来
// ============================================================
public class RaycastDebug : MonoBehaviour
{
    [SerializeField] private float _distance = 10f;

    private void Update()
    {
        // 只在编辑器里编译，打包后自动移除
        #if UNITY_EDITOR
        Debug.DrawRay(transform.position, transform.forward * _distance,
                      Color.green, 0f, false);
        #endif

        // 也可以用 Gizmos（需要在 OnDrawGizmos 里调用）
    }

    private void OnDrawGizmosSelected()
    {
        Gizmos.color = Color.red;
        Gizmos.DrawWireSphere(transform.position, 5f);
        Gizmos.DrawLine(transform.position, transform.position + transform.forward * _distance);
    }
}
射线检测的五个要点 ① Raycast（单个）本身就是零分配的，它返回最近的命中。只有需要多个结果时才用 All 或 NonAlloc。
② NonAlloc 版本不排序。需要按距离排序必须自己调 Array.Sort。
③ 层掩码能大幅提升性能。只检测需要的层，比检测所有层快得多——物理引擎会先做层过滤，再算碰撞。
④ QueryTriggerInteraction 决定是否检测触发器。默认 UseGlobal（看项目设置）。射击检测通常用 Ignore，交互检测用 Collide。
⑤ SphereCast 与 Raycast 的区别：球形投射有体积，起点处如果已经与其他碰撞体重叠会检测不到（这是最常见的坑）。解决办法：把起点往后退一点，或用 Physics.OverlapSphere 补检起点。

三、碰撞与触发器的检测矩阵

这是新手最困惑的地方：明明两个物体都有碰撞体，为什么回调不触发？答案在下面这张矩阵里。

物体 A物体 B触发碰撞回调说明
Rigidbody + ColliderRigidbody + Collider会正常物理碰撞
Rigidbody + Collider静态 Collider会动态撞静态，正常
静态 Collider静态 Collider不会两个静态物体之间不产生任何物理交互
Rigidbody + Trigger任意 ColliderOnTriggerisTrigger 决定回调类型
Kinematic Rigidbody静态 Collider不会Kinematic 不主动触发静态
Kinematic Rigidbody带 Rigidbody 的物体会Kinematic 能被动态物体撞到
三个最容易踩的坑 ① 两个静态碰撞体不产生任何交互。想让物体"碰撞但不移动"，给它加 Rigidbody 并勾选 isKinematic，而不是不加 Rigidbody。
② 触发器不产生物理效果。isTrigger = true 的碰撞体是"幽灵"——它能被检测到，但不阻挡任何东西。需要阻挡又要检测，得用两个碰撞体（一个 Trigger 一个普通）。
③ 回调函数名拼错不会报错，只是静默不触发。OnCollisionEnter 写成 onCollisionEnter 编译器不会有任何提示。这是"物理回调不触发"最常见的原因——先用一个 Debug.Log 验证函数名是否正确。

四、物理性能优化 ★

物理是 CPU 大户。一个管理不当的物理场景，能让帧率从 60 掉到 20。下面按收益从高到低排列优化手段。

#手段做法收益
1图层碰撞矩阵Project Settings → Physics → Layer Collision Matrix，取消不需要的勾选极高
2减少 Rigidbody 数量静止物体用 isKinematic 或直接移除刚体高
3简化碰撞体用 Box/Sphere/Capsule 代替 MeshCollider高
4降低 FixedUpdate 频率Project Settings → Time → Fixed Timestep（0.02 → 0.033）中
5关闭不必要的碰撞用 Physics.IgnoreCollision 或层屏蔽中
6减少射线检测次数合并检测、降低频率、用层掩码过滤中
7设置 sleepThreshold让静止物体进入睡眠状态低
图层碰撞矩阵是最容易被忽略的优化 默认情况下所有层都互相碰撞。但你的项目里通常有大量不需要互相检测的组合：
• 子弹层 与 子弹层（子弹之间不需要碰撞）
• UI 层 与 任何层（UI 不参与物理）
• 装饰物层 与 特效层
取消这些勾选，物理引擎的检测量能减少一半以上，而且这是纯粹的配置工作，不需要写任何代码。
