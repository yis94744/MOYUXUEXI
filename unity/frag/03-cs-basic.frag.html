03 · C# 基础与类型系统

这一页是整个路线的地基。你可能觉得"类型系统"听起来很学术，但实际情况是：你在 Unity 里遇到的每一个诡异 bug——改了位置没反应、传参不生效、每帧掉帧——根因都在这里。

阶段目标 约 2 周，50 小时。结束时你能：说清值类型与引用类型的全部差异、解释什么是装箱以及它在哪发生、知道什么时候该用 struct、能看懂 List<T> 和 Dictionary<K,V> 的源码实现。

一、值类型 vs 引用类型 ★

这是 C# 里唯一一个必须彻底搞懂、且无法靠经验绕过去的概念。搞错它，代码会以"看起来完全正确但行为不对"的方式失败。

一句话定义

  • 值类型：变量里直接装着数据本身。赋值 = 把内容复制一份。
  • 引用类型：变量里装着"东西在哪"的地址。赋值 = 把地址复制一份，两个变量指向同一个对象。
类别 包含哪些 赋值行为
值类型 struct、enum、所有数值类型、bool、char、DateTime 拷贝内容
值类型（Unity） Vector2/3、Quaternion、Color、Rect、Bounds、Matrix4x4、RaycastHit 拷贝内容
引用类型 class、interface、delegate、string、object、数组 拷贝引用
引用类型（Unity） GameObject、Transform、MonoBehaviour、ScriptableObject、Material、Texture2D 拷贝引用

代码验证：差异到底在哪

using UnityEngine;
using System.Collections.Generic;

public class ValueVsReference : MonoBehaviour
{
    private void Start()
    {
        // ============ 值类型：赋值即拷贝 ============
        Vector3 a = new Vector3(1f, 0f, 0f);
        Vector3 b = a;              // 拷贝了三个 float，a 和 b 从此无关
        b.x = 999f;

        Debug.Log("a.x = " + a.x);  // 1     <- a 完全不受影响
        Debug.Log("b.x = " + b.x);  // 999

        // ============ 引用类型：赋值即共享 ============
        var list1 = new List<int> { 1, 2, 3 };
        var list2 = list1;          // 两者指向同一个 List 对象
        list2.Add(4);

        Debug.Log("list1.Count = " + list1.Count);  // 4  <- list1 也变了！

        // 想真正复制一份，必须显式新建
        var list3 = new List<int>(list1);   // 拷贝构造函数
        list3.Add(5);
        Debug.Log("list1.Count = " + list1.Count);  // 4  <- 这次没变

        // ============ Unity 特有：Transform 是引用类型 ============
        Transform t1 = transform;
        Transform t2 = transform;
        Debug.Log("同一实例？ " + ReferenceEquals(t1, t2));   // True
    }
}
"值类型在栈上"是不准确的说法 准确表述是：值类型内联存储在它所属的位置——是方法局部变量 → 在栈上；是类的字段 → 就在堆上，跟对象连在一起；是数组元素 → 就在数组里连续排列。
所以"值类型一定快"也是错的：一个 96 字节的 struct 每次传参都要复制 96 字节，比传一个 8 字节的引用慢得多。

CS1612：返回 struct 的属性不能直接改成员

这是 Unity 新手遇到的第一个编译错误，几乎人手一次。

CS1612 的错误信息 Cannot modify the return value of 'Transform.position' because it is not a variable
中文：无法修改 "Transform.position" 的返回值，因为它不是变量。 
using UnityEngine;

public class PositionTrap : MonoBehaviour
{
    private void Start()
    {
        // 编译错误 CS1612
        // transform.position.x = 5f;

        // 为什么？position 是「属性」，get 访问器返回的是一个 Vector3 副本。
        // 你改副本，原对象纹丝不动。编译器直接禁止这种写法。

        // ============ 写法一：取出 -> 改 -> 写回 ============
        Vector3 p = transform.position;
        p.x = 5f;
        transform.position = p;

        // ============ 写法二：用内置 API（推荐）============
        // 只需一次 native 调用，比"读-改-写"三次调用更省
        transform.Translate(5f, 0f, 0f, Space.World);

        // ============ 写法三：SetPositionAndRotation（Unity 2021.3 LTS 已有）============
        transform.SetPositionAndRotation(new Vector3(5f, 0f, 0f), Quaternion.identity);
    }
}
比 CS1612 更可怕的静默错误 下面这段代码能编译、能运行、但不产生任何效果：
var p = transform.position; p.x = 5f; —— 少了最后一句 transform.position = p;
编译器不警告，运行时不报错，只是"位置没变"。遇到"代码明明执行了却没生效"时，第一个怀疑对象就是它。

二、装箱与拆箱 ★

把值类型塞进 object，运行时会在堆上新建一个"箱子"把值装进去。这是 Unity 里 GC 压力的头号来源之一，而且大多数时候是隐式发生的——你看不见它。

using UnityEngine;
using System.Collections;
using System.Collections.Generic;

public class BoxingDemo : MonoBehaviour
{
    private void Start()
    {
        int hp = 100;

        // ============ 显式装箱 ============
        object boxed = hp;        // 堆上分配一个箱子
        int back = (int)boxed;    // 拆箱：类型检查 + 取值

        // ============ 隐式装箱（更危险，因为看不见）============
        // 注意："..." + 数值类型【不装箱】—— C# 编译器走的是 string.Concat(string, string)
        //      重载，会先插值调用 ToString()。实测 160 字节的 struct 拼接只分配 24 B（纯字符串），
        //      没有 168 B 的装箱。真正装箱的是下面 2)、3) 两种。
        Debug.Log("HP = " + hp);   // 只分配字符串，不装箱

        // 2) 非泛型容器
        var arrayList = new ArrayList();
        arrayList.Add(hp);                  // 装箱
        arrayList.Add(Vector3.zero);        // Vector3 也装箱（12 字节）

        // 3) params object[] 参数 —— 这里才真的装箱
        string s = string.Format("{0}", hp);   // 装箱（实参装进 object[]）
        Debug.LogFormat("HP = {0}", hp);       // 装箱（params object[] 无法避免）

        Debug.Log(s + back);
    }
}

// ============================================================
//  正确做法：全程用泛型
// ============================================================
public class NoBoxingDemo : MonoBehaviour
{
    private readonly List<int> _numbers = new List<int>();          // 零装箱
    private readonly List<Vector3> _points = new List<Vector3>();  // 零装箱

    private void Start()
    {
        for (int i = 0; i < 100; i++)
        {
            _numbers.Add(i);         // 泛型容器：值类型按原样存进内部数组
            _points.Add(new Vector3(i, 0f, 0f));
        }

        // 显式 ToString()，避免经过 object 中转
        Debug.Log("数量 = " + _numbers.Count.ToString());
    }
}
哪些情况其实不装箱（避免过度焦虑） List<int>、Dictionary<string, Vector3> 等泛型容器不装箱——泛型参数在运行时会为值类型生成专用代码。
Dictionary<枚举, T> 在 Unity 2018.3+ 的 .NET 4.x 下也不装箱（编译器生成了专用的 EqualityComparer）。
但 string.Format("{0}", hp) 确实会装箱（签名是 params object[]）。
结论：不要凭记忆猜，直接用 Profiler 看 GC Alloc 列。这是唯一可靠的方法。

三、struct 与 class 的选型

用 struct 该用 class
体积 ≤ 16 字节（约 4 个 int） 大于 24 字节
语义 是"值"：坐标、颜色、范围 是"东西"：玩家、敌人、管理器
变异性 声明为 readonly struct 需要修改内部状态
继承 不需要继承 需要继承或多态
null 不需要 null 语义 需要用 null 表示"不存在"
集合 需要数组连续存储（缓存友好） 会被装箱或放进非泛型容器

完整实例：战斗伤害系统

using UnityEngine;

// ============================================================
//  伤害信息用 readonly struct —— 12 字节的精致体积
// ============================================================
public readonly struct DamageInfo
{
    public readonly float Amount;      // 4 字节
    public readonly int AttackerId;    // 4 字节 —— 用 int 而不是 GameObject 引用
                                       //         避免意外持有对象导致无法回收
    public readonly byte DamageType;   // 1 字节
    public readonly byte Flags;        // 1 字节（bit0 = 暴击，bit1 = 格挡）

    public DamageInfo(float amount, int attackerId, byte damageType, byte flags)
    {
        Amount = amount;
        AttackerId = attackerId;
        DamageType = damageType;
        Flags = flags;
    }

    public bool IsCritical { get { return (Flags & 1) != 0; } }
    public bool IsBlocked  { get { return (Flags & 2) != 0; } }
}

// ============================================================
//  接收方
// ============================================================
public class DamageReceiver : MonoBehaviour
{
    [SerializeField] private float _maxHp = 100f;
    private float _hp;

    private void Awake() { _hp = _maxHp; }

    // struct 按值或 in 传入：调用方拿到的是快照
    public void TakeDamage(in DamageInfo info)
    {
        float final = info.IsCritical ? info.Amount * 1.5f : info.Amount;
        if (info.IsBlocked) final *= 0.5f;

        _hp -= final;
        _hp = Mathf.Max(0f, _hp);

        Debug.Log(name + " 受到 " + final.ToString("F1") + " 点伤害，剩余 " + _hp.ToString("F1"));
    }
}

实测各种 Unity struct 的体积

using UnityEngine;

// 用 Marshal.SizeOf 实测各 struct 的体积
public class StructSize : MonoBehaviour
{
    private void Start()
    {
        Log<Vector2>("Vector2");
        Log<Vector3>("Vector3");
        Log<Quaternion>("Quaternion");
        Log<Color>("Color");
        Log<Bounds>("Bounds");
        Log<Matrix4x4>("Matrix4x4");
        Log<RaycastHit>("RaycastHit");
    }

    private static void Log<T>(string label)
    {
        int size = System.Runtime.InteropServices.Marshal.SizeOf<T>();
        Debug.Log(label.PadRight(12) + ": " + size + " 字节");
    }

    // ---------- 预期结果 ----------
    // Vector2      : 8
    // Vector3      : 12    <- 小，随便传
    // Quaternion   : 16
    // Color        : 16
    // Bounds       : 24    <- 开始值得用 in
    // Matrix4x4    : 64    <- 热路径必须用 in 或 ref
    // RaycastHit   : 40+   <- 热路径配合 NonAlloc 数组使用
}
为什么 struct 数组比 class 数组快 2–5 倍 这不是玄学，而是 CPU 缓存行（cache line）的物理限制。一次内存访问会加载 64 字节：
struct 数组：64 字节能拿到 4 个 16 字节的结构体，后续 3 次访问全部命中缓存。
class 数组：64 字节只装了 8 个指针（64 位平台；IL2CPP 移动端 32 位时是 16 个）。真实数据散落在堆的各处，每次解引用都可能是新的内存访问。
这就是 Unity 的 DOTS / ECS 架构的核心思想。

四、字符串与不可变性

string 是引用类型，但表现得像值类型——因为它是不可变的。每次"修改"字符串，实际上都是创建一个新对象。这是 Unity 里 GC 的头号来源。

using UnityEngine;

public class StringDemo : MonoBehaviour
{
    private void Start()
    {
        // ============ 不可变的含义 ============
        string a = "hello";
        string b = a;
        b += " world";      // 不是"修改 a"，而是新建了 "hello world"

        Debug.Log(a);       // hello      <- a 完全没变
        Debug.Log(b);       // hello world
        Debug.Log(ReferenceEquals(a, b));   // False

        // ============ 循环拼接是 GC 灾难 ============
        string result = "";
        for (int i = 0; i < 100; i++)
        {
            result += i.ToString();   // 每轮新建一个字符串，前一个立刻变垃圾
        }
        Debug.Log(result);

        // ============ 正确做法：StringBuilder ============
        var sb = new System.Text.StringBuilder(64);
        sb.Clear();
        for (int i = 0; i < 100; i++)
        {
            sb.Append(i);             // 直接写入内部缓冲区，零分配
        }
        Debug.Log("sb = " + sb.ToString());   // 只有最后 ToString 分配一次
    }
}
UTF-16 与代理对：中文字符串截断的坑 string.Length 返回的是 UTF-16 码元数量，不是"字符数"。
大多数中文在 BMP 内占 1 个 char，但 emoji、部分生僻字占 2 个 char（代理对）。
"😀".Length 等于 2。做文本截断时直接 Substring 可能把代理对切成两半导致乱码，要用 StringInfo 按文本元素截断。

五、集合选型

选对容器，性能差 10 倍以上；选错容器，代码也能跑，只是会越跑越"沉"。

容器索引查找插入删除内存典型用途
T[]O(1)O(n)——最省定长、热路径、零 GC
List<T>O(1)O(n)尾部 O(1)*O(n)省动态列表、绝大多数场景
Dictionary<K,V>—O(1)*O(1)*O(1)*中键值查找
HashSet<T>—O(1)*O(1)*O(1)*中去重、集合运算
Queue<T>—O(n)O(1)O(1)省先进先出
Stack<T>—O(n)O(1)O(1)省后进先出
SortedDictionary—O(log n)O(log n)O(log n)大需要有序遍历
LinkedList<T>O(n)O(n)节点 O(1)节点 O(1)大中间频繁插删（Unity 少用）

* 均摊复杂度：单次操作偶尔会更慢（扩容、rehash）。

Dictionary 的两个大坑

using UnityEngine;
using System.Collections.Generic;

public class DictionaryTraps : MonoBehaviour
{
    private readonly Dictionary<int, Enemy> _enemies = new Dictionary<int, Enemy>();
    private readonly List<int> _toRemove = new List<int>(16);

    private void Start()
    {
        // ============ 坑 1：遍历中删除 ============
        // foreach (var kv in _enemies)
        //     if (kv.Value == null) _enemies.Remove(kv.Key);   // Dictionary 会抛 InvalidOperationException
        //     （注意：这是 Dictionary 的行为。.NET Core 3.0+ 的 Dictionary 移除了版本号检查，
        //       在 .NET 5/8 上"删当前项"不抛异常——但 Unity 用的 Mono 仍然会抛。）

        // 正确：先收集，再删除
        _toRemove.Clear();
        foreach (var kv in _enemies)
        {
            if (kv.Value == null) _toRemove.Add(kv.Key);
        }
        for (int i = 0; i < _toRemove.Count; i++) _enemies.Remove(_toRemove[i]);

        // ============ 坑 2：用 Vector3 做键 ============
        // 浮点误差让"看起来相等"的两个值哈希到不同桶
        var bad = new Dictionary<Vector3, int>();

        // 1.1f - 1f 得到 0.100000024f，不是 0.1f（位模式不同 -> GetHashCode 不同）
        // 注意：0.1f + 0.2f 在 .NET/Mono 上【恰好等于】0.3f，用它演示会失败
        float drifted = 1.1f - 1f;
        bad[new Vector3(drifted, 0f, 0f)] = 1;

        bool found = bad.TryGetValue(new Vector3(0.1f, 0f, 0f), out int v);
        Debug.Log("Vector3 键查到了吗？ " + found);   // False
        // 因为 1.1f - 1f = 0.10000002f，位模式和 0.1f 不同

        // 正确：网格坐标用 Vector2Int / Vector3Int
        var good = new Dictionary<Vector2Int, int>();
        good[new Vector2Int(1, 2)] = 100;
        Debug.Log("Vector2Int 键: " + good[new Vector2Int(1, 2)]);   // 100
    }
}

public class Enemy : MonoBehaviour { }
Dictionary 的遍历顺序是不确定的 你可能会发现"添加顺序和遍历顺序正好一样"——这是巧合，不是保证。
一旦发生扩容（rehash）、或者删除后再添加，顺序就会改变。不同 .NET 版本、不同平台也可能不同。
需要确定顺序时：用 SortedDictionary，或额外维护一个 List<K> 记录插入顺序。
