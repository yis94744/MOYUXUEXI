13 · 动画系统

上一页（12）讲物理，OnCollisionEnter 让你知道"撞上了"。这一页讲动画——让角色看起来真的在走路、攻击、受伤。动画系统的核心是 Animator 状态机，而它的性能陷阱比物理更隐蔽。

这一页在路线中的位置 上一页（12）的物理速度会在这里被用到——用 velocity 驱动 Speed 参数是最常见的做法。当然也可以反过来，用动画驱动位移（根运动）。
关键衔接：页 09 学的 四元数在 IK 和根运动里大量使用；插值则用于动画过渡。
下一页（14）UI 系统。动画事件（Animation Event）经常用来触发 UI 效果，两页会配合。
难度提示：Animator 的概念简单但参数多，重点是理解"什么该放状态机、什么该用代码"。

一、Animator 状态机基础 ★

Animator 的使用方式很直观：代码改参数 → 状态机根据参数切换动画。但这里有几个必须知道的性能细节，不知道就会写出"角色一多就卡"的项目。

using UnityEngine;

// ============================================================
//  Animator：参数、混合树、状态查询
// ============================================================
public class AnimatorBasic : MonoBehaviour
{
    // 【性能关键】哈希只在类加载时算一次
    private static readonly int SpeedHash = Animator.StringToHash("Speed");
    private static readonly int VerticalHash = Animator.StringToHash("Vertical");
    private static readonly int GroundedHash = Animator.StringToHash("Grounded");
    private static readonly int JumpHash = Animator.StringToHash("Jump");
    private static readonly int DieHash = Animator.StringToHash("Die");

    [SerializeField] private float _dampTime = 0.1f;

    private Animator _animator;
    private Rigidbody _rb;
    private float _lastSpeed = float.NaN;

    private void Awake()
    {
        _animator = GetComponent<Animator>();
        _rb = GetComponent<Rigidbody>();

        // 屏幕外完全停止更新 —— 大量角色时收益极大
        _animator.cullingMode = AnimatorCullingMode.CullCompletely;

        // 位移由代码控制时，必须关闭根运动
        _animator.applyRootMotion = false;
    }

    private void Update()
    {
        // 用物理速度驱动动画（这个组合非常常见）
        Vector3 v = _rb != null ? _rb.velocity : Vector3.zero;

        // 局部速度：需要转换到物体自身的坐标系
        Vector3 local = transform.InverseTransformDirection(v);

        SyncSpeed(local.z);
        _animator.SetFloat(VerticalHash, local.x);
        _animator.SetBool(GroundedHash, IsGrounded());
    }

    // 【优化】只在值变化时才同步，避免每帧无谓调用
    private void SyncSpeed(float speed)
    {
        if (Mathf.Approximately(speed, _lastSpeed)) return;
        _lastSpeed = speed;

        // 带阻尼的重载：第三个参数是过渡时间，让动画平滑变化
        _animator.SetFloat(SpeedHash, speed, _dampTime, Time.deltaTime);
    }

    private bool IsGrounded()
    {
        return Physics.Raycast(transform.position + Vector3.up * 0.1f,
                               Vector3.down, 0.2f, ~0, QueryTriggerInteraction.Ignore);
    }

    // ============================================================
    //  单次动作：Trigger 会自动复位
    // ============================================================
    public void PlayJump()
    {
        // 【重要】播放一个 Trigger 前先重置其他，避免触发器堆积
        _animator.ResetTrigger(DieHash);
        _animator.SetTrigger(JumpHash);
    }

    public void PlayDie()
    {
        _animator.ResetTrigger(JumpHash);
        _animator.SetTrigger(DieHash);
    }

    // ============================================================
    //  状态查询
    // ============================================================
    public bool IsPlaying(string stateName, int layer = 0)
    {
        return _animator.GetCurrentAnimatorStateInfo(layer).IsName(stateName);
    }

    public bool IsInTransition(int layer = 0)
    {
        // 做连招判断时很有用：过渡中不接受新输入
        return _animator.IsInTransition(layer);
    }

    public float NormalizedTime(int layer = 0)
    {
        // 归一化进度：0 = 开头，1 = 结束（可以大于 1，循环时会累加）
        return _animator.GetCurrentAnimatorStateInfo(layer).normalizedTime;
    }

    public float RemainTime(string stateName, int layer = 0)
    {
        AnimatorStateInfo info = _animator.GetCurrentAnimatorStateInfo(layer);
        if (!info.IsName(stateName)) return 0f;

        float total = info.length;
        float played = info.normalizedTime * total;
        return Mathf.Max(0f, total - played);
    }

    // ============================================================
    //  层与权重：上半身攻击 + 下半身跑动
    // ============================================================
    public void SetLayerWeight(int layerIndex, float weight)
    {
        _animator.SetLayerWeight(layerIndex, weight);
    }

    // ============================================================
    //  直接播放（不经过状态机，适合一次性特效）
    // ============================================================
    public void CrossFadeTo(string stateName, float duration = 0.15f, int layer = 0)
    {
        _animator.CrossFade(stateName, duration, layer);
    }

    public void CrossFadeInFixedTime(string stateName, float duration = 0.15f, int layer = 0)
    {
        // 用固定时间过渡，不受 timeScale 影响
        _animator.CrossFadeInFixedTime(stateName, duration, layer);
    }
}
Animator 的四个性能要点 ① 参数名要用哈希，不要用字符串。SetFloat("Speed", v) 每次调用都要对字符串做哈希计算。用 Animator.StringToHash 缓存成 static readonly int——这是最基础也最容易忽略的优化。
② cullingMode 默认是 AlwaysAnimate。这意味着屏幕外的角色依然在完整计算动画。改成 CullCompletely 后，屏幕外完全不更新——在有几十个角色的场景里，这一项能省下大量 CPU。
③ 带阻尼的 SetFloat 会持续插值。它让参数平滑过渡，但每帧都在计算。只对真正需要的参数用（比如 Speed），布尔和 Trigger 不需要。
④ 每帧无条件同步参数是浪费。如果值没变，这次调用纯属开销。加一个 Mathf.Approximately 判断就能省下来——上面的示例代码里就是这么做的。
cullingMode 的三个选项
模式行为适用场景
AlwaysAnimate始终完整更新（默认值）几乎不用——除非你需要读取屏幕外角色的精确骨骼位置
CullUpdateTransforms屏幕外停止更新骨骼，但仍计算状态机需要屏幕外角色保持逻辑但不渲染
CullCompletely屏幕外完全停止绝大多数情况的最佳选择
注意：CullCompletely 下屏幕外的角色动画会"冻结"。如果游戏逻辑依赖动画位置（比如判断攻击判定框），要么改成 CullUpdateTransforms，要么在逻辑里做屏幕外特殊处理。

二、IK 与根运动 ★

这是动画系统里最"高级"但也最实用的部分。IK 让动画贴合环境，根运动让动画驱动位移。

using UnityEngine;

// ============================================================
//  IK 与 Root Motion：让动画与世界贴合
// ============================================================
public class AnimatorIKDemo : MonoBehaviour
{
    // 这三个目标在 Inspector 里拖入（编译器的 CS0649 警告可忽略，
    // 也可以在代码里用 = null 显式初始化来消除）
    [SerializeField] private Transform _lookTarget = null;
    [SerializeField] private Transform _rightHandTarget = null;
    [SerializeField] private Transform _leftFootTarget = null;
    [SerializeField] private float _lookWeight = 1f;

    private Animator _animator;

    private void Awake()
    {
        _animator = GetComponent<Animator>();
    }

    // ============================================================
    //  OnAnimatorIK：IK 求解前的回调（必须开启 IK Pass）
    // ============================================================
    // 【前提】在 Animator 的对应 Layer 上勾选 IK Pass，
    //        否则这个回调根本不会被调用。
    private void OnAnimatorIK(int layerIndex)
    {
        if (_animator == null) return;

        // ---------- 头部朝向：让角色看着目标 ----------
        if (_lookTarget != null)
        {
            _animator.SetLookAtWeight(
                weight: _lookWeight,      // 总权重
                bodyWeight: 0.3f,         // 身体参与程度
                headWeight: 1f,           // 头部参与程度
                eyesWeight: 0.5f,         // 眼睛参与程度
                clampWeight: 0.7f);       // 限制转动角度（防止脖子扭曲）

            _animator.SetLookAtPosition(_lookTarget.position);
        }
        else
        {
            // 目标为 null 时把权重归零，否则角色会一直保持扭曲姿势
            _animator.SetLookAtWeight(0f);
        }

        // ---------- 手部 IK：握枪、扶墙、攀爬 ----------
        if (_rightHandTarget != null)
        {
            _animator.SetIKPositionWeight(AvatarIKGoal.RightHand, 1f);
            _animator.SetIKRotationWeight(AvatarIKGoal.RightHand, 1f);
            _animator.SetIKPosition(AvatarIKGoal.RightHand, _rightHandTarget.position);
            _animator.SetIKRotation(AvatarIKGoal.RightHand, _rightHandTarget.rotation);
        }
        else
        {
            _animator.SetIKPositionWeight(AvatarIKGoal.RightHand, 0f);
            _animator.SetIKRotationWeight(AvatarIKGoal.RightHand, 0f);
        }

        // ---------- 脚部 IK：让脚贴合斜坡、台阶 ----------
        if (_leftFootTarget != null)
        {
            _animator.SetIKPositionWeight(AvatarIKGoal.LeftFoot, 1f);
            _animator.SetIKRotationWeight(AvatarIKGoal.LeftFoot, 1f);
            _animator.SetIKPosition(AvatarIKGoal.LeftFoot, _leftFootTarget.position);
            _animator.SetIKRotation(AvatarIKGoal.LeftFoot, _leftFootTarget.rotation);

            // 还有 SetIKHintPositionWeight / SetIKHintPosition
            // 用来控制膝盖、肘部的朝向（防止关节反向弯折）
        }
    }

    // ============================================================
    //  OnAnimatorMove：接管根运动
    // ============================================================
    // 开启 applyRootMotion 后，动画自带的位移会驱动物体移动。
    // 这个回调让你可以「读取动画的位移，但自己决定怎么用」。
    private void OnAnimatorMove()
    {
        if (_animator == null) return;

        // 读取动画计算出的位移增量
        Vector3 deltaPos = _animator.deltaPosition;

        // 读取动画计算出的旋转增量
        Quaternion deltaRot = _animator.deltaRotation;

        // 常见用法 1：只取水平位移，垂直交给物理
        Vector3 horizontal = new Vector3(deltaPos.x, 0f, deltaPos.z);
        transform.position += horizontal;

        // 常见用法 2：让表面法线影响移动（在斜坡上贴着走）
        // transform.position += Vector3.ProjectOnPlane(deltaPos, groundNormal);

        transform.rotation *= deltaRot;
    }

    // ============================================================
    //  匹配目标（Motion Matching / 步态同步）
    // ============================================================
    public void MatchTargetDemo()
    {
        // 让角色「精确攀爬到某个点」，用于翻墙、上车
        // 一般配合 Animation Event 在动画的特定帧调用
        // _animator.MatchTarget(
        //     matchPosition,
        //     matchRotation,
        //     AvatarTarget.RightHand,
        //     new MatchTargetWeightMask(Vector3.one, 1f),
        //     startNormalizedTime: 0.3f,
        //     targetNormalizedTime: 0.6f);
    }

    public bool IsMatchingTarget()
    {
        return _animator.isMatchingTarget;
    }
}

// ============================================================
//  IK 的三个前提条件
// ============================================================
//  1. 模型的 Rig 类型必须是 Humanoid（Generic 不支持标准 IK Goal）
//  2. Animator 的 Layer 上要勾选 IK Pass
//  3. 脚本挂在与 Animator 相同的 GameObject 上
//
//  【性能提醒】IK 求解不便宜，角色多时开销明显。
//  建议：只对近距离角色开启，远处角色用 SetIKPositionWeight(0) 关掉。
IK 的三个前提条件（缺一不可） ① Rig 类型必须是 Humanoid。Generic 动画不支持标准的 IK Goal（AvatarIKGoal.LeftFoot 这类）。用 Generic 的话只能靠额外骨骼 + 脚本手动算。
② Animator 的 Layer 上必须勾选 IK Pass。不勾选的话 OnAnimatorIK 根本不会被调用——而且没有任何报错提示，这是最常见的"IK 不生效"原因。
③ 脚本必须挂在有 Animator 的那个 GameObject 上。挂在子物体上不会触发回调。
IK 的性能提醒 IK 求解不便宜——它需要反向推算骨骼链的旋转，迭代次数与链长相关。
角色一多，IK 的开销会非常明显。实用的做法是分级处理：
• 近距离角色（玩家、镜头前的敌人）：完整开启 IK
• 中距离角色：只开头部 IK（权重 0.5）
• 远距离角色：SetIKPositionWeight(goal, 0f) 全部关掉
而且判断应该按距离更新频率做，不要每帧都算。

三、根运动：动画驱动位移

代码驱动根运动（Root Motion）
位移来源脚本计算（velocity / CharacterController）动画曲线自带
优点精确可控、手感一致动作与位移完美同步（不会有脚滑）
缺点容易"脚滑"（动作与速度不匹配）难以精确控制，与物理结合麻烦
适用绝大多数游戏动作游戏、格斗、需要精确位移同步的场景
两者可以混合使用 OnAnimatorMove 回调让你读取动画计算出的位移，但自己决定怎么用。常见的混合方案：
• 只取水平位移，垂直交给物理——这样角色能正常受重力影响（示例代码里的做法）
• 把位移投影到地面法线——让角色在斜坡上贴着走
• 位移乘以速度系数——用一个参数控制"这次动作走多远"
这个回调是根运动与代码控制的桥梁，值得熟练掌握。

四、什么该用状态机、什么该写代码

这是新手最容易用错的地方：把什么都往 Animator 里塞，结果状态机变成一团乱麻，改一个动作要动几十个过渡线。

需求推荐方案原因
角色移动的四种状态Animator 状态机状态之间有清晰的切换关系
攻击连招（多段）Animator + Trigger需要精确的动画帧同步
UI 弹窗的缩放淡入代码 / 简单的插值用 Animator 太重，改起来也麻烦
道具上下浮动代码 + Mathf.Sin一行代码的事
血条变化动画代码插值数值驱动的，不需要状态机
复杂骨骼动画（受击、死亡）Animator需要美术制作的动画资源
相机跟随代码 + SmoothDamp见页 09 的插值
判断标准：一行代码能做完的，不要开状态机 Animator 的成本：需要一个 Animator Controller 资产、美术要 K 帧、状态多了难维护、运行时还有性能开销。
代码插值的成本：三行代码。
简单的、程序化的、数值驱动的动效，一律用代码。只有需要美术制作的骨骼动画才放 Animator。
补充：如果你确实需要"配置化的代码动画"（比如策划想在编辑器里调缓动曲线），可以用 DOTween 这类 Tween 库，它比 Animator 轻得多，也比手写代码灵活。
