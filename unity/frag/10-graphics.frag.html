一、渲染管线：一帧画面是怎么来的

无论多复杂的画面，渲染流程都是这几步。理解它，你才知道"性能花在哪里"。

渲染管线的四个阶段

① 应用阶段（CPU）
剔除看不见的物体（视锥剔除、遮挡剔除）、排序、合批、准备渲染数据。
Unity 里这一步对应 Culling、Sorting、Batching。Draw Call 太多就是这一步的问题。

② 几何阶段（GPU）
顶点着色器：把顶点从模型空间变换到裁剪空间（这就是 MVP 矩阵做的事）。
图元装配：把顶点连成三角形。
光栅化：把三角形转换成屏幕上的像素。
顶点数太多、Shader 太复杂，就是这一步的问题。

③ 像素阶段（GPU）
片元着色器：为每个像素计算颜色（光照、纹理采样）。
深度测试、模板测试：决定这个像素要不要画。
混合：把新颜色和已有颜色混合（半透明）。
Overdraw（同一像素被画多次）就是这一步的问题。

④ 后处理（GPU）
把渲染结果当作一张图，再做处理：泛光、颜色校正、抗锯齿、景深。
后处理非常耗性能——特别是移动端。

坐标空间的完整变换链

这是理解 3D 渲染的关键。一个顶点从模型数据到屏幕像素，要经过四次变换：

空间含义变换矩阵什么时候有用
模型空间以模型自身原点为基准—建模时、局部偏移
世界空间整个场景的统一坐标系M (Model)物理、AI、绝大部分游戏逻辑
观察空间以相机为原点V (View)相机相关计算
裁剪空间经过透视投影后的齐次坐标P (Projection)裁剪、顶点着色器输出
屏幕空间最终的像素坐标视口变换UI、后处理、屏幕特效
MVP 矩阵就是这三步 MVP = Projection x View x Model（从右往左应用）。
顶点着色器里最常见的一行就是：pos = mul(UNITY_MATRIX_MVP, v.vertex)。
注意乘法顺序：先应用 Model（把模型放到世界），再 View（把世界放到相机前），最后 Projection（压扁到屏幕）。这和上一页学的四元数乘法顺序是同一个道理——从右往左。

Draw Call 与合批：性能的第一道关

Draw Call 是 CPU 向 GPU 发出的"画这批东西"的指令。每次 Draw Call 都有固定的 CPU 开销——移动端上通常几百个就已经是瓶颈。

合批类型触发条件优缺点
Static Batching标记为 Static 的物体，共享材质构建时合并顶点，增加内存和包体
Dynamic Batching顶点数少的物体（小于 300 顶点）运行时合并，开销可能比省下的还大
SRP BatcherURP/HDRP 下，用同一 Shader 变体现代管线的主力，几乎无额外开销
GPU Instancing同网格 + 同材质 + 开启 Instancing一次 Draw Call 画多个，适合大量重复物体
手动合批把多个网格合并成一个最彻底，但失去单独控制能力
合批失败的最常见原因 ① 材质不同：这是头号原因。两个物体只要材质实例不同，就无法合批。
② 使用了 MaterialPropertyBlock：虽然能避免材质克隆，但会打断 SRP Batcher。
③ Shader 变体不同：比如一个开了阴影一个没开。
④ 渲染队列不同：透明物体和不透明物体分属不同队列。
怎么查：用 Frame Debugger（Window -> Analysis -> Frame Debugger）可以逐 Draw Call 查看，它会明确告诉你为什么没能合批。

二、Shader 入门：从能看懂到能修改

Shader 是用 GPU 执行的小程序。你不需要从零写复杂的 Shader，但需要能：看懂一个基础 Shader 的结构、改改颜色和参数、遇到问题知道查哪里。

ShaderLab 的基本结构

Shader "Custom/SimpleColor"
{
    // ---------- 属性：会在 Inspector 里显示 ----------
    Properties
    {
        _MainTex ("主纹理", 2D) = "white" {}
        _Color ("叠加颜色", Color) = (1,1,1,1)
        _Glossiness ("光滑度", Range(0,1)) = 0.5
    }

    SubShader
    {
        Tags { "RenderType"="Opaque" "Queue"="Geometry" }

        // ---------- Pass：一次绘制 ----------
        Pass
        {
            CGPROGRAM
            #pragma vertex vert      // 指定顶点着色器函数
            #pragma fragment frag    // 指定片元着色器函数

            #include "UnityCG.cginc"

            struct appdata
            {
                float4 vertex : POSITION;   // 模型空间顶点位置
                float3 normal : NORMAL;     // 法线
                float2 uv : TEXCOORD0;      // 纹理坐标
            };

            struct v2f
            {
                float4 pos : SV_POSITION;  // 裁剪空间位置
                float2 uv : TEXCOORD0;
                float3 worldNormal : TEXCOORD1;
            };

            sampler2D _MainTex;
            float4 _MainTex_ST;              // 纹理的缩放和偏移
            fixed4 _Color;

            // ---------- 顶点着色器：每个顶点执行一次 ----------
            v2f vert(appdata v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);   // 模型空间 -> 裁剪空间
                o.uv = TRANSFORM_TEX(v.uv, _MainTex);
                o.worldNormal = UnityObjectToWorldNormal(v.normal);
                return o;
            }

            // ---------- 片元着色器：每个像素执行一次 ----------
            fixed4 frag(v2f i) : SV_Target
            {
                fixed4 tex = tex2D(_MainTex, i.uv);
                fixed3 lightDir = normalize(_WorldSpaceLightPos0.xyz);
                fixed ndotl = saturate(dot(i.worldNormal, lightDir));  // 兰伯特光照
                tex.rgb *= ndotl * _Color.rgb;
                return tex;
            }
            ENDCG
        }
    }
    FallBack "Diffuse"    // 低端设备不支持时的降级方案
}
兰伯特光照：一个能用一辈子的公式 颜色 = 贴图颜色 x 光照强度 x max(0, dot(法线, 光照方向))
点积在这里的含义：法线和光照方向越接近（点积接近 1），说明表面越正对光源，就越亮。这是点积在渲染里最经典的用法。
saturate() 把结果限制在 0~1，避免背光面出现负数颜色。

三、URP：现代 Unity 的渲染管线

Unity 现在有三套渲染管线。新项目几乎都应该用 URP——除非你明确要做 PC 高画质（HDRP）。

管线定位移动端学 Shader 难度
Built-in老管线，官方不再推荐新项目一般资料多但过时
URP手游 / 中低配 3D / 2D优秀推荐从这里开始
HDRPPC / 主机高画质基本不可用复杂
自定义 SRP需要完全掌控管线看实现很高
渲染管线选型是没有回头路的 Built-in 和 URP 之间的迁移不是改个设置就完事——材质、Shader、后处理全都要重做。
新项目一律用 URP（除非你明确要做 PC 高画质，那就 HDRP）。
学教程时如果教程用 Built-in，注意区分哪些代码是通用的、哪些是管线相关的。
判断方法：如果代码里出现 UnityCG.cginc 或 CGPROGRAM，那是 Built-in。URP 用 HLSLPROGRAM 和 Core.hlsl。

Shader Graph：不写代码做 Shader

如果你用的是 URP 或 HDRP，Unity 提供了可视化 Shader 编辑器——用连线代替写代码。

  • 适合：做效果原型、美术同学自己调、学习 Shader 概念。
  • 不适合：对性能极致敏感的场景（生成的代码可能不如手写优化）。
  • 建议：先用 Shader Graph 理解"数据怎么流动"，再回头读代码版 Shader，会比直接啃代码快得多。
