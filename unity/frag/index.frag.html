C# + Unity 学习路线

这是一份自成体系的 C# + Unity 路线：从"没写过代码"一直走到"能独立完成可玩、可上架、能通过面试的项目"。它不假设你有任何编程基础，也不回避行业里那些没人愿意明说的现实。

全站 26 页，按 "语言 → 数学 → 引擎 → 通用能力 → 实战" 的顺序组织。每一页都给出可验证的过关标准——不是"了解"、"熟悉"这类没法检验的词，而是"能写出什么、能跑出什么效果、能通过什么测试"。

这份路线和其他教程的区别 ① 它会告诉你"什么时候不该用"。比如对象池不是万能的、DOTS 不是所有项目都该上、ScriptableObject 也有它的代价。
② 它把性能问题提到很前面。GC 分配、Draw Call 合批、内存布局这些内容，多数教程留到后期才讲，但那时候你的架构已经烂了。
③ 它承认行业的残酷面。页 01 和页 25 里都有大量"劝退向"的真实数据，因为知道风险才能做对选择。

一、为什么选 Unity + C#

先说结论：如果你的目标是"尽快做出能玩的游戏"或者"进入国内游戏行业就业"，Unity + C# 是当前最优解。这不是因为它技术最强（Unreal 在画面上限更高），而是因为它的投入产出比最高。

维度 Unity + C# 对比 Unreal + C++
语言门槛 低 C# 没有指针、手动内存管理、模板元编程 高 C++ 心智负担重，编译慢
上手速度 天级 装好就能做出东西 周级 配置和框架概念多
画面上限 中高 URP 够做手游和大部分独立游戏 极高 Nanite/Lumen 是次世代标准
国内岗位 最多 手游是产业主流 较少 集中在少数 3A 团队
薪资上限 中高 高 技术壁垒带来溢价
学习资料 最多 中文资源极其丰富 中等，英文为主
迭代体验 好 热重载快 差 C++ 改动要重编译
但它们不是竞争关系 两个引擎底层概念是相通的：坐标系、渲染管线、物理、动画状态机、网络同步——换个引擎只是换 API。
所以：先深入一个，再学另一个，第二门会快得多。
如果你已经确定要走 Unreal 路线，本站的大部分"通用能力"章节（数学、图形学、模式、性能、网络）依然适用——去看配套的 C++ + Unreal 路线。

也不要无限期停留在学习。阶段 3 结束时你就该有一个完整的游戏了，哪怕很小。

三、怎么用这份路线

三种使用方式

① 从头刷（推荐给完全新手）
按页面顺序读，每页的动手任务全部做完再往下走。不要跳过任务——看懂和能写出来，中间的差距就是"能不能找到工作"。

② 查漏补缺（推荐给有基础的人）
直接看你薄弱的部分。但请务必先做每页的"过关标准"自测——很多人以为自己会了，一做才发现说不清楚。

③ 当参考手册（推荐给在职开发者）
用顶部搜索框（按 / 聚焦）查具体问题。每页的"常见错误"和"性能陷阱"部分，都是踩过坑总结出来的。

关于页面底部的复选框 每页的"动手任务"是可以勾选的，进度保存在你浏览器的 localStorage 里。顶部的进度条会实时显示本页完成度。
进度是按站点独立存储的（本站的进度不会和 Unreal 站混淆）。

四、两种典型路径

不是所有人都需要走完全部 26 页。下面是最常见的两条路径：

路径 A：求职导向（国内手游公司）

重点投入：03–08（C# 深入）、11–16（引擎核心）、20–22（架构与性能）、24（项目集）、25（面试）

可以略过：10（Shader 只需看懂，不必会写）、18（DOTS 除非岗位明确要求）、23（AI 部分了解即可）

核心产出：2 个完整项目 + 能讲清 GC / 生命周期 / 合批 三大高频考题

路径 B：独立开发导向

重点投入：03–05（语言够用即可）、11–16（引擎核心，要熟练）、17（画面优化）、24（项目集）

可以略过：07（GC 深入可后补）、18（DOTS）、22（网络除非做多人）

核心产出：一个能上架、能跑在真机上、有人愿意玩的完整游戏

额外提醒：独立开发的难点从来不是技术，是做完。先做小的，做一个能通关的。

五、几句实话

在开始之前，你需要知道这些 ① 学完不等于能找到工作。行业里"会 Unity"的人很多，稀缺的是能定位性能瓶颈、能设计可维护架构的人。本站的重点在后半段，但前半段是你必须跨过的门槛。
② AI 没有降低门槛，只是改变了门槛的位置。写样板代码变快了，但"判断 AI 给的方案对不对"变得更重要了。没有基础判断力的人，用 AI 只会更快地写出烂代码。
③ 独立开发在数学上是负期望值。大多数独立游戏不赚钱。这不是劝你别做，而是建议你别把它当成唯一的收入来源。
④ 前面几页会很枯燥。类型系统、GC、四元数——这些不像"让角色跑起来"那么有成就感。但它们决定了你的天花板。

如果你看到这里还没有被劝退，那就可以开始了。先从 02 环境搭建 入手——不要在没跑通代码之前读任何理论。
