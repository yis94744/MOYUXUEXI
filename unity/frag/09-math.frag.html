09 · 游戏数学基础

很多人一听到"数学"就想跳过。但游戏开发用到的数学其实很少，而且非常具体——真正每天都在用的只有四样：向量、矩阵、四元数、插值。它们不是为了考试，而是为了回答四个实际问题：东西朝哪、怎么转、怎么动、怎么摆。

这一页在路线中的位置 前面八页（03–08）讲的是"语言"：怎么写出正确的 C# 代码。你已经掌握了工具。
这一页开始讲"内容"：游戏世界里的一切位置、朝向、运动，都是数学。你会发现页 03 学的 Vector3 是 值类型这件事，在这里有了实际意义。
下一页（10）讲渲染管线：那本质上是"把这些数学用在屏幕上"。
难度曲线：这一页会比前面轻松一些——因为它更直观。但四元数那部分需要你动手算一遍。

一、为什么游戏开发需要数学

先破除一个误解：你不需要成为数学高手才能做游戏。Unity 已经把 95% 的数学封装成了 API——你调 Vector3.Distance 就行，不需要知道它是怎么算的。

但剩下 5% 你必须懂，因为不懂就会写出"能跑但很慢"或"看起来对但结果错"的代码。具体来说：

数学概念游戏里解决什么问题不懂的后果
向量位置、方向、速度、距离每帧调用 Distance 导致性能问题；判断方向时写出错误逻辑
点积 / 叉积判断前后、左右、夹角、视线检测不知道可以用点积判断朝向，写出复杂的三角函数
矩阵坐标空间转换（模型 -> 世界 -> 屏幕）看不懂 Shader；不理解为什么父物体移动子物体会跟着动
四元数旋转、朝向、平滑转向旋转顺序搞错导致物体歪头（最常见的 bug）
插值平滑移动、相机跟随、缓动动画写出与帧率相关的代码，高刷屏上快、低端机上慢
学习方法建议 不要先学理论再做游戏，那样你会失去动力。
推荐顺序：先看这一页的"每个概念解决什么问题"，然后动手写一遍代码，遇到不理解的地方再回头查。
最重要的练习：把页 04 的角色控制器改成用点积判断"敌人在不在视野内"，把页 02 的 LookAt 改成用四元数平滑转向。当你发现数学能让代码更简单时，就真正学会了。

二、向量：位置与方向

向量就是一个"带方向的箭头"。在游戏里，位置、速度、加速度、朝向全都是向量——只是语义不同。Vector3(1, 0, 0) 可以是"在 x=1 的位置"，也可以是"向右的速度"。

核心运算速查

运算符号几何含义游戏用途
加法a + b首尾相接位置 + 位移 = 新位置
数乘a * 2f拉长 / 缩短速度 x 时间 = 位移
长度a.magnitude箭头的长度距离、速度大小
归一化a.normalized方向不变，长度变 1求"朝哪个方向"
点积Vector3.Dot(a,b)判断夹角前方/背后、视野、光照
叉积Vector3.Cross(a,b)垂直于两者的向量判断左右、求法线
投影Vector3.Project一个向量在另一个上的影子沿坡面滑行、斜面移动
反射Vector3.Reflect弹射方向子弹反弹、光线追踪
 
using UnityEngine;

// ============================================================
//  向量：游戏开发中最基本的数学对象
// ============================================================
public class VectorBasics : MonoBehaviour
{
    private void Start()
    {
        Vector3 a = new Vector3(3f, 4f, 0f);
        Vector3 b = new Vector3(1f, 0f, 0f);

        // ---------- 长度 ----------
        float len = a.magnitude;            // 5（会开平方，较慢）
        float sqrLen = a.sqrMagnitude;      // 25（快，比较距离时用这个）

        // ---------- 距离：两种写法 ----------
        float dist = Vector3.Distance(a, b);          // 慢：内部开平方
        float sqrDist = (a - b).sqrMagnitude;         // 快：不开平方

        // 只比较"谁更近"时用平方距离
        Debug.Log("距离 " + dist + "，平方距离 " + sqrDist);

        // ---------- 归一化 ----------
        Vector3 norm = a.normalized;        // 长度变成 1，不修改 a
        a.Normalize();                      // 就地归一化

        // ---------- 点积：判断方向和角度 ----------
        // dot > 0：同向（夹角 < 90 度）
        // dot = 0：垂直
        // dot < 0：反向（夹角 > 90 度）
        Vector3 forward = transform.forward;
        Vector3 toTarget = (Vector3.zero - transform.position).normalized;
        float dot = Vector3.Dot(forward, toTarget);

        if (dot > 0.7f)
        {
            Debug.Log("目标在正前方 45 度内");
        }
        else if (dot > 0f)
        {
            Debug.Log("目标在前方");
        }
        else
        {
            Debug.Log("目标在后方");
        }

        // ---------- 叉积：求垂直于两者的向量 ----------
        // 用途：判断左右、生成法线、算力矩
        Vector3 cross = Vector3.Cross(forward, toTarget);

        // cross.y > 0 说明目标在右侧，< 0 在左侧（Unity 是左手坐标系）
        if (cross.y > 0f) Debug.Log("目标在右侧");
        else if (cross.y < 0f) Debug.Log("目标在左侧");

        // ---------- 投影 ----------
        // b 在 a 方向上的投影
        Vector3 proj = Vector3.Project(b, a.normalized);

        // b 在垂直于 a 的平面上的投影
        Vector3 perp = Vector3.ProjectOnPlane(b, a.normalized);

        // ---------- 反射：弹射方向 ----------
        Vector3 incoming = new Vector3(1f, -1f, 0f).normalized;
        Vector3 normal = Vector3.up;
        Vector3 reflected = Vector3.Reflect(incoming, normal);

        Debug.Log(norm + " " + proj + " " + perp + " " + reflected + " " + len + " " + sqrLen);
    }
}
一个能省下大量性能的细节：用 sqrMagnitude 代替 Distance Vector3.Distance 内部要开平方根——这是个相对昂贵的运算。
如果你只是比较远近（谁离我更近？在不在范围内？），那就不需要开平方：(a - b).sqrMagnitude < range * range 就够了。
什么时候必须用 Distance：需要真实的距离数值时（比如扣血公式、显示"距离 3.7 米"）。
在每帧执行数千次的地方，这个替换能省下可观的 CPU 时间。

点积与叉积：判断方向的利器

这两个运算是新手最容易忽略、但最能简化代码的工具。很多需要"算角度 + 判断象限"的复杂逻辑，用点积一行就够。

点积的三个用途

① 判断方向关系
Dot(a, b) > 0 同向；== 0 垂直；< 0 反向。注意：前提是 a 和 b 都是单位向量。

② 判断是否在视野内
Dot(transform.forward, toTarget.normalized) > 0.7f 表示目标在前方约 45 度内。不需要三角函数，不需要算角度。这是 AI 视野检测的标准做法。

③ 求夹角
Mathf.Acos(Dot(a.normalized, b.normalized)) * Mathf.Rad2Deg。但更推荐直接用 Vector3.Angle(a, b)，它内部做了数值稳定性处理。

叉积的用途

判断左右（最常用）
Vector3.Cross(forward, toTarget).y 的符号就能告诉你目标在左侧还是右侧。
Unity 是左手坐标系，y > 0 是右侧。这一点和很多数学教材相反，必须动手验证一次。

求法线
给定三角形的两个边向量，叉积就是它的法线。这是网格生成、光照计算的基础。

算力矩 / 角速度
物理引擎内部大量使用。日常开发中很少直接用到。

三、四元数：旋转的正确表示 ★

这是本页最难也最重要的部分。四元数经常被当作"黑盒"，但它其实有一个非常直观的几何解释：四元数 = 一根轴 + 一个旋转角度。

为什么不用欧拉角 欧拉角（(x, y, z) 三个角度）看起来更直观，但有三个致命问题：
① 万向节死锁：在某些角度下会失去一个旋转自由度，导致旋转"卡住"。
② 插值困难：(350, 0, 0) 到 (10, 0, 0) 直接插值会倒退 340 度。
③ 顺序敏感：(30, 40, 50) 到底是什么顺序？不同引擎约定不同，而且结果完全不同。
四元数解决了全部三个问题，代价是它不直观。但只要你记住"轴 + 角"这个图像，就不难了。 
using UnityEngine;

// ============================================================
//  四元数：旋转的本质是"绕一根轴转一个角度"
// ============================================================
public class QuaternionBasics : MonoBehaviour
{
    private void Start()
    {
        // ---------- 创建 ----------
        Quaternion identity = Quaternion.identity;                    // 无旋转
        Quaternion fromEuler = Quaternion.Euler(0f, 90f, 0f);         // 欧拉角 -> 四元数
        Quaternion look = Quaternion.LookRotation(Vector3.forward, Vector3.up);  // 朝向
        Quaternion axis = Quaternion.AngleAxis(45f, Vector3.up);      // 绕轴转

        // ---------- 属性 ----------
        Vector3 euler = fromEuler.eulerAngles;          // 转回欧拉角
        Quaternion inv = Quaternion.Inverse(fromEuler); // 逆旋转

        // ---------- 旋转向量 ----------
        Vector3 rotated = fromEuler * Vector3.forward;  // 四元数 * 向量

        // ---------- 旋转叠加：顺序至关重要 ----------
        Quaternion rx = Quaternion.AngleAxis(30f, Vector3.right);
        Quaternion ry = Quaternion.AngleAxis(90f, Vector3.up);

        // a * b 表示：先应用 b，再应用 a（从右往左读）
        Quaternion firstRxThenRy = ry * rx;   // 先绕 X 转 30，再绕 Y 转 90
        Quaternion firstRyThenRx = rx * ry;   // 先绕 Y 转 90，再绕 X 转 30

        // 两者结果完全不同！
        Debug.Log("先X后Y: " + (firstRxThenRy * Vector3.forward));
        Debug.Log("先Y后X: " + (firstRyThenRx * Vector3.forward));

        // ---------- 朝向目标 + 本地偏移（常用写法）----------
        Vector3 toTarget = (Vector3.zero - transform.position).normalized;
        if (toTarget != Vector3.zero)
        {
            // 基准朝向
            Quaternion targetRotation = Quaternion.LookRotation(toTarget, Vector3.up);

            // 本地偏移：让模型低头 10 度（相对于自己的朝向）
            Quaternion localOffset = Quaternion.Euler(10f, 0f, 0f);

            // 先应用偏移，再转到目标朝向
            transform.rotation = targetRotation * localOffset;
        }

        // ---------- 插值 ----------
        Quaternion slerp = Quaternion.Slerp(identity, fromEuler, 0.5f);   // 球面插值（推荐）
        Quaternion rot = Quaternion.RotateTowards(identity, fromEuler, 90f * Time.deltaTime);

        // ---------- 角度 ----------
        float angle = Quaternion.Angle(identity, fromEuler);   // 两个旋转的夹角

        Debug.Log(look + " " + axis + " " + euler + " " + inv + " " + rotated);
        Debug.Log(slerp + " " + rot + " " + angle);
    }

    // ---------- 2D：只绕 Z 轴旋转 ----------
    private void FaceTarget2D(Transform self, Transform target)
    {
        Vector3 diff = target.position - self.position;
        float angleDeg = Mathf.Atan2(diff.y, diff.x) * Mathf.Rad2Deg;
        self.rotation = Quaternion.Euler(0f, 0f, angleDeg - 90f);
    }
}
乘法顺序：这是四元数唯一的难点 规则：a * b 表示先应用 b，再应用 a（从右往左读）。
为什么容易记反：因为读代码是从左往右的，但四元数乘法的语义是从右往左。
实战写法：transform.rotation = targetRotation * localOffset;
读作"先应用本地偏移，再转到目标朝向"。这样写出来的旋转始终相对于物体自己，不会出现歪头。

四元数的四条实践规则

规则说明
不要用 == 比较浮点误差。用 Quaternion.Angle(a, b) < 1f 判断"转到了"
不要反复转换欧拉角和四元数每次转换都有精度损失，累积会出错。用四元数存状态，只在显示时转欧拉角
旋转叠加必须用乘法四元数不能相加。q1 * q2 才是叠加
平滑转向用 Slerp 或 RotateTowards不要用 Lerp（不匀速），更不要手算角度

四、插值：让运动自然起来 ★

插值是游戏里用得最多、也最容易写错的东西。新手最常见的 bug 就是：在自己电脑上流畅，到 144Hz 屏幕上快到飞起，或者低端机上慢得像蜗牛。

using UnityEngine;

// ============================================================
//  插值与缓动：让运动"自然"起来的数学
// ============================================================
public class InterpolationDemo : MonoBehaviour
{
    [SerializeField] private Transform _target = null;
    [SerializeField] private float _moveSpeed = 5f;
    [SerializeField] private float _smoothTime = 0.3f;

    private Vector3 _velocity;

    private void Update()
    {
        // ---------- 线性插值 Lerp ----------
        // t = 0 返回 a，t = 1 返回 b，会被自动 Clamp01
        // 注意：Lerp(current, target, 0.1f) 每帧调用是「指数逼近」，
        // 不是匀速，而且与帧率相关
        transform.position = Vector3.Lerp(transform.position, _target.position, 0.1f);

        // ---------- 正确的匀速移动：MoveTowards ----------
        // 以固定速度靠近，不会过冲
        transform.position = Vector3.MoveTowards(
            transform.position, _target.position, _moveSpeed * Time.deltaTime);

        // ---------- 帧率无关的平滑：SmoothDamp ----------
        // 内部维护速度状态，自动处理帧率
        transform.position = Vector3.SmoothDamp(
            transform.position, _target.position, ref _velocity, _smoothTime);

        // ---------- 帧率无关的指数插值 ----------
        // 如果你坚持要用 Lerp，必须这样写才能与帧率无关
        float t = 1f - Mathf.Exp(-10f * Time.deltaTime);
        transform.position = Vector3.Lerp(transform.position, _target.position, t);

        // ---------- 旋转插值 ----------
        Vector3 dir = (_target.position - transform.position).normalized;
        if (dir != Vector3.zero)
        {
            Quaternion targetRot = Quaternion.LookRotation(dir);
            // Slerp 用于旋转（保持角速度均匀）
            transform.rotation = Quaternion.Slerp(
                transform.rotation, targetRot, 5f * Time.deltaTime);
        }
    }

    // ---------- 缓动函数 ----------
    private void EasingDemo()
    {
        float t = Mathf.Repeat(Time.time, 1f);   // 0 -> 1 循环

        // 平滑起停（两端慢中间快）
        float smooth = Mathf.SmoothStep(0f, 1f, t);

        // 来回摆动（乒乓）
        float pingpong = Mathf.PingPong(Time.time, 1f);

        // 自定义缓动：ease out（开始快，结束慢）
        float easeOut = 1f - Mathf.Pow(1f - t, 3f);

        // 自定义缓动：ease in-out
        float easeInOut = t < 0.5f
            ? 4f * t * t * t
            : 1f - Mathf.Pow(-2f * t + 2f, 3f) / 2f;

        Debug.Log(smooth + " " + pingpong + " " + easeOut + " " + easeInOut);
    }

    // ---------- 角度插值（处理绕圈问题）----------
    private void AngleLerp()
    {
        float current = 350f;
        float target = 10f;

        // 直接用 Lerp 会绕远路（350 -> 10 会倒退 340 度）
        float bad = Mathf.Lerp(current, target, 0.5f);      // 180（错的）

        // 正确：用 LerpAngle，会自动选择最短路径（+20 度，而不是 -340 度）
        // 注意结果规范化到 [0,360)，所以是 360 而不是 0 —— 360 与 0 是同一个角度
        float good = Mathf.LerpAngle(current, target, 0.5f);   // 360（等价于 0，对的）

        Debug.Log(bad + " vs " + good);
    }
}
帧率无关：这是插值最重要的概念 错误的写法：Lerp(pos, target, 0.1f) 每帧调用。
问题：60 FPS 时每秒逼近 6 次，144 FPS 时每秒逼近 14 次——高刷屏上快得多。
正确写法有三种：
① MoveTowards(pos, target, speed * Time.deltaTime) —— 匀速，最常用
② SmoothDamp(pos, target, ref vel, smoothTime) —— 平滑起停，相机的标准做法
③ t = 1 - Exp(-k * deltaTime) 配 Lerp —— 帧率无关的指数逼近
判断标准：如果你的插值代码里出现了裸的数字（比如 0.1f），而没有乘以 deltaTime，那它几乎一定是错的。

三种平滑方式怎么选

方法运动特征适用场景
MoveTowards匀速直线，到点即停角色移动、UI 平移、需要精确到达
SmoothDamp平滑加速 + 平滑减速相机跟随、需要"顺滑感"
Lerp + Exp开始快、越来越慢（永远逼近但不等于）UI 淡入淡出、数值逼近
PingPong来回摆动巡逻、呼吸动画
SmoothStep两端慢、中间快缓动、过渡效果

五、本章动手任务

本章过关标准：

② 知道什么时候该用 sqrMagnitude 代替 Distance；
