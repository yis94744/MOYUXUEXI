    一、Rigidbody —— 物理刚体

    Rigidbody 有三十多个属性，但日常真正要调的只有下面这八个。如果你之前只改过 mass，那这一节会让你少走很多弯路。

    属性默认值什么时候该改
    mass1影响碰撞时的动量交换。质量比决定谁被撞飞
    drag0线性阻力。做"空气阻力"或"水中减速"时调大
    angularDrag0.05角阻力。物体旋转停不下来时调大
    useGravitytrue飞行单位、漂浮物要关掉
    isKinematicfalse开启后完全由代码控制，不受物理力影响但仍有碰撞
    interpolationNone几乎一定要改。设为 Interpolate 消除视觉抖动
    collisionDetectionModeDiscrete高速物体穿透时改成 Continuous
    constraintsNone2D 游戏锁 Z 轴；防翻倒锁旋转
    Rigidbody 的三个经典坑 ① 不要同时用 transform.position 和物理。直接改 position 会绕过物理引擎，导致穿墙、抖动、碰撞失效。正确做法是用 velocity 或 MovePosition()。
    ② isKinematic 与 velocity 不兼容。设为 Kinematic 后 velocity 就不再驱动移动了，必须改用 MovePosition。
    ③ 子物体的 Collider 会算进父 Rigidbody。给角色挂多个碰撞体（头、身体、腿）时，它们是同一个刚体的一部分，不需要每个都加 Rigidbody。

    还有个容易被忽略的问题：什么时候该用 velocity，什么时候该用 AddForce？

    • velocity：直接设定速度。响应即时、完全可控，适合角色移动。但会覆盖物理计算出的速度，失去部分物理感。
    • AddForce：施加力。物体逐渐加速，有惯性和质量感，适合爆炸冲击、被击退。但难以精确控制最终位置。
    • 实践建议：需要"手感"的地方用 velocity，需要"物理感"的地方用 AddForce。混用要小心——它们会互相干扰。

    二、角色控制：三种方案对比

    这是新手最容易选错的地方。三条路各有代价，选错了会一路痛苦。

    方案适用场景优点代价
    Rigidbody + AddForce物理感强的对象（滚球、载具）真实的物理交互难精确控制，手感难调
    Rigidbody + velocity需要物理交互又要手感可控且能参与物理要自己处理斜坡与台阶
    CharacterControllerFPS / 第三人称动作内置斜坡、台阶、isGrounded不参与物理，不会被推动
     
    using UnityEngine;

// ============================================================
//  CharacterController：角色控制的标准方案
// ============================================================
public class CharacterMotor : MonoBehaviour
{
    [SerializeField] private float _speed = 5f;
    [SerializeField] private float _jumpHeight = 1.2f;
    [SerializeField] private float _gravity = -20f;

    private CharacterController _cc;
    private Vector3 _velocity;

    private void Awake()
    {
        _cc = GetComponent<CharacterController>();
    }

    private void Update()
    {
        // ---------- 接地检测 ----------
        // isGrounded 是 CharacterController 最实用的属性
        bool grounded = _cc.isGrounded;

        if (grounded && _velocity.y < 0f)
        {
            _velocity.y = -2f;   // 轻微下压，保证贴合地面
        }

        // ---------- 水平移动 ----------
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");
        Vector3 dir = new Vector3(h, 0f, v);
        if (dir.sqrMagnitude > 1f) dir.Normalize();   // 斜向不加速

        // ---------- 跳跃 ----------
        if (grounded && Input.GetButtonDown("Jump"))
        {
            // 由高度反推初速度：v = sqrt(2 * g * h)
            _velocity.y = Mathf.Sqrt(_jumpHeight * -2f * _gravity);
        }

        _velocity.y += _gravity * Time.deltaTime;

        // Move 的参数是「这一帧要移动多少」，不是速度
        Vector3 motion = dir * _speed + Vector3.up * _velocity.y;
        _cc.Move(motion * Time.deltaTime);
    }

    // ---------- 被撞飞：CharacterController 需要手动实现 ----------
    public void ApplyKnockback(Vector3 impulse)
    {
        _velocity += impulse;
    }
}
    CharacterController 的三个关键参数 slopeLimit：能爬的最大坡度（默认 45 度）。爬不上坡先调这个。
    stepOffset：能自动迈上的台阶高度（默认 0.3 米）。走楼梯卡顿就调这个。
    skinWidth：不要随便改。默认是半径的 10%，改小容易卡进几何体，改大会让角色悬空。
    关于跳跃公式：v = sqrt(2 * g * h)。用高度反推初速度比直接调数值可靠得多——改重力时跳跃高度自动保持。

    三、Animator 优化与实用 API

    Animator 是 CPU 大户，尤其是场景里角色多的时候。下面这些设置能带来数量级的性能差异——但很多人不知道。

    技巧做法收益
    哈希缓存参数Animator.StringToHash("Speed")避免每帧对字符串做哈希
    屏幕外停止更新cullingMode = CullCompletely屏幕外不更新，省大量 CPU
    关闭根运动applyRootMotion = false由代码控制位移时必关
    用 Trigger 而非 Bool单次动作（攻击、跳跃）避免状态残留导致动作卡住
    只同步变化的参数加值变化判断省掉大量无谓的 Set 调用
     
    using UnityEngine;

// ============================================================
//  Animator：性能优化与实用 API
// ============================================================
public class AnimatorOptimized : MonoBehaviour
{
    // 静态只读：哈希只在类加载时计算一次
    private static readonly int SpeedHash = Animator.StringToHash("Speed");
    private static readonly int GroundedHash = Animator.StringToHash("Grounded");
    private static readonly int JumpHash = Animator.StringToHash("Jump");
    private static readonly int AttackHash = Animator.StringToHash("Attack");

    private Animator _animator;
    private float _lastSpeed = float.NaN;      // NaN 保证首帧一定会同步

    private void Awake()
    {
        _animator = GetComponent<Animator>();

        // 屏幕外完全停止更新动画 —— 大量角色时收益极大
        _animator.cullingMode = AnimatorCullingMode.CullCompletely;

        // 位移由代码控制时，必须关闭根运动
        _animator.applyRootMotion = false;
    }

    // ---------- 只在值变化时才同步（避免每帧无谓调用）----------
    public void SyncSpeed(float speed)
    {
        if (Mathf.Approximately(speed, _lastSpeed)) return;
        _lastSpeed = speed;

        // 带阻尼的平滑过渡：第 3 个参数是过渡时间
        _animator.SetFloat(SpeedHash, speed, 0.1f, Time.deltaTime);
    }

    public void SetGrounded(bool grounded)
    {
        _animator.SetBool(GroundedHash, grounded);
    }

    // ---------- 单次动作：Trigger 会自动复位 ----------
    // 关键：播放一个动作前先重置另一个，避免触发器堆积
    public void PlayJump()
    {
        _animator.ResetTrigger(AttackHash);
        _animator.SetTrigger(JumpHash);
    }

    public void PlayAttack()
    {
        _animator.ResetTrigger(JumpHash);
        _animator.SetTrigger(AttackHash);
    }

    // ---------- 不经过状态机直接播放（适合一次性特效动画）----------
    public void CrossFadeTo(string stateName, float duration = 0.1f, int layer = 0)
    {
        _animator.CrossFade(stateName, duration, layer);
    }

    // ---------- 查询当前状态 ----------
    public bool IsPlaying(string stateName, int layer = 0)
    {
        AnimatorStateInfo info = _animator.GetCurrentAnimatorStateInfo(layer);
        return info.IsName(stateName);
    }

    public float NormalizedTime(int layer = 0)
    {
        // 归一化播放进度：0 = 开头，1 = 结束
        return _animator.GetCurrentAnimatorStateInfo(layer).normalizedTime;
    }

    // ---------- 判断是否在过渡中（做连招判断时很有用）----------
    public bool IsInTransition(int layer = 0)
    {
        return _animator.IsInTransition(layer);
    }
}
    两个关于 SetFloat 的重要细节 ① 带阻尼的重载会持续插值。SetFloat(hash, value, dampTime, deltaTime) 让参数平滑过渡，但它每帧都在计算。只对真正需要的参数用（比如移动速度），布尔和 Trigger 不需要。
    ② 每帧无条件 SetFloat 是浪费。如果值没变，这次调用纯属开销。
    加一个 Mathf.Approximately 判断就能省下来——上面的示例代码里就是这么做的。

    四、AudioSource 参数速查

    属性范围说明
    volume0 ~ 1线性音量
    pitch0.1 ~ 31 是原速；0.95~1.05 用于制造变化
    loopbool循环播放
    playOnAwakeboolBGM 常用；音效要关掉
    spatialBlend0 ~ 10 = 2D，1 = 3D；中间值是混合
    rolloffMode枚举3D 衰减曲线，Linear 最可控
    minDistance米此距离内保持最大音量，常用 1~3
    maxDistance米超出后不再衰减，常用 20~40
    priority0 ~ 2550 是最高优先级（很多人搞反）
    dopplerLevel0 ~ 5设为 0 关闭多普勒效应
    两个反直觉的设计 ① priority 数字越小优先级越高。0 是最高，255 是最低。BGM 应设成较低优先级（如 128），重要音效设 0。
    ② dopplerLevel 默认是 1，会产生多普勒效应。高速移动的物体（子弹、飞车）会因此出现怪异的音调变化。绝大多数游戏应该直接设为 0。

    五、Camera 参数要点

    属性说明常用值
    fieldOfView透视相机的垂直视野角FPS 常用 60~90（不是 45）
    orthographicSize正交相机的半高（不是半宽！）2D 游戏按画面需求调
    nearClipPlane近裁剪面太小导致 Z-Fighting，0.3 是常见值
    farClipPlane远裁剪面能小就小，过大会降低深度精度
    clearFlags背景处理3D 用 Skybox；UI 相机用 Depth Only
    cullingMask只渲染哪些层UI 相机排除场景层可省性能
    depth渲染顺序数字大的后渲染，UI 相机要更大
    targetTexture渲染到贴图小地图、监控画面
    orthographicSize 是半高，不是半宽 这是 2D 开发最常见的误解。orthographicSize = 5 表示屏幕垂直方向显示 10 个世界单位（上下各 5）。
    水平方向显示多少取决于宽高比：宽 = 2 x orthographicSize x aspect。
    所以竖屏和横屏下，同样的 orthographicSize 看到的横向范围完全不同——做多分辨率适配时必须考虑这一点。

    六、Renderer 与材质

    属性用途注意
    enabled开关渲染比 SetActive 轻量，组件逻辑仍在运行
    shadowCastingMode是否投射阴影关掉能显著省性能。castShadows 已标记 [Obsolete]（CS0618：Use shadowCastingMode instead）
    receiveShadows是否接收阴影地面保留，小物件关掉
    material材质实例访问会克隆材质！
    sharedMaterial共享材质只读用这个，不会克隆
    materials多材质数组每次访问都创建新数组
    isVisible是否被任何相机看到可用来跳过不可见物体的逻辑
    lightProbeUsage光照探针静态小物件可关掉
    renderer.material 会克隆材质——这是隐形性能杀手 访问 renderer.material 会为该 Renderer 创建一个材质实例。后果是：
    ① 每个物体一份材质，彻底破坏合批；
    ② 每份材质都占内存；
    ③ 这个克隆不会自动销毁。
    三条规则：
    ① 只读属性用 sharedMaterial；
    ② 要改个别物体的颜色，用 MaterialPropertyBlock（但注意它会打断 SRP Batcher，见页 10）；
    ③ 确实需要独立材质时，在 Awake 里拿一次存起来，不要在 Update 里访问。
