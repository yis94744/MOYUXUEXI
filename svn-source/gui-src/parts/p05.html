5查看改动：哪些文件变了

提交之前，你必须先回答一个问题：这次到底改了哪些文件？ 凭记忆是靠不住的——你可能顺手改了个配置文件自己都忘了，也可能留了一堆临时文件在待提交列表里。 这一节讲的，就是提交前的那次「自查」。

为什么要自查：两个真实存在的风险
  • 漏提。该交的文件没交上去，同事更新完发现项目跑不起来，回头来找你——这种问题查起来极费时间。
  • 多提。把本机的调试配置、编译产物、临时备份文件一起交上去，轻则污染仓库，重则把别人的配置覆盖掉（尤其是那种「配置只该存在于本机」的文件）。

自查一次只要十几秒，能挡掉这两类问题。所以每次提交前都扫一眼，慢慢就变成肌肉记忆了。

打开「检查修改」对话框

CHECK看看本地到底有哪些改动
对着项目文件夹（或子文件夹）点右键对哪个文件夹右键，就检查哪个范围。对着项目根目录右键最稳妥，一次看全；只想看某个模块，就对着那个子文件夹右键。
点菜单顶层的 SVN Check for modifications在右键菜单最顶层、带 SVN 前缀的那一组里，位置和 SVN Update、SVN Commit... 挨着。这是唯一不会改动任何东西的操作，随便点，点错也没关系。
看窗口中间的改动列表每一行是一个文件，Status 列告诉你它怎么了，Text status 列告诉你内容有没有变。见下方截图逐列解说。
想看某个文件具体改了什么，双击它会立刻打开比对窗口，把你改的那几行标出来。不确定某个文件该不该提交时，双击看一眼最靠谱（第 6 节详讲）。
想看服务器上有没有新东西，点 Check repository默认这个窗口只反映本地状态——它不会主动连服务器。点一下 Check repository 按钮，它会去问服务器，把远程的状态也填进列表里。
看右下角的统计和版本号统计行把「多少个文件是正常的、多少个被改了、多少个冲突」一次列清。只要 conflicted 不是 0，就必须先处理冲突再提交。
◈检查修改对话框（Check for modifications）Working Copy Status
窗口标题是 工作副本路径 - Working Copy - TortoiseSVN，表示这是「当前工作副本的状态总览」。逐块看：

① 主体列表，每行一个文件，列的含义分别是一—
Path：文件或目录在工作副本里的相对路径。前面那个小图标就是角标，一眼能看出是「已修改」还是「未版本控制」。
Extension：扩展名，用来快速判断这是代码、配置还是资源文件。
Status：这一项的总体状态，常见值有 normal（正常）、modified（已修改）、added（已添加）、deleted（已删除）、missing（文件不见了）、conflicted（冲突）、non-versioned（未纳入版本控制）。
Remote status：服务器上这一项的状态。不点 Check repository 时它多半是空的或 normal。
Text status：文件内容有没有变。这里出现 modified 说明内容确实被你改了。
Property status：文件的属性（比如忽略规则、换行符设置、锁）有没有变。内容没改但属性改了，这里也会显示 modified。
Remote text st... / Remote property st...：服务器端的内容与属性状态，右侧被窗口挡住了，横向拉一下就能看全。

② Items to show（显示哪些条目）——这一组勾选框决定了列表里出现什么：Directories 目录  /  Files 文件  /  Unversioned 未纳入版本控制的  /  Unmodified 没改动的  /  Ignored 被忽略的  /  Properties 属性变化  /  Items in externals 外部引用里的条目。
日常自查的推荐勾法是：勾 Files、Unversioned、Properties，取消 Unmodified 和 Ignored。这样可以一次看到「改过的文件 + 冒出来的新文件」，既不会被几千个正常文件刷屏，也不会漏掉该 Add 的新文件。

③ 右下角统计区——最该看的地方：normal=12010 正常文件数   non-versioned=1 未版本控制   modified=328 已修改   added=10 待添加   deleted=3 待删除   conflicted=0 冲突数   Switched=0 被切换过的目录数。
提交前扫一眼这行：conflicted 必须是 0。

Lowest shown revision: 9323 / Highest shown revision: 29019：当前列表里出现的最低与最高版本号——数字不一样说明你的工作副本里混着不同版本的文件，这在刚更新完、或者只更新了部分目录时很常见。
HEAD revision: 29337：服务器当前的最新版本号。它比 Highest shown 大，就说明你落后了，该更新了。

④ 底部按钮：
Refresh 重新收集一遍本地状态（比如你刚在别的窗口改完文件，点它刷新列表）。
Check repository 连服务器取远程状态，见下面的技巧。
OK 关闭窗口——它只是个查看器，点 OK 不会提交任何东西。

状态字母与图标对照

列表里的 Status 一列，和文件角标是同一套语言。把下面这张表记住，一半的沟通成本就没了。

状态列表里的显示文件角标含义与该怎么办
Normalnormal绿色对勾和仓库完全一致。不用管。（勾了 Unmodified 才会出现在列表里）
Modifiedmodified红色叹号内容被改了，还没提交。这是你主要的提交对象。
Addedadded蓝色加号新文件已标记「要加入版本控制」，提交后才真正进仓库。见第 7 节。
Deleteddeleted红色叉已标记删除，提交后才从仓库消失。用了系统的 Delete 键，这里不会出现这一项。
Missingmissing—文件在磁盘上不见了，但 SVN 还认为它存在。多半是你用资源管理器直接删了它。
Conflictedconflicted黄底红叹号发生了冲突，必须先解决再提交。见第 10 节。
Unversionednon-versioned灰色问号新文件，SVN 还不认识它。二选一：Add 纳入，或 Add to ignore list 忽略。
Ignoredignored无角标（变淡）按忽略规则被排除。默认不显示，勾了 Ignored 才看得到。
Lockedlocked黄色锁被你或别人加了锁。别人加的锁只有 Get lock 里的 steal 才能抢。见第 18 节。

技巧：Shift + 点 Check repository，看「服务器上有但你没检出的文件」

正常点 Check repository，看到的是你本地已有文件的远程状态。如果同事刚往仓库里新增了一个目录，你本地根本还没有这个东西，普通视图里就看不到。

这时候：按住 Shift 不放，再点 Check repository。它会额外把仓库里有、你本地没有的条目也列出来——相当于提前拿到了一份「更新后会多出什么」的清单。

用途很实在：对着清单判断要不要现在就更新，免得更新到一半被人打断、或者在一个大更新前毫无心理准备。

右键菜单里能做什么

在列表里对着某个文件点右键，常用操作都在这里——不用关掉窗口、不用回资源管理器，能省不少来回切换的动作。

查看类（不改动任何东西）
  • Compare with base —— 和库里的原始版本比对，看自己改了哪几行
  • Show log —— 直接跳到这个文件的提交历史
  • Blame... —— 逐行显示每行代码是谁改的
  • Open / Explore to —— 用默认程序打开，或跳到所在文件夹
  • Properties... —— 查看这个文件的属性（忽略规则、锁等）
修改类（会改变本地状态）
  • Revert... —— 撤销这个文件的本地改动，不可逆，改了的东西直接没了
  • Add... —— 把未版本控制的文件纳入版本控制（第 7 节）
  • Add to ignore list —— 忽略它，以后不再出现在待提交列表
  • Delete —— 标记删除（走 SVN，保留历史）
  • Get lock —— 加锁，二进制文件防冲突用（第 18 节）
  • Update —— 只更新这一个文件或目录
两个容易踩的点
  1. 这个窗口的 OK 不是提交。它纯粹是个查看器，点 OK 只是关窗口。真正的提交要去 SVN → Commit...。很多人第一次看到这个窗口，会以为点 OK 就交上去了。
  2. 列表里的 Revert 不可逆。本地那些还没提交的修改会直接消失，找不回来。对着一个刚改了两小时的文件手滑点下去，就只能重做了。第 9 节会专门讲撤销的正确姿势。
提交前的十秒自查清单

按这个顺序扫一遍，心里就有底了：

  1. 列表里有没有我不认识的文件？（多半是编译产物或临时文件，该加忽略）
  2. 列表里有没有该在但没在的文件？（漏提了，或者忘了 Add）
  3. 右下角 conflicted 是不是 0？
  4. HEAD revision 比 Highest shown revision 大吗？大就先更新。
