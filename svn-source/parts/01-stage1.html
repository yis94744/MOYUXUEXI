1SVN 是什么

SVN（Subversion）是一个集中式版本控制系统。一句话概括它的作用： 把文件的每一次修改都记成一条不可篡改的历史，让多人协作时不互相覆盖、随时能回到过去。

它要解决的核心问题只有三个，但每个都很要命：

① 覆盖问题

两个人同时改同一个文件，后保存的把先保存的整个覆盖掉。SVN 通过「先更新再提交」的机制拦住这种情况。

② 回退问题

改了三天发现方向全错，想退回上周五的状态。没有版本控制就只能靠手抄备份。

③ 追责问题

这行代码是谁写的、为什么这么写、当时跟着什么需求一起改的——svn blame 一行行告诉你。

集中式的本质：一个中央仓库

「集中式」这三个字是整个 SVN 设计的地基，理解了它就理解了 SVN 一半的行为。 它意味着：所有历史只存在一个地方——服务器上的那个仓库（Repository）。 每个开发者的电脑上只有一份「工作副本」（Working Copy），是某次快照的解压结果，不含完整历史。

◈图 1-1　集中式 vs 分布式：历史存在哪里Architecture
看图要点：左边 SVN 的所有箭头都指向同一个中心——没有网络就没有版本历史可言。 右边每个节点自己就是一份完整仓库，节点之间是对等关系。 这张图解释了 SVN 的绝大部分「行为特性」：为什么提交要联网、为什么 .svn 目录不大、为什么分支那么轻量（服务端只记一条路径映射）。
一个必须扭转的直觉

很多人以为 SVN 的分支是「复制一份代码」——恰恰相反。 在 SVN 里创建分支是服务端一瞬间的元数据操作，0 字节数据被复制。 第 11 节会用一张图彻底讲清楚这个「廉价复制」机制，这也是 SVN 分支比 Git 更「轻」的地方。

SVN 与 Git 对照：该选谁

这是绕不开的一问。结论先给：SVN 没有死，它在特定场景下依然是最优解。

对比项SVN（集中式）Git（分布式）
历史存放 只在服务器 每人一份完整副本
提交是否需联网 需要 每次 commit 都走网络 不需要 本地 commit，push 才联网
版本号 全局递增整数（r1, r2, r3…）——好沟通 每对象一个 SHA-1 哈希——精确但难口述
分支成本 服务端几乎零成本；但切换要联网 本地瞬时切换
权限粒度 极细 可精确到目录级读/写 通常只能到仓库级
大文件 / 二进制 友好 支持 svn lock 独占锁 弱，需 LFS 外挂
部分检出 原生支持 --depth 稀疏检出 需 sparse-checkout，较繁琐
学习曲线 平缓 约 15 个命令覆盖 95% 场景 陡峭，需理解暂存区、引用、rebase
目录结构 约定俗成 trunk/branches/tags，靠人遵守 内置分支模型
典型用户 企业内网、游戏美术、嵌入式、
需要精细权限的团队		 开源社区、互联网研发
选 SVN 的场景
  • 项目里大量二进制资源（美术图、模型、音效）——Git 仓库会被撑爆
  • 需要目录级权限隔离，比如外包只能看 /trunk/art
  • 团队成员非技术人员多，需要简单直白的模型
  • 公司内网隔离，不希望完整代码库散落在每台电脑上
  • 需要「版本号」这种人类可读的沟通语言（"你回退到 r1523 试试"）
选 Git 的场景
  • 以文本代码为主，需要高频分支、频繁试验
  • 需要离线开发，或网络不稳定
  • 依赖 PR / Code Review 工作流
  • 参与开源协作，需要 fork + pull request
  • 大量历史清理需求（rebase、squash、Cherry-pick）
现实中两者常共存

很多游戏团队的做法是：美术资源用 SVN，程序代码用 Git，两边通过一个脚本同步。 这不是妥协，而是让每个工具做它最擅长的事。

2三层架构与通信协议

SVN 的所有命令都围绕三个东西转：仓库（Repository）→ 工作副本（Working Copy）→ 暂存区（其实是本地元数据）。 把下面这张图刻在脑子里，后面所有命令你都能猜到它作用在哪一层。

◈图 2-1　SVN 三层架构与数据流向Data Flow
关键理解：.svn 目录不是只在根目录有一份（那是 SVN 1.6 及以前的老设计）， 1.7 之后每一级目录都有自己的 .svn，元数据统一存在 wc.db 这个 SQLite 数据库里。 所以你看到 .svn 占空间小得反常——因为历史根本没下载下来， 真正的大头是 pristine/ 里那些「最近一次更新时拿到的原始副本」，它只用于本地 diff 和 revert。

三种部署形态：URL 前缀决定一切

SVN 客户端支持 4 种 URL 协议。你写什么前缀，就用什么方式连服务器—— 这是新手最容易懵的地方，一张图说清：

◈图 2-2　四种 URL 协议与对应部署方式Protocols
怎么选：个人练手用 file://；公司内网、追求简单用 svn://； 需要 HTTPS 加密、走防火墙、接 AD 域认证就用 http(s)://（第 17 节详细对比）。

3安装与环境准备

Windows：三种安装方式

方式一：SlikSVN（只装命令行）

最纯净，只有 svn 和 svnadmin 命令，安装包约 10MB。

适合：服务器、CI 机器、只要命令行的人。

sliksvn.com/download

方式二：VisualSVN Server

一站式服务端，自带图形管理器 + Apache，Web 界面可视化管理仓库与用户。

适合：要搭服务器的 Windows 团队（推荐）。

visualsvn.com/server

方式三：TortoiseSVN（图形外壳）

集成到资源管理器右键菜单，不提供命令行工具（需勾选 command line client tools）。

适合：不习惯命令行的 GUI 用户。

tortoisesvn.net

TortoiseSVN 安装时的一个坑

安装向导默认不勾选「command line client tools」。 如果你既想要右键菜单、又想在脚本里用 svn 命令，安装时必须手动选上这一项， 否则会在命令行里看到 'svn' 不是内部或外部命令。

Linux：包管理器一行搞定

bash安装客户端 + 服务端
# Debian / Ubuntu
sudo apt update && sudo apt install -y subversion

# RHEL / CentOS / Rocky
sudo dnf install -y subversion

# 顺便装上命令行补全工具（强烈推荐，能补全子命令和参数）
sudo apt install -y subversion-tools
# 或
sudo dnf install -y subversion-tools

# 验证
svn --version --quiet          # 只输出版本号，脚本里好用
svn --version -q               # 等价简写
which svn svnadmin svnserve svnlook

macOS：Homebrew

bashmacOS 安装
# macOS 自带的是很老的 1.7/1.8，务必用 brew 装新的
brew install subversion

# 确认用到的是 brew 版本而不是系统自带
which svn
# 期望输出：/opt/homebrew/bin/svn  （而不是 /usr/bin/svn）

# 如果还是系统的，把它加入 PATH 最前面
export PATH="/opt/homebrew/opt/subversion/bin:$PATH"

验证安装：一个自检脚本

装完别急着往下走，先跑这个自检——它能一次性告诉你客户端、服务端工具、协议支持是否齐全。

bashcheck-svn.sh　自检脚本
#!/usr/bin/env bash
# SVN 环境自检：确认客户端、服务端工具链、协议模块是否齐全
set -u

echo "===== 1. 四个核心可执行文件 ====="
for bin in svn svnadmin svnserve svnlook; do
  if command -v "$bin" >/dev/null 2>&1; then
    printf "  [OK]   %-10s %s\n" "$bin" "$(command -v "$bin")"
  else
    printf "  [MISS] %-10s 未安装\n" "$bin"
  fi
done

echo
echo "===== 2. 客户端版本 ====="
svn --version --quiet

echo
echo "===== 3. 仓库访问模块（协议支持）====="
svn --version | grep -E '^\* ra_' || echo "  (未检测到 ra_ 模块，异常)"

echo
echo "===== 4. 服务端工具版本 ====="
svnadmin --version --quiet
svnserve --version --quiet
svnlook --version --quiet

echo
echo "===== 5. 可用子命令总数 ====="
printf "  svn      : %s 个\n" "$(svn help | grep -cE '^   [a-z]')"
printf "  svnadmin : %s 个\n" "$(svnadmin help | grep -cE '^   [a-z]')"

echo
echo "自检完成。"

Windows 用户注意路径写法

本教程的命令在 Windows PowerShell / CMD 与 Linux bash 下完全通用， 唯一要改的是本地路径：Windows 是 E:\repo，Linux 是 /var/svn/repo。 而 URL 里的本地路径必须写成 file:///E:/repo 这种形式（三斜杠 + 盘符 + 正斜杠）。
