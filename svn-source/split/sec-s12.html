◈图 12-1　分支的三种工作模式Branching Modes

创建分支

bash建分支的五种写法
# 【推荐】服务端直接复制，一次提交就完成，不需要工作副本
svn copy https://svn.example.com/repo/trunk \
         https://svn.example.com/repo/branches/feature-login \
         -m "从 trunk 创建 feature-login 分支"

# 【更短】在工作副本内用 ^ 表示仓库根
svn copy ^/trunk ^/branches/feature-login -m "创建分支"

# 【从历史版本建分支】—— 修复老版本的 bug 时很常用
svn copy ^/trunk@520 ^/branches/hotfix-crash -m "基于 r520 创建热修分支"

# 【本地复制 + 提交】需要工作副本，多一步
cd wc
svn copy ^/trunk ^/branches/feature-local
svn commit -m "创建 feature-local 分支"

# 【直接用 mkdir 建空分支】（不推荐，没有历史关联）
svn mkdir ^/branches/empty-branch -m "建空分支"

# 验证分支建好了
svn list ^/branches
实测输出：svn copy 建分支
PowerShell
$ svn copy file:///E:/repo/trunk file:///E:/repo/branches/feature-login -m "从 trunk 创建 feature-login 分支"
Committing transaction...
Committed revision 5.
   ↑ 一次提交，只占一个版本号

$ svn list file:///E:/repo/branches
feature-login/

switch：一个工作副本切成两个分支

svn switch 是 SVN 里非常巧妙的一个命令：它保持本地文件不动， 只把「这个目录对应服务器上哪个 URL」这件事改掉，然后把差异同步过来。

bashswitch 的用法
# 切到分支
cd wc
svn switch ^/branches/feature-login

# 切完整 URL（等价）
svn switch https://svn.example.com/repo/branches/feature-login

# 切回主干
svn switch ^/trunk

# 切到某个历史版本（不是切分支，是把时间指针往回拨）
svn switch ^/trunk@520

# 只切换某个子目录（局部切换）
svn switch ^/branches/feature-login/src src/

# 常用选项
svn switch --ignore-ancestry ^/other-branch    # 忽略祖先关系直接覆盖内容
svn switch --relocate OLD_URL NEW_URL           # 仓库搬家了，改 URL 而不改内容
svn switch --accept postpone                    # 冲突策略

# 验证当前在哪个分支
svn info --show-item relative-url
svn info | grep URL
实测输出：switch 到分支再切回
PowerShell
# 切到分支
$ svn switch file:///E:/repo/branches/feature-login
At revision 5.

$ svn info | Select-String 'URL|Relative URL'
URL: file:///E:/repo/branches/feature-login    ← URL 变了
Relative URL: ^/branches/feature-login

# 在分支上工作并提交
$ Add-Content README.md "## 登录功能（分支开发）"
$ svn commit -m "分支：新增登录功能说明"
Sending        README.md
Committing transaction...
Committed revision 6.       ← 提交进了分支，trunk 完全不受影响

# 切回主干（本地未提交的改动会自动带过去，可能产生冲突）
$ svn switch file:///E:/repo/trunk
U    README.md               ← U = 内容被更新成 trunk 的版本
Updated to revision 6.

$ svn info | Select-String 'URL'
URL: file:///E:/repo/trunk
switch 前务必把手头改动处理掉

如果工作副本里有大量未提交的修改，直接 switch 会让 SVN 试图把这些改动带到目标分支上。 如果两边差异大，会产生一堆莫名其妙的冲突。

正确姿势：switch 之前先 svn status 确认干净， 或者 svn commit / svn revert 处理掉。

另外，实测证实：工作副本处于「混合版本」状态时执行 merge 会直接被拒绝 （E195020: Cannot merge into mixed-revision working copy）， switch 之后紧接着 merge 也容易踩这个坑，记得先 svn update 拉平。
