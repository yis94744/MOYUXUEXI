11分支的本质：一次廉价的复制

如果你只从 Git 过来，SVN 的分支概念会让你困惑三分钟，然后突然豁然开朗。 核心只有一句话：SVN 里的分支就是一个普通目录，复制它只花 0 字节。

「复制」在 SVN 里意味着什么

传统理解里，复制一个 5GB 的目录要占 5GB 空间、花几分钟。 但在 SVN 里，svn copy 创建分支是瞬间完成的，仓库几乎不增长。为什么？

◈图 11-1　廉价复制：分支为什么不占空间Cheap Copy
一句话总结：SVN 的分支就是仓库里多了一个目录，内容是原目录的「快捷方式式引用」。 这解释了两个常见疑问：① 为什么建分支要联网，因为要在服务器上提交一次； ② 为什么分支多了仓库也不膨胀，因为没改的文件共享同一份数据。
分支和标签，在 SVN 里技术上完全一样

这是一个必须点破的事实：SVN 的 tag 不是特殊对象，它就是一个用 svn copy 复制出来的目录。 和 branch 唯一的区别是——约定上你认为它是「发布快照」而不该再改。

SVN 不会阻止你往 /tags/v1.0/ 里提交代码，它照样接受。 想真正实现「标签只读」，得靠 authz 权限控制（第 19 节会给完整配置）。
