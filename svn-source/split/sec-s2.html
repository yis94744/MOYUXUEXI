2三层架构与通信协议

SVN 的所有命令都围绕三个东西转：仓库（Repository）→ 工作副本（Working Copy）→ 暂存区（其实是本地元数据）。 把下面这张图刻在脑子里，后面所有命令你都能猜到它作用在哪一层。

◈图 2-1　SVN 三层架构与数据流向Data Flow
关键理解：.svn 目录不是只在根目录有一份（那是 SVN 1.6 及以前的老设计）， 1.7 之后每一级目录都有自己的 .svn，元数据统一存在 wc.db 这个 SQLite 数据库里。 所以你看到 .svn 占空间小得反常——因为历史根本没下载下来， 真正的大头是 pristine/ 里那些「最近一次更新时拿到的原始副本」，它只用于本地 diff 和 revert。

The following repository access (RA) modules are available:

* ra_svn : Module for accessing a repository using the svn network protocol.
  - handles 'svn' scheme
* ra_local : Module for accessing a repository on local disk.
  - handles 'file' scheme
* ra_serf : Module for accessing a repository via WebDAV protocol using serf.
  - using serf 1.3.10 (compiled with 1.3.10)
  - handles 'http' scheme
  - handles 'https' scheme

输出里列出的 ra_* 模块，就是你实际可用的协议。 如果这份清单里缺了 ra_serf，说明客户端没编译 HTTP 支持，https:// 的仓库就连不上。
