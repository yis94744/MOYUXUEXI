16锁机制：解决二进制文件不能合并的问题

文本文件冲突了可以人工合并，但 PSD、FBX、Unity 场景文件冲突了根本没法合。 对这些文件，唯一的办法是「一个人改的时候别人别动」——这就是 svn lock 的用途。

◈图 16-1　svn:needs-lock 的完整工作流Locking
核心机制：svn:needs-lock 让文件签出后只读， 强制你必须 svn lock 才能编辑。锁在服务器上是一条独立记录， 提交时自动释放，也可以用 svn unlock 主动释放。
bash锁的完整操作
# ---- 1. 给文件设置 needs-lock 属性 ----
svn propset svn:needs-lock "*" art.psd
svn propset svn:needs-lock "*" scene.unity
svn commit -m "为美术源文件设置 svn:needs-lock"

# 批量设置
find art -type f \( -name "*.psd" -o -name "*.max" \) \
  -exec svn propset svn:needs-lock "*" {} \;
svn commit -m "美术资源统一加锁保护"

# ---- 2. 加锁（编辑前必须做）----
svn lock art.psd
svn lock art.psd -m "正在调整封面配色，预计 2 小时"   # 带说明更友好
svn lock art/*.psd                                      # 批量加锁

# ---- 3. 查看锁 ----
svn info art.psd                     # 输出里的 Lock Owner / Lock Created
svn status                           # 加锁的文件在第 6 列显示 K
svnadmin lslocks /var/svn/repo       # 服务端查看所有锁
svnadmin lstxns /var/svn/repo        # 查看未完成的事务

# ---- 4. 解锁（提交时会自动解，也可手动）----
svn unlock art.psd
svn unlock --force art.psd           # 强制解锁别人的锁（需要权限，慎用）
svn unlock --force -R art/           # 递归强制解锁整个目录

# ---- 5. 别人要抢锁 ----
svn lock art.psd --force             # 强制抢锁（会破坏对方的工作，需要沟通！）
# 服务端管理员也可以：
svnadmin rmlocks /var/svn/repo art.psd   # 管理员移除锁

# ---- 6. 查看工作副本里的锁状态 ----
svn status -u                        # 显示服务器上的锁
svn status --show-updates            # 同上

锁 vs 分支：什么时候用哪个
场景推荐方案理由
改一个 PSD 的配色svn lock二进制无法合并，加锁最直接
重构整个模块（多个文件）建分支涉及多文件，锁不住；分支让改动隔离
修一行 bug直接改 + commit改动小，冲突概率极低
给旧版本打补丁从标签建 热修分支主干已经走远，不能直接在上面改
多个美术同时改同一个场景文件lock + 沟通Unity 场景是二进制，必须串行
