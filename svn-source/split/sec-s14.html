14标签与发布管理

bash打标签的三种场景
# 【场景 1】发布正式版：从 trunk 打标签
svn copy ^/trunk ^/tags/v1.0.0 -m "发布 v1.0.0：从 trunk 打标签"

# 【场景 2】从修复分支打标签（发布了 hotfix）
svn copy ^/branches/release-1.0 ^/tags/v1.0.1 -m "发布 v1.0.1：包含紧急修复"

# 【场景 3】给历史版本补打标签（当时忘了打）
svn copy ^/trunk@520 ^/tags/v1.0.0-retro -m "补打 v1.0.0 标签（对应 r520）"

# 【验证】标签与 trunk 应该零差异
svn diff ^/tags/v1.0.0 ^/trunk --summarize
# 无输出 = 完全一致
# 如果打标签后又往 trunk 提交了东西，这里就会显示出差异文件

# 【检出标签】发布构建用
svn checkout ^/tags/v1.0.0 release-1.0.0
svn export ^/tags/v1.0.0 release-1.0.0    # 更干净，无 .svn

# 【删除标签】打错了
svn delete ^/tags/v1.0.0 -m "撤销误打的标签"
实测输出：打标签并验证
PowerShell
$ svn copy file:///E:/repo/trunk file:///E:/repo/tags/v1.0-release -m "发布 v1.0：从 trunk 打标签"
Committing transaction...
Committed revision 21.

# 验证：标签与 trunk 零差异（刚刚打的，trunk 没变过）
$ svn diff file:///E:/repo/tags/v1.0-release file:///E:/repo/trunk --summarize
<空输出 = 完全一致>

用 authz 强制标签只读

前面说过 SVN 不会阻止你改标签。想真正锁死，靠 authz 权限文件—— 这是 SVN 相对 Git 的一个优势：目录级权限。

iniconf/authz　标签只读配置
[groups]
admins = alice, bob          # 只有这两个人能改标签
devs   = carol, dave

# 仓库根：默认无权限，逐条放开
[/]
* =
@admins = rw

# 主干：开发全员可读写
[/trunk]
@devs = rw
@admins = rw

# 分支：开发可读写
[/branches]
@devs = rw
@admins = rw

# 标签：所有人只读，只有 admins 能写
[/tags]
* = r
@admins = rw
实测：权限配置生效，普通开发者写标签被拒
PowerShell
# bob 属于 devs 组，不是 admins → 往 /tags 写会被拒
$ svn mkdir --username bob --password bob123 svn://127.0.0.1/repo/tags/v2.0 -m "bob 写 tags"
svn: E220004: Access denied

# alice 属于 admins → 成功
$ svn mkdir --username alice --password alice123 svn://127.0.0.1/repo/tags/v2.0 -m "alice 打标签"
Committing transaction...
Committed revision 15.

# bob 读 /trunk 是允许的（authz 里给了 r）
$ svn list --username bob --password bob123 svn://127.0.0.1/repo/trunk
art.psd
docs.md
src/

发布管理的实践建议

标签命名要能排序

用零填充让版本号能按字典序正确排序：

✓ v1.0.0 / v1.0.1 / v1.10.0
✗ v1 / v1.2 / v1.10
   （字典序里 v1.10 < v1.2，会排错）

语义化版本 v主.次.修 是目前最通用的约定。

标签里别再提交

一旦打了标签，就该视为冻结的化石。发现 bug 怎么办？

  • 从该标签创建修复分支：svn copy ^/tags/v1.0.0 ^/branches/hotfix-1.0.1
  • 在分支上修，打完补丁再打新标签 v1.0.1
  • 这样 v1.0.0 永远是「当时发出去的那份」，可复现
发布构建的标准脚本片段
bash从标签构建发布包
#!/usr/bin/env bash
# 从指定标签导出并构建发布包
set -euo pipefail

TAG="${1:-v1.0.0}"
REPO="https://svn.example.com/repo"
BUILD="./build-${TAG}"

# export 而非 checkout：产物里不含 .svn，可直接打包
svn export --force "${REPO}/tags/${TAG}" "${BUILD}" \
  --username build-bot --password "${SVN_PASS}" --non-interactive

# 记录构建来源，便于事后追溯
cat > "${BUILD}/BUILD-INFO.txt" <<EOF
tag          : ${TAG}
built_at     : $(date -Iseconds)
built_by     : $(whoami)
svn_revision : $(svn info --show-item revision "${REPO}/tags/${TAG}")
EOF

tar czf "${TAG}.tar.gz" -C "${BUILD}" .
echo "发布包已生成: ${TAG}.tar.gz"
