    01 · 岗位与行业现实

    先搞清楚你要转的是什么。游戏后端、Web 后端、全栈是三个要求不同的方向——薪资、门槛、发展路径都不同。

    这一页在路线中的位置 上一页路线总览 —— 整条路线的结构、两段式设计与学习节奏。
    这一页（01）岗位与行业现实 —— 游戏后端 vs Web 后端 vs 全栈：分工、薪资、技能要求。
    下一页（02）环境搭建与第一个 API —— 装 .NET SDK、跑起第一个 Web API、理解请求响应。

    一、三条路径对比

    方向做什么门槛你的优势
    游戏后端战斗服、匹配、排行、跨服中（需懂游戏架构）懂玩法，最稀缺
    Web 后端业务系统、中台、CRUD低要补业务领域知识
    全栈一个人从前端到部署高（面广）能独立扛项目
    我的建议：先游戏后端，再全栈 不要一上来就急着做「全栈」——全栈的前提是有一项擅长。

    现实路径：
    ① 先补后端基础（03-10 页）——不管走哪条路都要
    ② 做游戏后端（11-19 页）——你的差异化优势在这
    ③ 补全栈能力（20-24 页）——能独立做运营后台就够了

    「全栈」不是「什么都懂一点」，而是「能一个人把项目做完」。

    二、薪资与需求（参考）

    岗位国内需求薪资水平备注
    游戏后端中较高大厂需求稳定
    Web 后端很大中等竞争激烈
    全栈中（创业公司多）看能力小团队刚需
    客户端主程中较高你现在的定位
    一个现实提醒 转后端不会立刻涨薪——前期大概率是平薪甚至降薪。

    原因：
    · 你的后端经验是零——面试官按初级后端评估
    · 游戏客户端的经验不能直接折算成后端年限
    · 但懂游戏业务这一点确实稀缺

    什么时候值得转：
    · 想做技术负责人（必须懂前后端）
    · 想自己接项目或创业
    · 客户端遇到天花板，想拓宽能力

    如果只是「听说后端工资高」，建议先了解清楚再做决定。

    三、你的能力盘点

    你可能已经有的需要补的
    C# 语言（扎实）ASP.NET Core 框架
    网络编程概念HTTP/REST 规范
    性能调优直觉数据库与 SQL
    游戏业务理解缓存与消息队列
    工程化意识部署与运维
    调试能力分布式问题排查
    一个容易忽略的盲区 客户端和后端最大的思维差异：客户端「可以重启」，后端「不能」。

    · 客户端崩了 → 玩家重进游戏
    · 后端崩了 → 所有玩家掉线 + 数据可能损坏

    这带来几个必须改的习惯：
    · 所有操作要幂等——重复请求不能重复扣钱
    · 所有状态要能恢复——进程崩了要能从数据库恢复
    · 边界条件要防御——客户端传什么都得校验

    这些在客户端是「最好有」，在后端是「必须有」。

    本章动手任务

    本章过关标准：
    ① 能说出三条路径的差异与门槛；
    ② 知道转后端前期可能不涨薪；
    ③ 知道「全栈」= 能一个人把项目做完，不是什么都懂一点；
    ④ 盘点了自己的能力，列出待补项；
    ⑤ 明确了目标方向。

    这一页的标准很低——**只要能回答「转什么、为什么转」就够了**。
