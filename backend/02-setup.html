    02 · 环境搭建与第一个 API

    这一页的目标：半小时内跑起第一个 Web API，用浏览器看到 JSON 返回。后端的第一步比 Unity 简单——没有引擎要装。

    一、装 .NET SDK

    方式命令说明
    官方安装包下载 .NET 8 SDK推荐新手
    脚本安装dotnet-install.ps1无需管理员，可装到指定目录
    已有 Visual Studio勾选「.NET 桌面开发」顺带就装了
    验证dotnet --version应输出 8.x.x
    为什么用 .NET 8 选择依据：
    · LTS（长期支持）——2026 年 11 月前有官方支持
    · 性能比 .NET 6 提升明显
    · 生态成熟，第三方库都支持

    .NET 9 / 10 也可以用——但新版本第三方库跟进慢，生产环境建议 LTS。

    和 Unity 的关系：Unity 用的是 .NET Standard 2.1 子集——后端可以用完整 .NET，不受 Unity 限制。
    不必担心「和 Unity 版本冲突」——它们是两套运行时。

    二、第一个项目

    三条命令跑起来 ① 创建项目
    dotnet new web -n MyFirstApi

    ② 进入目录并运行
    cd MyFirstApi
    dotnet run

    ③ 浏览器访问
    http://localhost:5000（端口看控制台输出）

    会看到 Hello World!

    发生了什么：
    · dotnet new web——生成最小 Web API 项目
    · dotnet run——编译 + 启动 Kestrel 服务器
    · Kestrel 是 .NET 内置的 Web 服务器，不需要额外装 Nginx（生产环境通常会加）
    项目结构只有三个文件 最小 Web API 的结构：
    MyFirstApi/
    ├── Program.cs——入口 + 路由
    ├── MyFirstApi.csproj——项目配置
    └── Properties/launchSettings.json——启动配置

    对比 Unity：
    · Unity 项目有上千个文件
    · 后端项目三个文件就能跑

    这就是为什么后端入门比游戏开发快——没有引擎那层复杂度。

    三、最快的验证：改一行代码

    真正的「跑通」标准 不是看到 Hello World，而是能改代码并看到变化。

    任务：把返回内容改成一段 JSON。
    app.MapGet("/hero", () => new {
      Id = 1001,
      Name = "勇者",
      Level = 10
    });

    访问 /hero → 应看到：
    {"id":1001,"name":"勇者","level":10}

    这一刻你才真正跑通了：改代码 → 重新编译 → 看到新结果。
    两个常见卡点 ① 端口冲突
    提示 Address already in use
    → 换端口：dotnet run --urls "http://localhost:5100"

    ② 找不到 dotnet 命令
    装完需要重开终端（PATH 才生效）
    → 或用绝对路径：C:\Program Files\dotnet\dotnet.exe --version

    ③ HTTPS 证书警告
    首次运行可能提示证书不受信任
    → 执行一次 dotnet dev-certs https --trust

    本章动手任务

    本章过关标准：
    ① 装好 .NET 8 SDK 并能运行；
    ② 成功创建并启动一个 Web API 项目；
