    一、基础函数

    函数作用示例
    print(...)输出print("a", 1)
    type(v)返回类型字符串type({}) == "table"
    tostring(v)转字符串tostring(42) == "42"
    tonumber(s [, base])转数字tonumber("42")
    #t长度#{1,2,3} == 3
    select(n, ...)取第 n 个起 / 计数select("#",1,nil,3) == 3
    assert(v, msg)断言assert(x, "不能为nil")
    error(msg [, level])抛错error("出错了", 2)
    pcall(f, ...)保护调用返回 ok, ...
    xpcall(f, h, ...)带处理器h 里可拿堆栈
    ipairs(t)数组迭代连续数组
    pairs(t)全表迭代顺序不确定
    next(t [, k])下一个键值pairs 的底层
    rawget/rawset绕过元表不触发 __index
    rawequal绕过 __eq直接比较
    setmetatable/getmetatable元表操作Lua 的核心机制
    load(chunk [, name [, mode [, env]]])加载代码第 4 参可做沙箱
    三个必须记牢的 ① select("#", ...) 是唯一可靠的参数计数
    #arg 对含 nil 的表是未定义行为。

    ② rawget 绕过元表
    想确认"表里真的有没有这个字段"，必须用 rawget。

    ③ load 的第四个参数是沙箱的关键
    load(code, name, "t", customEnv) —— 这样脚本里的全局变量会去 customEnv 找。

    二、string 库

    函数作用备注
    string.format(fmt, ...)格式化类似 printf
    string.rep(s, n [, sep])重复rep("ab",3) → ababab
    string.sub(s, i [, j])子串负数索引从末尾算
    string.len(s)长度等同 #s
    string.upper/lower大小写只处理 ASCII
    string.find(s, pat [, init [, plain]])查找第 4 参 true = 不用模式
    string.match(s, pat)提取捕获返回捕获组
    string.gmatch(s, pat)迭代匹配for w in s:gmatch("%a+")
    string.gsub(s, pat, repl [, n])替换repl 可以是函数
    string.byte/char字符码byte("A") == 65
    string.reverse反转
    string.pack/unpack二进制打包5.3+ 新增
    string.packsize计算打包大小5.3 随 pack 一起新增
    % 转义与 plain 参数 Lua 的模式不是正则，但语法相似——大部分特殊字符要加 % 转义：
    "a.b.c":match("%.") → 匹配字面量 .
    "a.b.c":match(".") → . 匹配任意字符

    find 的第四个参数（plain）：
    find("a.b.c", ".", 1, true) → 返回 2（按纯文本找）
    find("a.b.c", ".") → 返回 1（按模式匹配）

    要查找用户输入的字符串（可能含特殊字符），必须传 true。

    三、table 库

    函数作用注意
    table.insert(t, [pos,] v)插入pos 处插入会移动后续元素
    table.remove(t [, pos])删除并返回remove(t,1) 是 O(n)
    table.concat(t [, sep [, i [, j]]])拼接循环拼接必须用它
    table.sort(t [, comp])排序comp 必须是严格弱序
    table.unpack(t [, i [, j]])展开5.2+ 从 unpack 改名
    table.pack(...)打包带 n 字段
    table.move(a1, f, e, t [, a2])移动5.3+ 新增
    两个易错点 ① table.sort 的比较函数必须是"严格弱序"
    错误写法：function(a,b) return a <= b end —— 用了 <=
    这会导致：invalid order function for sorting 错误
    正确写法：function(a,b) return a < b end

    ② table.remove(t, 1) 是 O(n)
    删除第一个元素要移动后面所有元素。
    队列应该用环形缓冲或头尾索引（见算法站页 03）。
    实测差距可达 500 倍。

    四、math 库

    函数作用备注
    math.floor/ceil向下/上取整
    math.abs/max/min绝对值/最值
    math.sqrt(x)平方根
    math.huge无穷大比任何数都大
    math.pi圆周率
    math.maxinteger/mininteger整数边界5.3+ 新增
    math.type(x)区分 integer/float5.3+ 新增
    math.tointeger(x)转整数（失败返回 nil）5.3+ 新增
    math.random([m [, n]])随机数随机种子见下
    math.randomseed(x)设种子5.4 起解释器启动时自动播种，可以不调
    math.fmod取余与 % 在负数时不同
    整数与浮点的三个坑 ① 3 和 3.0 相等但不是同一类型
    3 == 3.0 → true（值相等）
    math.type(3) → "integer"
    math.type(3.0) → "float"
    做哈希 key 或序列化时，这两个要区分对待。

    ② 整数除法与浮点除法是两个运算符
    7 / 2 → 3.5（浮点）
    7 // 2 → 3（整除）

    ③ 整数会溢出回绕（不会变浮点）
    math.maxinteger + 1 == math.mininteger → true

    五、os / io / 协程

    函数作用备注
    os.time()时间戳（秒）不是毫秒
    os.clock()CPU 时间测性能用这个
    os.date(fmt)格式化时间os.date("%Y-%m-%d")
    os.getenv(name)读环境变量沙箱里要禁用
    os.execute(cmd)执行命令沙箱里必须禁用
    io.open(path, mode)打开文件沙箱里要禁用
    io.write(...)写输出不自动换行
    coroutine.create(f)创建协程不会自动运行
    coroutine.resume(co, ...)恢复返回 ok, ...
    coroutine.yield(...)暂停交出控制权
    coroutine.wrap(f)包装出错会抛出
    coroutine.status(co)状态4 种：running/suspended/normal/dead
    coroutine.isyieldable()能否 yield5.3+ 新增
    两个测性能的选择 测性能用 os.clock()
    它返回 CPU 时间，不受系统调度、其他进程影响。
    测真实时间用 os.time()——但精度只有秒，太粗。

    需要毫秒级真实时间：
    · Unity 项目里用 C# 的 Time.realtimeSinceStartup（通过 xLua 调）
    · 或 os.clock()（绝大多数性能测试够用）

    本站在所有性能测试里用的都是 os.clock()。

    六、Lua 5.4 新增特性

    特性说明用途
    to-be-closed 变量local x <close> = res离开作用域自动清理
    __close 元方法配合 <close>相当于 C# 的 using
    const 变量local x <const> = v编译期常量，可能被优化
    整数除法 //向下取整5.3+
    math.type区分整型/浮点5.3+
    to-be-closed 最实用的场景 自动释放资源：
    do
  local file <close> = io.open("data.txt")
  -- 使用 file
end
-- 离开作用域时自动 close()
    对比手动管理：忘记 close 会泄漏文件句柄。
    对比 pcall 包装：即使中途 error，__close 也会被调用。

    在游戏里可用于：
    · 加锁/解锁
    · 临时修改状态后自动还原
    · 性能计时的自动结束

    这是 5.4 最值得用的新特性。

    七、调试相关

    函数作用备注
    debug.traceback([msg])获取调用栈配合 xpcall 使用
    debug.getinfo([thread,] f [, what])获取函数信息性能开销大
    debug.sethook(hook, mask)设置钩子可用于 profiler
    debug.getupvalue(f, n)读闭包变量调试用
    debug.getlocal(level, n)读局部变量调试用
    debug 库的性能代价 debug.getinfo 非常慢——它会生成完整的函数信息表。
    千万不要在热路径上调用。

    安全的用法：
    · debug.traceback 只在错误处理时调用
    · debug.getinfo 只在调试工具里用
    · 生产环境可以考虑移除 debug 库（减小包体、提升安全）

    沙箱环境里通常也会移除 debug 库。

    八、常用代码片段

    片段一：安全的深拷贝 
    local function deepCopy(obj, seen)
  if type(obj) ~= "table" then return obj end
  seen = seen or {}
  if seen[obj] then return seen[obj] end
  local copy = {}
  seen[obj] = copy
  for k, v in pairs(obj) do
    copy[deepCopy(k, seen)] = deepCopy(v, seen)
  end
  return setmetatable(copy, getmetatable(obj))
end
    关键点：用 seen 表处理循环引用，否则会无限递归。
    片段二：带堆栈的错误处理 
    local function try(fn, ...)
  local ok, err = xpcall(fn, debug.traceback, ...)
  if not ok then
    print("[错误] " .. tostring(err))
    -- 上报服务器
  end
  return ok, err
end
    用法：框架的顶层回调（UI 按钮、网络回调、定时器）都应该用它包一层。
    片段三：类型安全的断言 
    local function checkArgs(...)
  local args = { ... }
  for i = 1, select("#", ...) do
    assert(args[i] ~= nil,
      "参数 " .. i .. " 不能为 nil")
  end
end
    关键点：用 select("#", ...) 而不是 #args——因为参数可能含 nil。
    片段四：只读表 
    local function readonly(t)
  return setmetatable({}, {
    __index = t,
    __newindex = function()
      error("这是只读表", 2)
    end,
    __len = function() return #t end,
    __pairs = function() return pairs(t) end,
  })
end
    用途：配置表加载后设为只读，防止业务代码意外修改（见页 14）。
    片段五：性能计时 
    local function timeIt(name, fn)
  local t = os.clock()
  local results = { fn() }
  local dt = (os.clock() - t) * 1000
  if dt > 1 then   -- 只报告超过 1ms 的
    print(string.format("[耗时] %s: %.2f ms", name, dt))
  end
  return table.unpack(results)
end
    关键点：只报告超过阈值的——避免日志本身成为瓶颈（见页 19）。
