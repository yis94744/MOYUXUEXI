    一、xLua 的核心能力

    能力说明使用频率
    Lua 调用 C#Lua 里访问 C# 的类、方法、属性极高
    C# 调用 LuaC# 里执行 Lua 代码、访问 Lua 变量高
    热补丁（hotfix）用 Lua 替换 C# 的方法高
    生成代码预生成绑定代码，避免反射性能关键
    调试支持VS Code 断点调试 Lua开发期常用
    热补丁是 xLua 最有价值的能力 场景：一个 C# 写的老项目，逻辑散落各处。全改成 Lua 成本太高。

    xLua 的热补丁让你只替换有问题的那几个方法：
    xlua.hotfix(CS.GameLogic, "CalculateDamage", function(self, atk, def)
      return atk * 1.5 - def
    end)

    代价：
    · 被 hotfix 的方法调用开销变大（要过一次 Lua）
    · 需要预先生成绑定代码（不能运行时反射）
    所以：只 hotfix 真正需要频繁调整的方法，不要全量 hotfix。

    二、C# 与 Lua 的类型映射

    跨语言调用有隐式转换规则。不知道规则就会写出"看起来对但很慢"的代码。

    Lua 类型C# 类型转换方式开销
    numberint / float / double直接映射极低
    booleanbool直接映射极低
    stringstring需要拷贝中
    tableclass / struct创建新对象高
    functiondelegate创建委托高
    nilnull直接映射极低
    三个性能黑洞 ① Vector3 之类的 struct 传递
    Lua 里 transform.position = Vector3(x, y, z)
    每次都创建一个新的 C# struct 对象——这是 GC 的重灾区。
    优化：用 xLua 提供的 xlua.struct 或缓存 Vector3 对象复用。

    ② 频繁的 string 转换
    C# string 传给 Lua 要拷贝一份。每个字符串都有开销。
    优化：避免在热路径上频繁传字符串（比如每帧拼接日志）。

    ③ Lua table 转 C# 对象
    CS.SomeClass(table) 会创建一个完整的 C# 对象并逐字段拷贝。
    优化：复用对象，不要每次 new。

    三、生成代码：性能的关键

    为什么必须生成代码 两种调用方式：
    ① 反射模式：运行时查方法 → 慢 10~100 倍
    ② 生成代码：编译期生成绑定函数 → 接近原生调用

    做法：
    · 在 C# 类上加 [LuaCallCSharp] 标记
    · 生成 XLua/Generate Code
    · 生成的代码会出现在 Assets/XLua/Gen/ 下

    必须注意：
    · 没标记的类走反射，性能差
    · 标记要精确——全量标记会让包体暴增、编译变慢
    · 每次改标记后要重新生成

    这是 xLua 项目性能优化的第一优先级。
