一、跨语言调用的真实成本

先看一组实测数据（数量级参考，具体值因机器而异）。

操作相对开销说明
Lua 内部函数调用1x基准
Lua 调 C#（已生成代码）5~20x有栈切换成本
Lua 调 C#（反射）100x+必须避免
Lua 调 C# 并创建对象50~200x还有 GC 压力
C# 调 Lua（已生成代码）5~20x同样有切换成本
核心原则：减少跨语言的调用次数 不是"减少每次调用的开销"，而是"减少调用次数"。

反面例子（每帧调用 N 次）：
for i = 1, 100 do
  transform.position = Vector3(i, 0, 0) -- 100 次跨语言调用
end

正面例子（跨语言 1 次）：
local positions = {}
for i = 1, 100 do positions[i] = {i, 0, 0} end
batchSetter(positions) -- 1 次调用，批量设置

这是 xLua 优化的第一原则——把 N 次调用合并成 1 次。

二、GC 优化（xLua 的重灾区）

每一次跨语言调用都可能产生垃圾 垃圾来源：
① 参数装箱——Lua number 传给 C# 的 object 参数
② 临时对象——Vector3、Color 等 struct
③ 字符串拷贝——每次传 string 都复制
④ 委托创建——传 Lua function 给 C# 的 delegate 参数

优化手段：
· 缓存 Vector3：local tmpVec = CS.UnityEngine.Vector3.zero，用 Set 修改而不是 new
· 避免传字符串：用数字 ID 或缓存字符串引用
· 避免传函数：用事件 ID + 注册表代替直接传 delegate
· 给值类型加 [GCOptimize]：让 struct 在 Lua 与 C# 之间传递不产生 GC Alloc（见下）
关于 Vector3 的一个常见误解 「xLua 提供了一个 xlua.struct 让 struct 按值语义传」——没有这个 API。
xLua 的 Lua 侧接口（官方 XLua_API 文档所列）只有 xlua.hotfix / xlua.private_accessible / xlua.structclone / xlua.get_generic_method / cast / typeof / uint64.*， 官方文档里不存在 xlua.struct。

真正管 struct 的是 C# 侧的 [GCOptimize] 标签：
· 加在「字段全是值类型」的 struct（或枚举）上，xLua 会为它生成无 GC 的打包/解包代码
· 加了这个标签之后，Vector3 这类值类型在通过 delegate、无 GC 接口或数组传递时才不产生 GC Alloc
· Unity 内置的 Vector2/Vector3/Color/Quaternion 等，xLua 已经预置了 GCOptimize 配置

所以「每次 Vector3(x,y,z) 都是 GC 重灾区」这个说法要打个折： 真正贵的是调用次数（每次跨语言调用都有栈切换），而不只是对象本身。
结论不变：把 N 次调用合成 1 次，收益远大于纠结「这个 struct 会不会分配」。
验证方法 Profiler 看 GC Alloc 列：
· 目标：Update 相关的 GC Alloc 降到 0 B
· 如果有分配，展开调用树，定位到具体哪一行

常见的高分配位置：
· transform.position 的读写
· Debug.Log 里的字符串拼接
· 每帧的 UI 文本更新

这些在纯 C# 项目里可能不是问题，但在 Lua + C# 的边界上，成本被放大了。

三、六个实战优化技巧

技巧做法收益
批量操作N 次调用合并成 1 次极大
缓存引用local go = CS.UnityEngine.GameObject中
缓存组件不要每帧 GetComponent大
避免反射标记 [LuaCallCSharp] 并生成代码极大
减少字符串用数字 ID 代替字符串中
分帧执行把耗时逻辑摊到多帧大
缓存引用的正确姿势 差的写法（每帧都在查 CS 表）：
for i = 1, 100 do
  CS.UnityEngine.GameObject.Find("Enemy")
end

好的写法：
local GameObject = CS.UnityEngine.GameObject -- 模块顶部缓存
for i = 1, 100 do GameObject.Find("Enemy") end

但要小心：缓存的是"类引用"，不是"实例引用"。
C# 的 UnityEngine.Object 被 Destroy 后，Lua 侧拿到的对象不是 nil（"假 null"）， obj ~= nil 判不出来——要写成 if obj and not obj:Equals(nil) then，或者先用 xlua.private_accessible 之外的方式拿到 UnityEngine.Object.op_Equality 再比较。
这是 xLua 项目里非常高频的一类空引用崩溃（详见 C# 站页 11 的"假 null"）。
