二、⭐ 一个真实踩到的坑：self.super 无限递归

错误示范：这样写会栈溢出 我最初写这一页的示例时，就是这么写的： 
local Character = class("Character", Entity)

function Character:ctor(id, name)
  self.super.ctor(self, id, name)   -- ❌ 无限递归！
end
运行结果：stack overflow，堆栈里全是同一个 ctor 在循环调用。 看起来完全合理对不对？——"我在 Character 里，调父类 Entity 的 ctor"。 但它错了，而且错得很隐蔽。
根因：self.super 查的是"实例的类"，不是"当前方法的类" 关键理解：self 是实例，不是类。 · self.super 实际是 getmetatable(self).super · 而 getmetatable(self) 是实例所属的类（Player） · 所以 p.super 永远是 Character（Player 的父类） 本页实测验证了这一点： 
p.super 实际是: Character
-- 注意！p 是 Player 的实例，但 p.super 拿到的是 Character
于是递归发生了： · 创建 Player 实例 → 调用 Character:ctor · 里面写 self.super.ctor → self 是 p → p.super 是 Character · 结果又调用了 Character:ctor → 无限循环 三级继承时必然踩坑，两级可能侥幸不崩（因为 self 的类与当前类刚好一致）。
正确做法：用局部变量捕获父类 每个类都要单独捕获自己的父类： 
local Character = class("Character", Entity)
local super = Character.super          -- ✅ 捕获

function Character:ctor(id, name)
  super.ctor(self, id, name)           -- ✅ 用局部变量
end

local Player = class("Player", Character)
local superPlayer = Player.super        -- ✅ 每个类单独捕获

function Player:ctor(id, name, role)
  superPlayer.ctor(self, id, name, role)
end
为什么这样对：局部变量 super 在定义方法时就已经绑定到 Character.super（= Entity），与 self 是谁无关。 本页实测：三级继承正确工作 
勇者(id=1, hp=100/100), lv=1, role=战士, gold=0 [VIP]
这一行的每一段都来自不同层级的构造函数——说明 super 调用链完全正确。

三、组合优于继承

组件化：避免类爆炸 问题：如果 UI 界面都靠继承，每加一个能力，组合数翻倍： ListView, RedDotView, ListViewRedDot, AnimListView, AnimRedDotListView… 解决：把能力做成可挂载的组件： 
local bagView = View.new("背包界面")
bagView:addComponent(ListComponent, 20)
bagView:addComponent(RedDotComponent, "bag.new")
本页实测输出： · 组件数量: 2 · 列表组件滚动到: 250 · 红点组件刷新: true / true(无变化) / false(消失) 注意第二次 refresh(true) 返回 false——红点组件会做状态去重，无变化时不触发 UI 刷新。这是很实用的优化。

四、类注册表：配置驱动

把"类型判断"变成"查表" 没有注册表时： 
if typeName == "Player" then new(Player, ...)
elseif typeName == "Monster" then new(Monster, ...)
elseif ... end
每新增一种类型都要改这段代码。 有注册表时： 
ClassRegistry.register("Player", Player)
local obj = ClassRegistry.create(cfg.class, table.unpack(cfg.args))
本页实测：从配置表批量创建了 3 个对象（2 个 Player + 1 个 Entity），代码里没有任何类型判断。 价值：策划在配置表里写 "Player"，代码就能创建对应对象——加新类型不用改代码。

五、单例的状态残留 ★★

Lua 热更项目最常见的疑难 bug 问题：Lua 模块是全局缓存的，重新加载脚本时单例的状态会残留。 触发场景： · 热更新后重新执行模块代码 · 编辑器里停止播放再重新开始 · 结果：上次的数据还在，产生诡异 bug 三种解决办法： ① 提供 reset() 方法——框架启动时统一调用所有单例的 reset ② 在模块末尾返回新表——避免缓存旧表 ③ 避免在单例里存"应该有生命周期"的数据——那类数据应该属于具体对象 这一条在页 18（调试排错）会再次出现——它是 Lua 项目最容易被忽视、又最难排查的问题之一。
