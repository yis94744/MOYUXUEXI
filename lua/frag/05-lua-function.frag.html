05 · 函数与闭包

Lua 的函数是一等公民——可以赋给变量、存进表、当参数传、当返回值。这让 Lua 能写出非常灵活的代码，但也带来两个必须理解的概念：闭包和尾调用。

一、函数的多种形态

缺少代码样本05/function
多返回值的三个陷阱 陷阱一：多返回值在表达式中间会被截断为 1 个
print(three(), "结束") —— 只输出第一个值。
print("开始", three()) —— 三个值都在（因为它在最后）。
要完整保留，用 table.pack(f()) 或把调用放在最后。

陷阱二：{...} 会丢掉中间的 nil
local t = {...} 之后 #t 不可靠。要准确计数必须用 select("#", ...)。

陷阱三：加括号会强制只取一个值
(three()) 只返回第一个值。这是"显式截断"的标准写法。
local function 与 local f = function 的区别 local function f() ... end——定义时就把 f 放进作用域，所以函数体里能递归调用自己。
local f = function() ... end——赋值时 f 还是 nil，函数体里访问 f 会得到全局的 f（通常是 nil）。

结论：需要递归时，必须用 local function。

二、闭包：捕获外部变量 ★★

闭包是函数 + 它捕获的外部变量的组合。它是 Lua 里实现"私有状态"的标准手段，也是性能陷阱的高发区。

闭包的两个经典用途 ① 私有状态（真正的私有，外部无法访问）
把变量声明成局部变量，然后让方法闭包捕获它。这是 Lua 里唯一能实现"真私有"的方式——用 _ 前缀只是约定，外部照样能改。

② 工厂函数 / 带状态的函数
makeCounter() 每次调用返回一个独立计数的函数——两个 counter 互不影响，因为它们捕获的是不同的局部变量。
闭包的性能陷阱：循环内创建 实测数据（Lua 5.4，300 万次循环）：
• 循环内每次创建闭包：0.34 秒
• 循环外创建一次复用：0.07 秒
• 相差约 5 倍

原因：每次创建闭包都会分配一个新的函数对象并捕获变量，这有内存分配成本。

规则：热路径（Update、循环体）里不要在循环内创建匿名函数。
把函数提到循环外，或定义成模块级局部函数。

三、尾调用优化 ★

什么是尾调用 当一个函数的最后一个动作是"返回另一个函数的调用结果"，且没有额外运算时，Lua 会复用当前栈帧，不会累积调用栈。

是尾调用：return f(x)
不是尾调用：return f(x) + 1（有加法）、return f(x), g(y)（多个返回值）
实测数据：栈深度差异 在 Lua 5.4 下实测：
• 尾调用：10 万层递归正常返回，因为栈帧被复用
• 非尾调用：20 万层仍能过，但 500 万层就 stack overflow

实战意义：
• 状态机的状态跳转、递归下降的解析器、协程调度——设计成尾调用可以支持任意深度；
• 常见错误是把 return f(x) * 2 这种写法用在深递归上，几百层就崩。
