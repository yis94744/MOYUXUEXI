最容易答错的三道 ① "0 是真值还是假值？"
只有 nil 和 false 是假值。0 和空字符串都是真值。
这和 C/C#/Python 都不同，是从其他语言转过来最容易踩的坑。

② "#t 可靠吗？"
对连续数组可靠；对含 nil 的表是"未定义行为"。
可能返回 2，也可能返回 4——取决于内部数组边界的实现。
可靠做法：用 select("#", ...) 数参数，或自己维护计数。

③ "多返回值什么时候会被截断？"
有三个位置会保留全部返回值，其余一律截断成一个。
· 函数调用的实参列表：f(multiReturn())
· return 语句：return multiReturn()
· 表构造器的最后一个元素：{multiReturn()} → 收全 3 个；{multiReturn(), 9} → 只收第 1 个

实测（Lua 5.4.7）：#{f()} = 3、#{f(), 9} = 2、local a = f() → 只有 1 个、 (f()) → 加括号强制截断成 1 个
注意 print(f()) 也是"实参列表"，所以 3 个都会打出来——不要把它和"赋值截断"混为一谈。

三个"反常识"的答案，答对了很加分（其中两个我实测改了口径） ① "缓存全局函数有用吗？"
有用，而且不算小——但要先搞清楚为什么。

常见说法是「Lua 5.4 用数组存全局变量，访问是 O(1) 索引，所以缓存没收益」。 这个说法是错的：Lua 5.4 的全局变量存在 _ENV 这张普通哈希表里， 访问全局编译成 OP_GETTABUP + luaH_getshortstr，就是一次哈希查找 （见 lvm.c 的 OP_GETTABUP 分支）。

本页实测（Lua 5.4.7，300 万次纯读取，取 7 次最小值）：
· 只取值不调用：单层全局 / 局部 ≈ 1.0~1.3 倍；两层链（math.floor）/ 局部 ≈ 2.0~2.9 倍
· 连调用一起测（math.floor(i) vs local floor = math.floor，400 万次）≈ 1.2 倍 ——因为函数体本身的耗时把差距摊薄了

注意这两组数字不矛盾：查找成本才是被优化的那部分， 它占总耗时的比例越大，缓存收益越明显；被调函数越重，相对收益越小。

所以"缓存全局函数无收益"这个结论站不住——真正的结论是： 单层全局访问的差距不大（几十个百分点），但两层链（math.xxx、table.xxx）差距明显。
这也是为什么热循环里仍应把 math.floor、table.insert 提到局部变量——成本几乎为零，收益是实打实的。

② "ipairs 比数字 for 快吗？"
反而更慢——因为每次迭代都要调用一次迭代器函数（数字 for 是 VM 原生指令，没有函数调用）。
实测（Lua 5.4.7，本机 1000 元素数组、20 万轮内层遍历）约慢 2.5 倍； 这个比值随数据规模和机器波动，当"约 2 倍量级"记即可，不要背具体数字。
热路径应该用数字 for——for i = 1, #t 的上限只求值一次（见页 08），不需要再手工缓存长度；只有 while i <= #t 那种写法缓存才有收益。

③ "客户端加密能防住作弊吗？"
不能。加密的价值是提高攻击成本，真正的安全靠服务器权威。
敢直接说"不能"的人，通常比说"能防住"的人更懂安全。
