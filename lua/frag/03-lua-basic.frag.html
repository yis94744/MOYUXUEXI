03 · 基础语法与类型

Lua 的语法非常小——八种类型、几个关键字、一套控制流。它的学习曲线是"一周上手，一年精通"：语法简单，但隐藏在语法背后的行为差异很多。这一页把那些"反直觉但必须知道"的点全部列出来。

这一页在路线中的位置 上一页（02）你已经装好环境、跑通了第一段脚本。这一页开始正式学语言。
关键提醒：这一页有三个反直觉的点，它们会决定你后面代码的正确性——索引从 1 开始、0 是真值、不加 local 就是全局变量。
下一页（04）讲 table 与元表，那是 Lua 真正的地基。这一页先打好语法基础。
验证方式：本页所有代码都在 Lua 5.4.7 解释器里实际运行过，你看到的结果就是真实输出。

一、八种类型 ★

Lua 只有八种类型，比其他语言少得多，这是它轻量的原因之一。注意：类型不是"变量的属性"，而是"值本身的属性"——同一个变量可以先存数字再存字符串。

缺少代码样本03/types
反直觉之一：只有 nil 和 false 是假值 这是 Lua 与 C / C++ / C# / JavaScript 都不同的地方：
0 是真值、空字符串 "" 是真值、空表 {} 也是真值。

后果：从 C# 转过来的人最容易写出这种 bug：
if (count) then ... end —— 当 count 是 0 时，依然会进入分支。

正确写法：if count > 0 then ... end，或者 if count ~= nil and count ~= false then。
Lua 5.3+ 的整数与浮点 Lua 5.3 之前只有一种 number（都是双精度浮点）。5.3 起引入了整数子类型：
• math.type(3) 返回 "integer"，math.type(3.0) 返回 "float"
• 但 3 == 3.0 仍然是 true（比较时按数学值）
• 7 // 2 是整数除法（得 3），7 / 2 是浮点除法（得 3.5）
• 整数会溢出回绕：math.maxinteger + 1 == math.mininteger 为 true

实战影响：做时间累加、ID 计算时，整数和浮点的精度差异会导致难以复现的 bug。需要精确整数运算时，用 // 而不是 /。

二、变量作用域与性能 ★★

这一节看起来是"语法基础"，但实际上是Lua 性能优化的第一课——因为访问局部变量和访问全局变量的性能差距，在热循环里非常明显。

缺少代码样本03/scope
反直觉之二：不加 local 就是全局变量 Lua 默认创建全局变量。这意味着：
count = 0 —— 这行代码创建的是一个全局变量，会进 _G 表。

两个后果：
① 性能差：全局变量访问是表查找（相当于哈希查找），局部变量是寄存器访问。
② 污染环境：不同模块的变量名会互相覆盖，产生"A 模块改了全局变量导致 B 模块行为异常"这类难查的 bug。

规则：除了确实需要全局共享的东西，所有变量都加 local。这是 Lua 代码规范的第一条。
把常用全局函数缓存成局部变量 这个技巧在 LuaJIT 下收益更大，但在标准 Lua 下也值得做：
local print = print
local table_insert = table.insert
local math_floor = math.floor

为什么快：调用全局 table.insert 需要两次表查找（先找 _G.table，再找 .insert）；
而局部变量只需一次寄存器读取。

注意：这招在模块顶部做一次即可，不要在每个函数里都写一遍——那反而让代码难读。

三、控制流与运算符

类别语法注意点
条件if ... then ... end没有 do，直接 then
if ... then ... elseif ... then ... else ... end是 elseif，不是 else if
a and b or c三元运算符的替代写法，b 为 false 时会出错
循环for i = 1, 10 do ... end含首尾，步长可选（for i = 10, 1, -1）
for k, v in pairs(t) do ... end遍历所有键，顺序不确定
while cond do ... end / repeat ... until condrepeat 至少执行一次
运算符+ - * / % ^^ 是幂运算，不是异或
//整数除法（5.3+），向下取整
..字符串拼接，两边必须是字符串或数字
#取长度，对含 nil 的表结果不确定
逻辑and or not返回的是操作数本身，不是 true/false
and / or 返回操作数，不是布尔值 这是 Lua 的一个很有用但容易误用的特性：
print(1 and 2) 输出 2（不是 true）
print(nil and 2) 输出 nil
print(nil or 3) 输出 3
print(false or "默认值") 输出 "默认值"

用途：这正是 Lua 没有三元运算符却能写默认值的原因：
local name = input or "无名" —— 用得最多的一行代码。

陷阱：如果 input 的值是 false，这行会错误地取到默认值。
所以当变量可能是 false 时，必须写 if input == nil then 来区分。
