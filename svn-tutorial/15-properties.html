15属性系统：SVN 的隐藏超能力

属性（Property）是 SVN 最被低估的功能。它们是附着在文件或目录上的键值对， 和文件内容一起被版本控制——但普通用户几乎从来不看它们。 掌握属性，你才能解锁忽略规则、关键字替换、外部引用、只读锁这些能力。

◈图 15-1　属性：附着在版本控制对象上的元数据Properties
为什么要关心属性：它们让 SVN 能适配各种工程需求—— 让编译产物不污染状态输出、让源码里自动带上版本号、让美术源文件必须加锁才能改。 属性改动也要提交，这是很多人第一次遇到「明明没改文件，status 却显示 M」的原因。

属性的增删改查（实测）

bash属性的四个基本操作
# ---- 查 ----
svn proplist README.md              # 列出属性名
svn proplist -v README.md           # 连值一起显示（-v = verbose）
svn propget svn:ignore .            # 读单个属性的值
svn proplist -v -R .                # 递归列出整个工作副本的属性

# ---- 增/改 ----
svn propset owner "team-alpha" README.md      # 自定义属性
svn propset svn:ignore "*.log" .               # 设置忽略规则（注意最后是目录）

# 从文件读入属性值（多行属性必须这样写）
svn propset svn:ignore --file ignore-list.txt .

# ---- 删 ----
svn propdel owner README.md
svn propdel svn:ignore . -R                    # 递归删除

# ---- 批量编辑（最方便的方式）----
svn propedit svn:ignore .                      # 会打开编辑器，一行一个模式
svn propedit svn:ignore . --editor-cmd "code --wait"   # 指定编辑器

# ---- 提交属性改动 ----
svn commit -m "添加 owner 属性与 svn:ignore 忽略规则"

$ svn propget owner README.md

$ svn proplist -v README.md

       ↑ 第一列的空格说明：文件【内容】没变，只有属性变了

Sending        README.md
Committing transaction...
Committed revision 9.
属性冲突也会显示 C，且更隐蔽

如果两个人同时改了同一个文件的属性，update 时会产生属性冲突： 第 2 列显示 C，同时生成 .prej 文件（prej = property reject）。

处理方式：svn resolve --accept working 文件名， 然后查看 .prej 文件里记录的被拒绝的属性值，手工 propset 回去。

svn:ignore　忽略规则

这是使用频率最高的属性。目的是让 svn status 输出保持干净—— 你不想每次都用眼睛过滤掉 bin/、obj/、*.log、.vs/ 这些东西。

实测踩坑：目录名后面加斜杠会失效

这是 svn:ignore 最经典的坑。很多人凭直觉写成 build/（带斜杠表示目录）， 结果完全不生效——svn status 照样显示 ? build。

原因：svn:ignore 的模式是文件名 glob，不是路径。它拿目录名 build 去匹配模式 build/（含斜杠），自然匹配不上。

实测对比：带斜杠 vs 不带斜杠
PowerShell
# ✗ 错误写法：目录名带结尾斜杠
$ svn propset svn:ignore "*.log`nbuild/`ntemp/" .
property 'svn:ignore' set on '.'

$ svn status
 M      .
 M      README.md
?       build                  ← build 目录还是显示出来了！忽略没生效

# ✓ 正确写法：去掉结尾斜杠
$ svn propset svn:ignore "*.log`nbuild`ntemp" .

$ svn status
 M      .                        ← build 和 debug.log 都消失了
 M      README.md

# 确认被忽略的内容（排查问题时用）
$ svn status --no-ignore
 M      .
 M      README.md
I       build                    ← I = Ignored，被规则命中
I       debug.log

忽略规则的三种层级

◈图 15-2　三种忽略方式的作用范围Ignore Layers
bash实用的 ignore 配置模板
# ===== 通用项目（C# / .NET / Visual Studio）=====
cat > /tmp/ignore.txt <<'EOF'
*.log
*.tmp
*.user
*.suo
*.cache
.vs
bin
obj
packages
TestResults
EOF
svn propset svn:ignore --file /tmp/ignore.txt .

# ===== Java / Maven =====
printf '%s\n' target .idea '*.iml' '*.class' > /tmp/jignore.txt
svn propset svn:ignore --file /tmp/jignore.txt .

# ===== Node.js =====
printf '%s\n' node_modules dist build .cache '*.log' .env > /tmp/nignore.txt
svn propset svn:ignore --file /tmp/nignore.txt .

# ===== Python =====
cat > /tmp/pyignore.txt <<'EOF'
__pycache__
*.pyc
*.pyo
.pytest_cache
.mypy_cache
venv
.venv
*.egg-info
EOF
svn propset svn:ignore --file /tmp/pyignore.txt .

# ===== 游戏项目（美术资源库，加上全仓规则）=====
svn propset svn:global-ignores --file /tmp/ignore.txt .

# 别忘了提交属性改动！
svn commit -m "配置 svn:ignore 忽略规则"

# ===== 验证 =====
svn status                       # 应该干净了
svn status --no-ignore           # 看看哪些被忽略了（确认没忽略错东西）
svn propget svn:ignore .         # 确认规则内容
万一某个文件已经被 svn add 了，ignore 就不起作用

svn:ignore 只能影响未版本控制的文件。 如果一个文件已经 svn add 过（甚至连同父目录被添加了）， 设置 ignore 后它依然会被跟踪。

解决方案：

  • 单独移除：svn delete --keep-local 文件名，然后提交
  • 整个目录移除：svn delete --keep-local bin，文件保留在磁盘上，但不再被跟踪
  • 然后设置 ignore 规则，两者配合才彻底干净

关键字替换与 MIME 类型

bashsvn:keywords　让源码自动带上版本号
# 在文件里放占位符（注意是 $ 包裹的关键字）
cat > version.txt <<'EOF'
$Id$
$Revision$
$Author$
$Date$
$HeadURL$
EOF

# 启用关键字替换（不设置的话，占位符永远不会变）
svn add version.txt
svn propset svn:keywords "Id Revision Author Date HeadURL" version.txt

# 提交后，占位符会在【提交那一刻】被替换成真实值
svn commit -m "添加 version.txt 并启用关键字替换"

# 结果（不需要 update 就已经展开）
cat version.txt
实测输出：提交前 vs 提交后（注意展开时机）
PowerShell
# 提交前：占位符原样保留
$ Get-Content version.txt
$Id$
$Revision$
$Author$
$Date$

$ svn propset svn:keywords "Id Revision Author Date" version.txt
property 'svn:keywords' set on 'version.txt'

$ svn commit -m "添加 version.txt 并启用关键字替换"
Transmitting file data .done
Committing transaction...
Committed revision 18.

# ★ 关键：提交完成后【立刻】查看，占位符已经展开，无需 update
$ Get-Content version.txt
$Id: version.txt 18 2026-10-08 03:09:06Z kelang $
$Revision: 18 $
$Author: kelang $
$Date: 2026-10-08 11:09:06 +0800 (周四, 08 10月 2026) $
↑ 全部被替换成真实版本信息了

# 提交时 SVN 先在本地展开关键字，再把结果送进仓库
# 所以展开发生在 commit 阶段，而不是后续的 update
关键字替换成什么典型用途
$Revision$版本号，如 18脚本里读版本号
$Author$最后修改者用户名文件头注释
$Date$最后修改时间（含时区）文件头注释
$Id$「文件名+版本号+时间+作者」组合串最常用，一行包含全部信息
$Header$含仓库 URL 的完整头部信息需要溯源的场景
$HeadURL$文件在仓库中的完整 URL判断文件来自哪个分支
关键字替换的四个陷阱（实测确认）
  1. 不设置 svn:keywords 属性，占位符永远不会变—— 很多人以为 $Id$ 是自动的，其实必须显式启用。而且属性本身也要提交，否则对别人无效。
  2. 展开发生在 commit 那一刻，不是 update 时—— 实测结果：文件里写着 version=$Revision$， 执行 svn commit 后立刻就变成了 version=$Revision: 12 $， 不需要再 svn update。 原因：提交时 SVN 会先在本地做关键字替换，再把替换后的内容送进仓库。
  3. 所以提交后文件会「看起来被改过」—— svn status 可能显示 M，但那只是因为替换结果与 BASE 不同。 再次 svn update 后状态就会消失，属正常现象。
  4. 属性必须与文件一起提交—— 如果只提交了文件而忘了 svn:keywords 属性，别人拿到这份文件时不会有任何替换。
bashsvn:mime-type 与 svn:eol-style
# ===== svn:mime-type：告诉 SVN 二进制还是文本 =====
# 为什么重要：SVN 对「文本」文件会尝试自动合并，对「二进制」直接报冲突
# 如果二进制文件被当成文本，自动合并会把它改坏！

svn propset svn:mime-type application/octet-stream logo.png
svn propset svn:mime-type image/png logo.png
svn propset svn:mime-type application/pdf manual.pdf
svn propset svn:mime-type application/zip archive.zip

# 批量给所有图片设置（Linux/macOS）
find . -name "*.png" -o -name "*.jpg" | xargs svn propset svn:mime-type image/png

# 启用自动探测（1.5+，在 ~/.subversion/config 里）
# enable-auto-props = yes
# [auto-props]
# *.png = svn:mime-type=image/png
# *.jpg = svn:mime-type=image/jpeg
# *.pdf = svn:mime-type=application/pdf

# ===== svn:eol-style：统一换行符（跨平台协作关键）=====
# Windows 用 CRLF，Linux/macOS 用 LF，不统一会导致整个文件看起来全改了
svn propset svn:eol-style native   *.cs       # 各平台自动用本地风格（推荐）
svn propset svn:eol-style LF       *.sh       # 强制 LF（shell 脚本必须）
svn propset svn:eol-style CRLF     *.bat      # 强制 CRLF

# 批量给源码目录设置（推荐配置）
find src -name "*.cs" | xargs svn propset svn:eol-style native
find src -name "*.js" | xargs svn propset svn:eol-style native
svn commit -m "统一源码换行符为 eol-style=native"

# ===== svn:executable：可执行权限（Linux/macOS）=====
svn propset svn:executable on build.sh
svn propdel svn:executable build.sh      # 取消
强烈建议：在 ~/.subversion/config 里配置 auto-props

手工给每个文件设属性太累了。配置 auto-props 后， svn add 会自动按扩展名给新文件设好属性。 这是 SVN 提高效率最值得做的一次配置：

ini~/.subversion/config（Windows: %APPDATA%\Subversion\config）
[miscellany]
# 打开自动属性
enable-auto-props = yes

# 全局忽略（个人习惯，不进仓库）
global-ignores = *.o *.lo *.la *.al .libs *.so *.so.[0-9]* *.a *.pyc *.pyo
  __pycache__ *.rej *~ #*# .#* .*.swp .DS_Store [Tt]humbs.db
  *.vs bin obj *.user *.suo

[auto-props]
# ---- 文本源码：统一换行符 ----
*.c     = svn:eol-style=native;svn:keywords=Id Revision Author Date
*.h     = svn:eol-style=native;svn:keywords=Id Revision Author Date
*.cpp   = svn:eol-style=native;svn:keywords=Id
*.cs    = svn:eol-style=native;svn:keywords=Id
*.java  = svn:eol-style=native;svn:keywords=Id
*.py    = svn:eol-style=native;svn:keywords=Id
*.js    = svn:eol-style=native;svn:keywords=Id
*.ts    = svn:eol-style=native;svn:keywords=Id
*.sh    = svn:eol-style=LF;svn:executable;svn:keywords=Id
*.bat   = svn:eol-style=CRLF
*.cmd   = svn:eol-style=CRLF
*.xml   = svn:eol-style=native
*.json  = svn:eol-style=native
*.md    = svn:eol-style=native

# ---- 二进制资源：标记 MIME，避免误合并 ----
*.png   = svn:mime-type=image/png
*.jpg   = svn:mime-type=image/jpeg
*.jpeg  = svn:mime-type=image/jpeg
*.gif   = svn:mime-type=image/gif
*.ico   = svn:mime-type=image/x-icon
*.pdf   = svn:mime-type=application/pdf
*.zip   = svn:mime-type=application/zip
*.7z    = svn:mime-type=application/x-7z-compressed
*.psd   = svn:mime-type=image/vnd.adobe.photoshop;svn:needs-lock=*

svn:externals　外部引用

svn:externals 让一个目录自动包含另一个仓库路径的内容。 典型场景：多个项目共享一个公共库，或者美术资源和程序代码分仓库管理，但要放在一起用。

◈图 15-3　svn:externals 的工作原理与两种引用方式Externals
bashexternals 完整用法
# ---- 设置外部引用（注意：属性值是多行文本，用 propedit 最方便）----
cd wc
svn propedit svn:externals src
# 编辑器里逐行写，格式：URL 本地目录名

# 或者用单行 propset（多个引用用换行分隔）
svn propset svn:externals "^/trunk/webapp webapp-link" src

# 读取确认
svn propget svn:externals src

# ---- 提交（属性改动必须提交，否则对别人无效）----
svn commit -m "为 src 添加 svn:externals 外部引用"

# ---- 更新时自动拉取外部内容 ----
svn update

# ---- 控制 externals 行为 ----
svn update --ignore-externals        # 跳过外部引用（CI 里常用）
svn checkout --ignore-externals URL  # 检出时也不拉外部
svn export --ignore-externals URL    # 导出时不带外部

# ---- 在外部目录里提交（它有自己的 .svn）----
cd src/webapp-link
svn status                # 这里看到的是 webapp 仓库的状态
svn commit -m "修改 webapp 内容"

# ---- 用 ^ 和 // 的语法（1.5+ 推荐）----
# ^/path        相对仓库根
# //host/path   相对服务器根（多仓库时用）
# ../path       相对父目录（易错，不推荐）
svn propset svn:externals "^/trunk/shared/common common" src

# ---- 删除某个外部引用 ----
svn propedit svn:externals src     # 删掉对应行
svn commit -m "移除过期的外部引用"
