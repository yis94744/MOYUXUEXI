07 · 堆与优先队列 ★★

堆的应用场景比你想的多：A* 寻路的开放列表、技能冷却队列、Top-K 排名、事件调度。它的价值在于"插入"和"取最值"都是 O(log n)——两者都平衡。

这一页在路线中的位置 上一页（06）讲的树用指针连接。这一页的堆是树的特殊形式——完全二叉树，但用数组存储。 关键衔接：页 11 的 A* 寻路依赖堆做开放列表；页 25 的定时器用堆做调度。 下一页（08）Trie 与 AC 自动机。另一种特殊的树。 验证方式：本页实现了完整的最小堆/最大堆，并实测出 Top-K 比完整排序快 8.4 倍。

二、堆用数组存储（缓存友好）

堆的索引计算 完全二叉树可以用数组存储，不需要指针： parent(i) = i / 2 left(i) = i * 2 right(i) = i * 2 + 1 为什么这样没问题：完全二叉树没有空洞，按层序编号正好填满数组。 带来的好处： · 缓存友好——父节点与子节点在内存上很近 · 零指针开销——不像链表树每个节点要存两个指针 · 遍历快——顺序访问数组 这就是为什么堆是"实现优先队列的最佳结构"。
自定义比较函数让代码复用 最小堆与最大堆的实现完全相同——只差一个比较函数。 本页的实现用 compare(a, b) 参数化： · 最小堆：function(a,b) return a < b end · 最大堆：function(a,b) return a > b end · 按对象字段排序：function(a,b) return a.readyAt < b.readyAt end 这是本页代码能同时演示"技能冷却队列"和"事件调度器"的原因—— 同一个堆实现，换一个比较函数就是完全不同的用途。

三、Top-K：堆最实用的场景 ★★★

实测数据：堆比完整排序快 8.4 倍 场景：从 100000 个伤害数字里找最高的 10 个。
方法复杂度实测耗时
完整排序O(n log n)0.0760 秒
堆的 Top-KO(n log K)0.0090 秒
快 8.4 倍，而且结果完全一致。 做法： ① 维护一个大小为 K 的最小堆 ② 遍历数据，如果大于堆顶，就替换堆顶并下沉 ③ 最终堆里的就是最大的 K 个 为什么用最小堆而不是最大堆：因为我们要快速淘汰最小的——堆顶就是"当前 K 个里最小的"。 游戏应用：伤害排名、排行榜、最近的敌人、最贵的物品。
