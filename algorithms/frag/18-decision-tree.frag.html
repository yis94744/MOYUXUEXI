18 · 决策树与效用 AI ★

行为树解决的是"怎么执行"，决策树解决的是"做什么"。这两者经常被混淆，但它们是互补的——而效用系统（Utility AI）又是决策树的平滑版本。

这一页在路线中的位置 上一页（17）行为树讲"行为怎么组织与执行"。这一页讲"在多个行为之间怎么选"。
关键衔接：决策树本质是树结构（06）的应用；效用系统大量使用数学曲线（参见 C# 站的页 09 插值）。
下一页（19）GOAP——它比决策树更灵活，能自动组合出未预设的行为序列。
验证方式：本页代码在 Lua 5.4.7 实测运行，输出结果是真实的。

一、从硬编码到数据化

缺少代码样本18/decision-tree
数据化的最大价值：策划能改 硬编码的 if-else 只有一个问题，但它是致命的——策划改不了。

每一次"把血量阈值从 30 改成 35"，都要走需求 → 开发 → 提测 → 发版的完整流程。
而数据化之后，策划在 Excel 里改个数字、重新导出配置就完成了。

数据结构设计：
{ type = "condition", key = "hp", op = "<", value = 30, trueNode = {...}, falseNode = {...} }
这样一份 JSON 就能描述整棵决策树。

二、效用系统：用评分代替硬判断 ★★

决策树的根本问题：硬边界 看本页的实测对比（4 个敌人、无药水，血量从 100 降到 0）：
血量决策树效用系统
100 ~ 40使用群攻技能使用群攻技能
30使用群攻技能（突变点）逃跑（平滑过渡）
20 及以下逃跑逃跑
决策树在血量 30 处突然改变行为——31 打、29 跑。
而效用系统的分数是连续变化的，行为切换发生在"两个分数交叉"的时刻，看起来更自然。
五种常用效用曲线
曲线形状用途
linear均匀上升通用的"越多越好"
inverseLinear均匀下降"越低越想要"（逃跑、喝药）
quadratic低值区更敏感强调极端情况
smoothstep两端平缓、中间陡最自然的手感
threshold超过阈值立即满分"至少要有 3 个敌人"
组合方式：多个维度加权求和。例如"逃跑"的分数 = 血量权重 x 血量因子 + 敌人数权重 x 敌人因子。

三、模糊逻辑：处理"有点危险"

传统逻辑 vs 模糊逻辑 传统逻辑：hp < 30 是"危险"，否则是"安全"——非黑即白。
模糊逻辑：血量 40 时，危险度 0.4、安全度 0.6——同时是两者。

实测数据（用 smoothstep 模拟隶属度）：
• hp = 25 → 危险度 1.00，安全度 0.00
• hp = 40 → 危险度 0.40，安全度 0.60
• hp = 60 → 危险度 0.00，安全度 1.00

用途：需要"渐变式"行为过渡的 AI——潜行游戏里敌人的警觉度、恐怖游戏的紧张感、赛车 AI 的激进程度。

四、三者对比与选型

方案决策方式优点缺点适用
决策树条件判断（硬边界）清晰、可配置、易调试边界突变、规则多时树很深技能选择、UI 状态、明确规则
效用系统评分取最高平滑、可量化、易扩展参数难调、难调试NPC 日常、策略 AI
模糊逻辑隶属度 + 规则最自然、能表达模糊概念最复杂、最难调需要细腻情绪表现的 AI
实战中的组合方式 最常见的做法是混合使用：
• 决策树判断"要不要做"——比如"现在该不该进入战斗状态"
• 效用系统决定"做哪个"——进入战斗后，用评分选具体技能
• 行为树执行"怎么做"——选中的技能用行为树的子节点来执行

三层各司其职，比用单一方案硬套要清晰得多。
