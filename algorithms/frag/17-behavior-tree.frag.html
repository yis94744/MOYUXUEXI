17 · 行为树 Behavior Tree ★★★

行为树是目前游戏 AI 的事实标准。它比状态机好扩展、比 GOAP 好调试、策划能看懂。几乎所有商业游戏里的敌人 AI、NPC 行为、Boss 战斗，底层都是行为树。

这一页在路线中的位置 上一页（16）状态机是 AI 的基础。行为树是状态机的进化版——解决了状态机"状态多了连线爆炸"的问题。
关键衔接：行为树用到树结构（06）的遍历思想、黑板类似弱引用表的概念。
这一页和下一页的关系：18 讲决策树（一次性决策），19 讲 GOAP（规划型 AI）。三者是互补的，不是替代关系。
验证方式：本页实现了一个完整可运行的行为树，包含组合节点、装饰器、黑板，并真实模拟了一段 Boss 战斗。

一、四种节点状态（基础中的基础）

为什么有 RUNNING SUCCESS（成功）和 FAILURE（失败）好理解，但 RUNNING 是行为树的精髓所在。

它表示"我这个节点还没做完，下一帧继续"。
这让 AI 能"记住"自己做到哪一步——比如"走到目标点"这个动作需要 20 帧，用 RUNNING 就能跨帧保持状态。

没有 RUNNING 会怎样：每帧都要从头判断"我现在该做什么"，无法表达"我正在做但还没做完"。

print("=== 4. 组合节点：序列（Sequence）===")
-- 依次执行子节点，全部成功才成功，任一失败立即失败
-- 类比：AND 逻辑 / 做任务清单
local Sequence = setmetatable({}, { __index = Node })
Sequence.__index = Sequence

function Sequence.new(name)
  local self = Node.new(name or "Sequence")
  setmetatable(self, Sequence)
  self.currentIndex = 1              -- 【关键】记录执行进度，支持 RUNNING
  return self
end

function Sequence:entry()
  self.currentIndex = 1
end

function Sequence:tick(blackboard)
  while self.currentIndex <= #self.children do
    local child = self.children[self.currentIndex]

    -- 第一次进入子节点时调用 entry
    if child._running ~= true then
      if child.entry then child:entry(blackboard) end
    end

    local status = child:tick(blackboard)
    child._lastStatus = status

    if status == Status.RUNNING then
      child._running = true
      return Status.RUNNING          -- 记住位置，下帧从这里继续
    end

    child._running = false

    if status == Status.FAILURE then
      return Status.FAILURE          -- 短路：一个失败就整体失败
    end

    self.currentIndex = self.currentIndex + 1
  end

  return Status.SUCCESS
end

print("  序列节点：全部成功才成功，遇失败短路")
print("  支持 RUNNING：记住执行到第几个子节点")

-- 依次尝试子节点，任一成功就成功，全部失败才失败
-- 类比：OR 逻辑 / 备选方案
local Selector = setmetatable({}, { __index = Node })
Selector.__index = Selector

function Selector.new(name)
  local self = Node.new(name or "Selector")
  setmetatable(self, Selector)
  self.currentIndex = 1
  return self
end

function Selector:entry()
  self.currentIndex = 1
end

function Selector:tick(blackboard)
  while self.currentIndex <= #self.children do
    local child = self.children[self.currentIndex]

    if child._running ~= true then
      if child.entry then child:entry(blackboard) end
    end

    local status = child:tick(blackboard)
    child._lastStatus = status

    if status == Status.RUNNING then
      child._running = true
      return Status.RUNNING
    end

    child._running = false

    if status == Status.SUCCESS then
      return Status.SUCCESS          -- 短路：一个成功就整体成功
    end

    self.currentIndex = self.currentIndex + 1
  end

  return Status.FAILURE
end

print("=== 6. 并行节点（Parallel）===")
-- 同时 tick 所有子节点，按策略决定结果
local Parallel = setmetatable({}, { __index = Node })
Parallel.__index = Parallel

function Parallel.new(name, successPolicy, failurePolicy)
  local self = Node.new(name or "Parallel")
  setmetatable(self, Parallel)
  self.successPolicy = successPolicy or "all"    -- all / one
  self.failurePolicy = failurePolicy or "one"    -- all / one
  return self
end

function Parallel:tick(blackboard)
  local successCount, failureCount = 0, 0

  for _, child in ipairs(self.children) do
    local status = child:tick(blackboard)

    if status == Status.SUCCESS then
      successCount = successCount + 1
    elseif status == Status.FAILURE then
      failureCount = failureCount + 1
    end
  end

  -- 失败判定优先
  if self.failurePolicy == "one" and failureCount > 0 then
    return Status.FAILURE
  elseif self.failurePolicy == "all" and failureCount == #self.children then
    return Status.FAILURE
  end

  -- 成功判定
  if self.successPolicy == "all" and successCount == #self.children then
    return Status.SUCCESS
  elseif self.successPolicy == "one" and successCount > 0 then
    return Status.SUCCESS
  end

  return Status.RUNNING
end

print("  并行节点：同时执行所有子节点")
print("  策略：successPolicy(all/one) + failurePolicy(all/one)")

print("=== 7. 装饰器（Decorator）===")
-- 只有一个子节点，修改其行为

-- 7.1 反转：SUCCESS <-> FAILURE
local Inverter = setmetatable({}, { __index = Node })
Inverter.__index = Inverter

function Inverter.new(name)
  local self = Node.new(name or "Inverter")
  setmetatable(self, Inverter)
  return self
end

function Inverter:tick(blackboard)
  local status = self.children[1]:tick(blackboard)
  if status == Status.SUCCESS then return Status.FAILURE end
  if status == Status.FAILURE then return Status.SUCCESS end
  return status
end

-- 7.2 重复：执行 N 次或无限
local Repeater = setmetatable({}, { __index = Node })
Repeater.__index = Repeater

function Repeater.new(name, times)
  local self = Node.new(name or "Repeater")
  setmetatable(self, Repeater)
  self.times = times or -1           -- -1 表示无限
  self.count = 0
  return self
end

function Repeater:entry()
  self.count = 0
end

function Repeater:tick(blackboard)
  if self.times > 0 and self.count >= self.times then
    return Status.SUCCESS
  end

  local status = self.children[1]:tick(blackboard)

  if status == Status.SUCCESS then
    self.count = self.count + 1
    if self.times > 0 and self.count >= self.times then
      return Status.SUCCESS
    end
    -- 重置子节点，准备下一轮
    if self.children[1].entry then self.children[1]:entry(blackboard) end
  elseif status == Status.FAILURE then
    return Status.FAILURE
  end

  return Status.RUNNING
end

-- 7.3 冷却：一段时间内不执行
local Cooldown = setmetatable({}, { __index = Node })
Cooldown.__index = Cooldown

function Cooldown.new(name, duration)
  local self = Node.new(name or "Cooldown")
  setmetatable(self, Cooldown)
  self.duration = duration or 1.0
  self.lastRunTime = -999
  return self
end

function Cooldown:tick(blackboard)
  local now = blackboard:get("time", 0)
  if now - self.lastRunTime < self.duration then
    return Status.FAILURE             -- 冷却中
  end

  local status = self.children[1]:tick(blackboard)

  if status ~= Status.RUNNING then
    self.lastRunTime = now            -- 记录执行时间
  end

  return status
end

二、组合节点：序列与选择

节点逻辑类比短路规则
Sequence 序列依次执行，全部成功才成功AND / 任务清单任一失败立即返回失败
Selector 选择依次尝试，任一成功就成功OR / 备选方案任一成功立即返回成功
Parallel 并行同时执行所有子节点多线程按策略配置决定
Random 随机随机选一个执行抽签—
短路（Short-circuit）是性能关键 Sequence 遇到 FAILURE 立即返回，不再执行后面的子节点。
Selector 遇到 SUCCESS 立即返回，不再尝试后面的备选。

这个特性直接影响性能：把最容易失败的条件判断放在 Sequence 前面，把最高优先级的行为放在 Selector 前面——
这样每帧实际执行的节点数会大幅减少。

这是行为树性能优化的第一手段，比任何代码优化都有效。

三、装饰器：修改子节点行为

装饰器作用实战用途
Inverter 反转SUCCESS ↔ FAILURE"不在范围内"这类反向条件
Repeater 重复执行 N 次或无限巡逻循环、持续攻击
Cooldown 冷却一段时间内不执行技能释放节奏、Boss 大招
Succeeder无论子节点结果都返回成功"尝试一下，失败也无所谓"
UntilFail 直到失败重复直到子节点失败持续执行到条件不满足
TimeLimit 限时超过时间就返回失败技能前摇超时、卡住检测
冷却装饰器是最实用的一个 没有它：Boss 每帧都会尝试放大招，需要自己写"技能是否就绪"的判断，而且要处理状态重置。
有了它：包一层 Cooldown(3.0)，Boss 每 3 秒才能放一次。逻辑清晰，不用改其他地方。

注意：冷却装饰器需要访问"当前时间"。这通常通过黑板传递，而不是直接读全局时间——这样便于做时间缩放、暂停、回放。

四、黑板（Blackboard）：AI 的共享内存

为什么需要黑板 行为树的节点是独立的对象，它们需要共享数据：
• "玩家在哪" —— 感知节点写入，追击节点读取
• "当前血量" —— 状态同步写入，逃跑判断读取
• "上次攻击时间" —— 冷却装饰器读写

如果没有黑板：要么层层传参（每层都要转发），要么每个节点各自持有引用（耦合严重）。
有了黑板：所有节点通过 get/set 访问同一份数据，节点之间完全解耦。
黑板的设计要点 ① 类型安全：C# 实现时用泛型 Get<T>(key)，避免装箱（参见 C# 站的页 03）。
② 键用哈希而非字符串：和 Animator 参数一样，字符串键每次查找都要算哈希。
③ 支持默认值：get(key, default) 避免到处判空。
④ 考虑"黑板作用域"：单个 AI 一份黑板（私有），还是全队共享一份（便于协同）？实战中两者都有。
⑤ 变化通知：某些数据变化时需要唤醒 AI（比如"发现玩家"），可以给黑板加事件机制。

五、性能优化：六个关键手段

行为树的性能问题通常不在算法，而在使用方式 行为树本身的 tick 逻辑很简单（一次树遍历），真正的性能问题来自：

① 每帧重建树 ✗
在 Update 里 new 节点对象 → GC 灾难。
正确做法：初始化时构建一次，运行时只 tick。

② 所有 AI 每帧都 tick ✗
100 个 NPC 每个每帧 tick 一次，即使它们在做同样的事。
正确做法：分级更新（见下）。

③ 节点里做重活 ✗
在条件节点里做射线检测、路径计算。
正确做法：结果缓存到黑板，多个节点复用。

④ 树太深 ✗
深度 10 的树，最坏情况每帧要走 10 层。
正确做法：扁平化设计，用条件前置减少遍历。

⑤ 条件节点顺序不对 ✗
把"距离判断"放在"是否死亡"前面，导致每帧都算距离。
正确做法：最廉价、最容易失败的判断放最前。

⑥ 没有 RUNNING 复用 ✗
长动作每帧重头开始，而不是用 RUNNING 保持进度。
分级更新（LOD）是收益最大的优化 做法：按 AI 与玩家的距离，用不同的 tick 频率。
距离更新频率效果
屏幕内 / 近处每帧表现完全正常
中距离每 3~5 帧玩家察觉不到
远处每 10~20 帧只见大致行为
不可见每秒 1 次 / 停止省下绝大部分开销
注意：降频会带来"行为不精确"——比如远处的敌人可能晚 0.5 秒才反应。
所以战斗中的敌人不应该降频，只对"背景 NPC"用这个策略。
性能经验值 单个 NPC 的行为树 tick，每帧开销通常在 1~10 微秒。
100 个 NPC 每帧约 0.1~1 毫秒。

超过这个量级就说明有问题——通常是条件节点里做了重活，或者树的深度过大。
用 Unity Profiler 的 Deep Profile 可以看到具体是哪个节点最耗时。

六、行为树 vs 状态机 vs GOAP

方案优点缺点适用
状态机简单、快、直观状态多了连线爆炸角色状态、UI、简单敌人
行为树可读、可复用、模块化复杂决策要写很深的树大多数游戏 AI（主流）
决策树易理解、可配置化只做单次决策，无时序选择行为、技能选择
效用系统平滑、可量化、涌现性好参数难调、难调试策略游戏、资源分配
GOAP灵活、能生成未预设的行为难调试、性能不可控模拟类、沉浸式 AI
实战中它们是组合使用的 常见的组合方式：
• 行为树 + 决策树：行为树的某个节点做决策树判断，决定执行哪个分支
• 行为树 + 效用：用效用评分决定 Selector 的子节点优先级
• 状态机 + 行为树：大状态（巡逻/战斗/逃跑）用状态机，每个状态内部用行为树

不要试图用一个方案解决所有问题。

七、本章动手任务

本章过关标准：
① 能不看资料写出 Sequence、Selector、Inverter、Cooldown 四种节点；
② 能解释 RUNNING 状态的作用，以及它对跨帧动作的意义；
③ 能画出你项目中一个 AI 的完整行为树结构；
④ 知道黑板的作用与设计要点；
⑤ 能说出至少四种行为树的性能优化手段，并知道为什么"条件前置"最有效。

第 ① 条是硬要求——行为树是面试中让你"现场设计"的高频题。
