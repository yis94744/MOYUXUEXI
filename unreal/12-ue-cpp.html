    一、四个核心宏

    Unreal 用宏来实现反射——这是 C++ 本身没有的能力。C# 有反射，C++ 没有，所以 UE 自己造了一套。

    宏作用必须放在哪
    UCLASS()标记一个类参与反射类声明前
    USTRUCT()标记一个结构体结构体声明前
    UPROPERTY()标记成员变量变量声明前
    UFUNCTION()标记成员函数函数声明前
    UENUM()标记枚举枚举声明前
    UINTERFACE()标记接口接口声明前
    UPROPERTY 最大的作用：防止被 GC 回收 ★★★ 这是 Unreal C++ 最重要的规则。

    问题：UE 有垃圾回收。如果一个 UObject 没有被任何 UPROPERTY 引用，它会被回收。
    class AMyActor : public AActor {
      UMyObject* Data; // ❌ 没有 UPROPERTY，可能被回收！
    };
    表现为：运行一段时间后，Data 突然变成 nullptr，游戏崩溃。

    正确写法：
    UPROPERTY()
    UMyObject* Data; // ✅ 被 GC 追踪

    为什么难查：刚创建时有值，能正常工作——只有 GC 跑过一次后才出问题。

    规则：任何指向 UObject 的成员指针，都必须加 UPROPERTY。
    UPROPERTY 的常用说明符
    说明符作用
    EditAnywhere编辑器里可编辑（蓝图和实例都能改）
    VisibleAnywhere可见但不可编辑
    BlueprintReadWrite蓝图可读写
    BlueprintReadOnly蓝图只读
    Category="X"编辑器里的分组
    Transient不保存到磁盘
    Replicated网络复制（页 19）
    组合示例：
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category="Stats")
    float MaxHealth = 100.f;

    注意：说明符不改变代码逻辑——它们只影响编辑器、蓝图、网络的元数据。真正的效果由 UHT 生成的代码实现。

    二、Unreal 的垃圾回收机制

    概念说明注意
    UObject受 GC 管理必须用 UPROPERTY 持有
    非 UObject不受 GC 管理用智能指针或手动管理
    GC 触发引擎定期执行不是每帧
    引用追踪从根集合开始遍历UPROPERTY 是追踪线索
    Mark & Sweep标记可达对象，回收其余会有停顿
    什么时候 UObject 会被回收 规则：当一个 UObject 从"根集合"不可达时，就会被回收。

    根包括：
    · GameInstance、World、GameMode 等引擎持有的对象
    · 加了 UPROPERTY 的成员
    · 被 AddToRoot() 的对象

    危险场景：
    ① 局部变量持有——UMyObject* Temp = NewObject<UMyObject>(); → 函数返回后被回收
    ② 非 UPROPERTY 成员 → GC 后变 nullptr
    ③ 只被 C++ 容器持有——std::vector<UMyObject*> → 不被追踪

    解法：
    · 成员用 UPROPERTY()
    · 临时持有时用 TStrongObjectPtr（UE 提供的强引用）
    · 或 AddToRoot() / RemoveFromRoot()（要配对）
    UObject 不能用智能指针 常见困惑："我学了 RAII 和 shared_ptr，能不能用在 UObject 上？"

    答案：不能。
    · UObject 有自己的 GC 系统（和 shared_ptr 的引用计数冲突）
    · 混用会导致双重释放或泄漏

    正确的选择：
    类型用什么
    UObjectUPROPERTY() + 裸指针
    非 UObject 的堆对象C++ 智能指针（页 04）
    UE 的容器TArray/TMap 等

    UE 也提供了 TObjectPtr<T>（UE5 推荐）——
    它不是智能指针，而是带访问追踪的 UObject 指针。
    UPROPERTY() TObjectPtr<UMyObject> Data;

    三、UE 的命名约定

    前缀含义例子
    AActor 派生类ACharacter
    UUObject 派生类UActorComponent
    F普通结构体/类FVector
    I接口IDamageable
    T模板TArray
    E枚举EWeaponType
    B蓝图类BP_Character
    为什么命名约定这么重要 UE 的命名不是"风格问题"，而是编译要求：
    · A 和 U 前缀是 UHT 识别类类型的依据
    · 写错前缀会导致编译错误或反射失败

    规则：
    · 继承自 AActor → 用 A
    · 继承自 UObject → 用 U
    · 其他（含结构体）→ 用 F

    文件名要和类名一致：
    MyActor.h 里必须是 class AMyActor——否则 UHT 会报错。
