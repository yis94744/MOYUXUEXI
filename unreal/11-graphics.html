    一、渲染管线的六个阶段

    阶段做什么瓶颈常见于
    1. 顶点处理顶点着色器：坐标变换顶点数太多
    2. 图元装配把顶点连成三角形一般不是瓶颈
    3. 光栅化三角形 → 像素像素太多会慢
    4. 片元处理片元着色器：算颜色最常见的瓶颈
    5. 测试混合深度测试、透明度混合Overdraw 相关
    6. 输出写入帧缓冲带宽受限
    两个最需要理解的瓶颈点 ① 顶点数量（Vertex Bound）
    · 顶点着色器对每个顶点执行一次
    · 复杂模型、大量实例化对象时是瓶颈
    · 优化：LOD、剔除、简化模型

    ② 像素填充（Fill Rate / Pixel Bound）
    · 片元着色器对每个像素执行一次
    · 全屏后处理、半透明、粒子时是瓶颈
    · 优化：降低分辨率、减少 Overdraw、简化 Shader

    怎么判断瓶颈在哪：
    · 降低分辨率后变快 → 像素瓶颈
    · 减少模型面数后变快 → 顶点瓶颈

    这个判断方法比看 Profiler 更快。

    二、坐标空间的转换链 ★★

    空间含义转换
    模型空间模型自身的坐标系模型矩阵 →
    世界空间整个场景的坐标系视图矩阵 →
    观察空间以相机为原点投影矩阵 →
    裁剪空间准备做裁剪透视除法 →
    NDC标准化设备坐标（-1~1）视口变换 →
    屏幕空间像素坐标最终输出
    为什么需要这么多空间 每个空间解决一个问题：
    · 模型空间——模型可以复用（同一棵树用在多个位置）
    · 世界空间——处理物体间的关系（碰撞、光照）
    · 观察空间——简化"相对相机"的计算
    · 裁剪空间——高效剔除屏幕外的物体
    · NDC——与分辨率无关的标准化坐标
    · 屏幕空间——最终要写进具体的像素

    实战中的常见问题：
    · "为什么我的物体不在预期位置？" → 可能搞混了空间
    · "为什么缩放后位置偏了？" → 变换顺序错了

    Unreal 的帮助函数：
    GetActorLocation()——世界空间
    GetActorTransform()——包含旋转缩放
    UKismetMathLibrary::InverseTransformLocation()——空间转换
