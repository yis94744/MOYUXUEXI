    一、UMG 的关键实践

    概念作用注意
    Widget界面元素分 UserWidget 和底层控件
    Widget Blueprint可视化编辑主流方式
    SlateC++ 层 UI 框架性能更好
    Invalidation Box避免每帧重绘必用
    Retainer Box缓存渲染结果静态内容用
    Widget Switcher切换显示比隐藏/显示好
    UMG 最大的性能陷阱：每帧重绘 ★★ 问题：UMG 默认每帧都重新计算布局和重绘——哪怕界面完全没变。

    表现：
    · HUD 复杂时帧率明显下降
    · UI 越多越卡

    解决方案：
    ① Invalidation Box——包住不常变的界面部分
    ② Retainer Box——缓存成纹理
    ③ 用 Widget Switcher 而不是 SetVisibility（折叠的控件不参与布局）
    ④ 拆分 Widget——动态部分单独成 Widget

    实践原则：只有真正需要每帧更新的部分（比如血条、倒计时）才让它每帧重绘，其他都包进 Invalidation Box。
    不要在 Tick 里频繁创建 Widget 常见错误：
    // 每帧创建一个提示
    CreateWidget<UMyWidget>(...);
    创建 Widget 是"昂贵操作"——会有明显的 GC 和布局开销。

    正确做法：
    · 提前创建好，用的时候显示/隐藏
    · 或者用对象池复用（算法站页 26）
    · 列表类 UI 只创建可见的部分（虚拟列表）

    典型场景：聊天框、伤害数字、任务提示——这些高频出现的 UI 必须有池化方案。

    二、MetaSound 与音频

    组件作用性能
    Sound Cue传统音频逻辑轻
    MetaSound程序化音频比 Cue 重
    Sound Class音量分组必用
    Sound Mix动态音量调整轻
    Attenuation3D 衰减轻
    Concurrency限制同时播放数重要
    音频最容易被忽略的两件事 ① Concurrency（并发限制）
    如果不限制，100 个敌人同时开枪会有 100 个音效——音频线程爆炸。

    设置：同类型音效最多同时播 4~8 个，超出的截断最旧的。

    ② Sound Class 音量分组
    让玩家能分开调 BGM / 音效 / 语音——这是玩家的基本预期。

    结构：
    Master
    ├── BGM
    ├── SFX
    ├── Voice
    └── UI

    没有这个结构的话，后期要加音量设置会非常麻烦。
