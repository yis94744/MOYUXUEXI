    一、模板与 C# 泛型的区别 ★★

    维度C# 泛型C++ 模板
    实现方式运行时（JIT 生成）编译期（代码生成）
    约束where 子句concept（C++20）/ SFINAE
    实例化时机运行时编译时
    代码膨胀较小可能很大
    编译错误清晰极长（几百行）
    能力类型参数类型 + 值 + 模板模板参数
    C++ 模板的代价：编译时间与错误信息 实例化的意思：每个不同的类型参数都会生成一份代码。
    template<typename T> T Max(T a, T b);
    Max<int>(1, 2); // 生成 int 版本
    Max<float>(1, 2); // 生成 float 版本
    Max<MyClass>(...); // 又生成一份

    后果：
    · 编译时间增长——每个实例都要编译一遍
    · 可执行文件变大——多个版本的代码
    · 这是 Unreal 编译慢的原因之一

    错误信息为什么那么长：
    模板错误会显示完整的实例化链：
    在实例化 "TArray<UMyClass>::Sort" 时...
    在实例化 "TArray<UMyClass>::HeapSort" 时...
    ... (几十层)
    真正的错误往往在最后几行——从后往前读。

    二、游戏里需要的三个模板场景

    场景例子收益
    通用容器TArray<T>、TMap<K,V>类型安全 + 零开销
    通用算法template<typename T> void Sort(...)一次编写，多类型使用
    对象池template<typename T> class Pool每种类型一个池
    单例模板template<typename T> class Singleton避免重复代码
    编译期计算constexpr把计算移到编译期
    最实用的场景：对象池模板 游戏里每个类型都需要对象池：
    Pool<Bullet> bulletPool;
    Pool<Enemy> enemyPool;
    Pool<Particle> particlePool;
    模板让一份代码服务所有类型。

    对比 C#：
    C# 也能用泛型做到，但C++ 的版本没有装箱、没有虚调用——更快。
    而且 C++ 的模板能做 C# 做不到的事：
    · 编译期计算容量
    · 编译期选择策略
    · 零运行时开销

    Unreal 的实践：TArray/TMap 就是模板，UE 还提供了 TObjectPtr 等模板工具。

    三、C++20 的 concept：模板约束的革命

    concept 解决了什么 问题：C++20 之前，模板约束靠 SFINAE——极其难写难读。
    template<typename T, typename = std::enable_if_t<std::is_integral_v<T>>>
    这一行代码只有专家能看懂。

    C++20 的 concept：
    template<std::integral T>
    T Add(T a, T b) { return a + b; }
    清晰多了。

    自定义 concept：
    template<typename T>
    concept Damageable = requires(T t, int d) {
      { t.TakeDamage(d) } -> std::same_as<void>;
    };

    Unreal 的支持情况：
    · UE5 逐步支持 C++20
    · 但很多项目还在用 C++17
    · concept 会被越来越多地使用（因为错误信息友好得多）
