    一、C++ 与蓝图的职责边界 ★★★

    没有绝对正确的划分，但有一条被大量项目验证过的原则：

    内容放 C++放蓝图
    性能关键逻辑✓✗
    复杂算法✓✗
    数据结构定义✓可继承使用
    易变配置✗✓
    具体数值✗✓
    美术资源组合✗✓
    一次性逻辑✗✓
    策划能理解的流程✗✓
    一条实用的判断标准 问自己："这个东西多久变一次？"

    · 很少变（框架、算法、数据结构）→ C++
    · 经常变（数值、配置、流程）→ 蓝图

    为什么这样分：
    · C++ 改一次要编译几分钟（页 09）
    · 蓝图改一次立刻生效
    · 蓝图还能热更新（打包后也能改）

    经典模式：
    C++ 定义基类（框架）
      ↓
    蓝图继承并填数值

    例如：AWeapon（C++）→ BP_Rifle、BP_Shotgun（蓝图）
    蓝图的性能代价 蓝图比 C++ 慢多少：粗略估计 10~40 倍（取决于节点的复杂度）。

    为什么：
    · 蓝图是解释执行的（逐节点求值）
    · 每个节点都有虚函数调用开销
    · 参数传递要装箱解箱

    什么时候要换 C++：
    · Tick 里执行的逻辑
    · 大量实例同时执行（比如 100 个敌人每帧跑蓝图）
    · 数学密集的计算

    实践建议：先用蓝图做原型，确认逻辑稳定后再考虑要不要移到 C++。
    过早优化会浪费时间——很多蓝图逻辑根本不在热路径上。

    二、怎么把 C++ 暴露给蓝图

    说明符作用
    BlueprintReadWrite蓝图可读写变量
    BlueprintReadOnly蓝图只读变量
    BlueprintCallable蓝图可调用函数
    BlueprintImplementableEventC++ 声明，蓝图实现
    BlueprintNativeEventC++ 有默认实现，蓝图可覆盖
    BlueprintPure无副作用的函数（不加执行引脚）
    两个最有用的事件类型 ① BlueprintImplementableEvent——C++ 声明，蓝图实现
    UFUNCTION(BlueprintImplementableEvent)
    void OnWeaponFired();
    C++ 里没有实现，调用时执行蓝图的版本。
    用途：把"表现层"交给美术/策划（特效、音效、动画）。

    ② BlueprintNativeEvent——C++ 有默认，蓝图可覆盖
    UFUNCTION(BlueprintNativeEvent)
    void OnDamaged(float Amount);
    // 实现要加 _Implementation 后缀
    void AMyActor::OnDamaged_Implementation(float Amount) { /* 默认逻辑 */ }
    用途：默认行为 + 允许定制。

    注意：NativeEvent 的实现函数必须加 _Implementation 后缀——忘了会链接错误。
