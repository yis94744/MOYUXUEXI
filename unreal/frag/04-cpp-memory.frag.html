04 · 指针、内存与 RAII ★★★

这是C++ 最难也最重要的知识点。很多人卡在这里，是因为把内存管理当成"手动挡"——但现代 C++ 的核心思想是用 RAII 让编译器帮你管理。

这一页在路线中的位置 [object Object]

一、栈与堆：两种内存

理解 C++ 内存管理，首先要理解两种内存区域的区别。

缺少代码样本04/memory
栈（Stack）堆（Heap）
分配速度极快（移动指针）慢（找空闲块）
大小限制小（通常 1~8 MB）大（受物理内存限制）
生命周期离开作用域自动销毁手动管理
缓存友好是（连续）看分配情况
C# 里对应值类型（结构体）引用类型（类）
C# 程序员最容易犯的错 在 C++ 里习惯性地把一切放在堆上：
Monster* m = new Monster(...); // ❌ 不必要的堆分配
应该这样：
Monster m(...); // ✅ 栈对象

为什么：
· 栈分配几乎零成本（只是移动栈指针）
· 堆分配要查找空闲块、可能有锁竞争
· 栈对象自动销毁——不会忘记 delete
· 栈对象缓存友好——连续访问

判断标准：只有在对象"需要活过当前作用域"或"很大"时，才用堆。

二、RAII：C++ 最重要的设计思想 ★★★

RAII 是什么 RAII = Resource Acquisition Is Initialization
（资源获取即初始化）

核心思想：把资源的生命周期绑定到对象的生命周期。
· 构造函数里获取资源
· 析构函数里释放资源

本页实测的输出：
打开文件: save.dat
正在使用: save.dat
关闭文件: save.dat ← 离开作用域自动调用！
离开了作用域

为什么这是最重要的：
· 即使中途抛异常，析构函数也会被调用
· 即使提前 return，也会被调用
· 不可能"忘记释放"——因为编译器帮你记着

这正是 C# 的 using / Python 的 with 的底层原理。
智能指针：RAII 的标准实现 三种智能指针的选择：
指针所有权什么时候用
unique_ptr独占默认选择
shared_ptr共享（引用计数）确实需要多方持有
weak_ptr不持有打破循环引用
原则：能用 unique_ptr 就用 unique_ptr。
· 更轻量（没有引用计数的原子操作）
· 更清晰（所有权唯一，不会搞混）
· 需要共享时再改成 shared_ptr

本页实测输出验证：
· unique_ptr 移动后，原指针变空
· shared_ptr 的引用计数会正确增减
· weak_ptr 能检测对象是否已销毁
循环引用：shared_ptr 的致命陷阱 本页实测演示了这个陷阱：
a->next = b;
b->next = a; // ❌ 形成环
两个对象的引用计数都是 2（自己 + 对方），永远不会归零
→ 内存泄漏

本页输出验证：
a 计数: 2, b 计数: 2
【注意】离开作用域后，这两个对象【不会】被销毁

正确做法：一端用 weak_ptr
a->next = b; // 强引用
b->weakNext = a; // 弱引用（不形成环）
本页输出验证：两个对象都能正常销毁。

实战经验：父子关系、双向关联、观察者模式都要考虑这个问题。

三、三类内存错误

错误原因后果预防
内存泄漏new 后忘记 delete内存持续增长用智能指针
悬垂指针delete 后继续使用未定义行为delete 后置空
双重释放同一块内存 delete 两次崩溃用智能指针
越界访问数组下标超范围可能不崩溃（更糟）用 at() 或 vector
什么是"未定义行为"（UB） C++ 里最危险的概念：标准没有规定会发生什么。

UB 的可能表现：
· 崩溃（运气好的情况）
· 读到垃圾数据（更糟——bug 会传到后面）
· 看起来正常运行（最糟——在不同机器上崩溃）
· 甚至编译器可以把 UB 当作"不可能发生"来优化，导致诡异结果

常见 UB：
· 数组越界
· 空指针解引用
· 使用已释放的内存
· 有符号整数溢出
· 未初始化的变量

防护手段：用 std::vector 的 at()、开编译器警告、用 AddressSanitizer。
