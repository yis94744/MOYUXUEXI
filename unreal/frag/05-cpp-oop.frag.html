05 · 面向对象与多态

C++ 的 OOP 和 C# 差别很大：值语义、多重继承、虚函数表、没有接口。这一页讲清这些差异，以及游戏里怎么用。

这一页在路线中的位置 [object Object]

一、值语义 vs 引用语义

C#C++
类默认引用语义值语义
赋值拷贝引用拷贝整个对象
传参传引用默认传值（拷贝）
比较== 比引用== 比值（需重载）
多态自动（引用类型）需要指针或引用
最重要的差异：多态需要指针或引用 在 C# 里：
Animal a = new Cat(); // 直接多态
a.Speak(); // 调用 Cat 的版本

在 C++ 里这样写会出问题：
Animal a = Cat(); // ❌ 对象切片！
a.Speak(); // 调用 Animal 的版本

什么是"对象切片"（Object Slicing）：
· Animal a = Cat() 会把 Cat 对象拷贝到 Animal 类型的空间
· Cat 特有的成员被切掉了
· 虚函数表也变成了 Animal 的

正确写法：
Animal& a = cat; // 引用
Animal* a = &cat; // 指针
auto a = std::make_unique<Cat>(); // 智能指针（推荐）

这是 C# 转 C++ 最容易踩的坑之一。

二、虚函数与虚函数表

虚函数表（vtable）的原理 编译器怎么实现多态：
① 含有虚函数的类，编译器会生成一张"虚函数表"
② 表里存着各个虚函数的实际地址
③ 每个对象里有一个隐藏的指针（vptr）指向这张表
④ 调用虚函数时：通过 vptr 找到表，再找到函数地址

代价：
· 每个对象多一个指针的大小（通常 8 字节）
· 每个虚调用多一次间接寻址（难以预测分支）
· 无法内联（因为不知道具体调用哪个）

游戏里的影响：
· 大量频繁调用的虚函数会影响性能
· 但绝大多数情况下这点开销可以忽略
· Unreal 的 UObject 系统大量使用虚函数

关键规则：基类的析构函数必须是 virtual——
否则 delete 基类指针时，子类的析构函数不会被调用（资源泄漏）。
override 和 final 关键字 C++11 引入的两个关键字，强烈建议使用：

override：明确表示"我要重写基类的虚函数"
void Speak() override;
· 如果基类没有这个虚函数 → 编译错误
· 能防止"拼写错误导致没重写成功"

final：表示"不能再被重写"或"不能被继承"
void Speak() final; // 子类不能重写
class Cat final; // 不能被继承

为什么建议用 override：
这个错误非常隐蔽：
// 基类
virtual void Speak();
// 子类（忘了 const 或参数类型不同）
void Speak() const; // ❌ 不是重写，是新函数！
加了 override 就会立刻报错。

三、多重继承与接口

C++ 没有 interface，但有纯虚函数 用纯虚函数模拟接口：
class IDamageable
{
public:
  virtual ~IDamageable() = default;
  virtual void TakeDamage(int amount) = 0; // 纯虚
};
= 0 表示"没有实现，子类必须实现"

然后可以多重继承：
class Enemy : public AActor, public IDamageable
{
  void TakeDamage(int amount) override { /* ... */ }
};

Unreal 的接口约定：
· 接口类以 U 或 I 开头（如 IDamageable）
· 必须用 UINTERFACE 宏
· 实现类用 UCLASS + 多继承
页 13 会详细讲 Unreal 的接口写法。
