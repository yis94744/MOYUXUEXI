一、向量：游戏数学的基础

向量是游戏里最高频的数学工具。位置、方向、速度、法线，都是向量。

运算公式游戏里的用途
点积a·b = |a||b|cosθ判断前后、夹角、投影
叉积a×b（垂直两向量）判断左右、求法线
归一化a / |a|得到纯方向
距离|a - b|范围判断
平方距离|a-b|²省掉开方的比较
点积的三个实用判断 ① 判断在不在前方
dot(forward, toTarget) > 0 → 目标在前方
这是"敌人在我前面吗"的最快判断。

② 判断角度
dot 的归一化值 = cos(夹角)
1 = 同向，0 = 垂直，-1 = 反向

③ 投影
投影长度 = dot(a, b) / |b|
用于"沿某方向能走多远"的计算。

为什么重要：点积比 acos 快得多——能不用角度就不用角度。
叉积的方向：左手坐标系陷阱 ★★ 这是游戏开发中最容易出错的地方之一。

右手坐标系（数学标准、OpenGL）：
X × Y = Z（右手法则）

左手坐标系（Unity、Unreal、DirectX）：
X × Y = -Z

实测验证（在 Unity 里）：
Vector3.Cross(Vector3.forward, Vector3.right)
结果是 (0, -1, 0)，不是 (0, 1, 0)

实际影响：
· "判断目标在左边还是右边"的代码可能完全反了
· 在 Unity 里写对的代码，搬到 Unreal 或换成右手系就可能错

正确做法：不要记公式，而是用具体数值验证一遍。

二、四元数：旋转的正确表示 ★★

表示优点缺点
欧拉角直观易读万向节死锁
旋转矩阵计算方便存储大（9 个数）、会累积误差
四元数无死锁、可插值、紧凑不直观
万向节死锁：为什么不能只用欧拉角 问题：欧拉角用三个角表示旋转，但当第二个角接近 ±90° 时，第一个和第三个角的效果会重合——失去一个自由度。

表现：
· 旋转到某个角度后，某个轴突然"转不动了"
· 或者两个轴变成同一个效果

经典场景：相机上下看超过 89° 时视野开始翻滚。

解决：用四元数。但 UI 显示可以仍用欧拉角（方便人类理解）。

Unreal 的实践：
· FRotator——欧拉角（Pitch/Yaw/Roll）
· FQuat——四元数（内部计算用）
· 编辑器和 UI 用 Rotator，计算用 Quat。
四元数乘法的顺序（和矩阵一致） 关键：四元数乘法顺序与矩阵乘法一致。
q1 * q2 表示先应用 q2，再应用 q1。

实测验证（Unity）：
Quaternion ry = Quaternion.AngleAxis(90, Vector3.up);
Quaternion rx = Quaternion.AngleAxis(90, Vector3.right);
Vector3 result = (ry * rx) * Vector3.forward;
结果约 (0, -1, 0)——先绕 X 转（forward→down），再绕 Y 转（down 不变）。

常见错误：以为是"从左到右依次应用"——正好相反。
