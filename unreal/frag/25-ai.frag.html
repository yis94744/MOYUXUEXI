一、AI 辅助 UE 开发的真实效果 ★★

任务效果原因
基础 C++ 语法好标准知识
标准库用法好资料丰富
UE 宏的写法中容易漏细节
UE 类层次中可能记错继承关系
GAS / 网络代码差上下文太复杂
构建配置差版本差异大
AI 写 UE 代码的三个高频错误 ① 版本不匹配
UE4 的写法用在 UE5 上——比如：
· GetWorld()->GetTimeSeconds() 的替代
· 某些 API 改名或废弃

② 漏掉必要的东西
UE 的代码有很多"必须写"的部分：
· 忘了 GENERATED_BODY()
· 忘了 _Implementation 后缀（页 14）
· 忘了 UPROPERTY 导致 GC 回收（页 12）

③ .Build.cs 依赖没加
AI 给了代码，但没说要在 .Build.cs 加模块→ 链接错误（页 09）

防护：AI 给的 UE 代码，重点检查这三项——比逐行读代码快得多。
AI 在 UE 上最有价值的用法 不是"让它写代码"，而是：

① 解释不熟悉的代码
把一段引擎源码丢给它，让它解释——比读文档快。

② 找 API
"UE 里怎么做 X？"——它会给出函数名，你再自己去验证。

③ 写样板代码
USTRUCT 的定义、Subsystem 的框架、接口的声明——这些模板化的东西它写得不错。

④ 分析错误信息
把编译错误贴给它——模板错误的解读特别有用（页 06）。

关键是定位准确：AI 是"加速器"，不是"决策者"。

二、在 UE 里做 AI NPC

层次技术难度
行为 AI行为树 + EQS低（UE 内置）
对话 AI接 LLM中
语音 AI语音识别 + TTS中高
完整 NPC感知 + LLM + 行为高
UE 里接 LLM 的架构 四步循环（和 Lua 站页 23 讲的一样）：
① 收集上下文（玩家位置、对话历史）
② 调用 LLM（用 HTTP 请求）
③ 过滤输出（安全审核、格式校验）
④ 执行行为（映射到行为树能执行的动作）

UE 的实现要点：
· HTTP 要在非游戏线程（否则卡帧）
· 用 Subsystem 管理 LLM 连接（页 22）
· 输出必须走白名单（绝不能让 LLM 直接产生行为指令）

关键限制：LLM 响应要 1~3 秒——玩家等不了。
要用异步 + 打字机效果掩盖延迟。
