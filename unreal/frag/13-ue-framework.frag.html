一、核心类与继承关系

Unreal 的 Gameplay Framework 有明确的职责划分。理解每个类"该做什么"，比记住继承关系更重要。

类职责谁创建
UObject所有对象的基类—
AActor可放入关卡的物体关卡 / 代码 / Spawn
UActorComponent给 Actor 加能力Actor 创建
USceneComponent有 Transform 的组件Actor 创建
APawn可被控制的 ActorGameMode
ACharacter带移动的 PawnGameMode
AController控制 Pawn 的抽象GameMode
APlayerController玩家控制GameMode
AAIControllerAI 控制GameMode
AGameMode游戏规则（服务器）引擎
AGameState游戏状态（所有端）引擎
APlayerState玩家状态（所有端）GameMode
GameMode 与 GameState 的区别 ★★ 这是最容易搞混的一对。

AGameMode：
· 游戏规则——"怎么玩"
· 只在服务器存在（单机也有）
· 存放服务器专属逻辑（分数计算、胜负判定）

AGameState：
· 游戏状态——"现在什么样"
· 所有客户端都有
· 存放需要复制的状态（比分、倒计时）

判断标准：
· "这个数据客户端能看到吗？"
· 能 → GameState
· 不能 → GameMode

典型错误：把比分存在 GameMode 里，客户端拿不到。
Controller 与 Pawn 的分离设计 为什么要把"控制"和"被控制"分开：

场景 1：角色死亡
Pawn 销毁，但 Controller 保留——可以复活、可以观察其他角色

场景 2：切换角色
Controller 不变，只换它控制的 Pawn——玩家的输入配置不变

场景 3：AI 接管
PlayerController 换成 AIController，Pawn 不变——实现了"掉线托管"

这个设计的意义：把"意图"和"实体"解耦——这是 UE 框架最精妙的设计之一。

二、Actor 的生命周期

阶段函数注意
1. 构造Constructor编辑器也会调用
2. 初始化PostInitializeComponents组件已就绪
3. 开始BeginPlay游戏开始时
4. 每帧Tick需手动开启
5. 销毁EndPlay清理资源
6. 析构Destroyed / BeginDestroy不一定立即调用
Constructor 的三个坑 ① Constructor 在编辑器里也会执行
每次打开编辑器、拖入关卡都会调用。
所以不要在这里做游戏逻辑（比如随机数、读文件）。

② 不要在 Constructor 里调游戏 API
World 还不存在——GetWorld() 可能返回 nullptr。
要放到 BeginPlay。

③ 组件要在 Constructor 里创建
AMyActor::AMyActor()
{
  PrimaryActorTick.bCanEverTick = true; // 开启 Tick
  Mesh = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("Mesh"));
  RootComponent = Mesh;
}
这是 UE 的标准写法——组件是"默认子对象"。
