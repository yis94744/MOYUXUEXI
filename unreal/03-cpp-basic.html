    一、C++ 与 C# 的编译差异

    维度C#C++
    编译单元所有 .cs 一起编译每个 .cpp 独立编译
    声明与定义合一分离（头文件 vs 源文件）
    链接运行时加载编译后链接成可执行文件
    符号名称修饰（简单）名称修饰（复杂，含类型信息）
    错误时机编译期多链接期也有大量错误
    编译速度快慢（每个文件独立编译）
    核心概念：声明 vs 定义 这是理解 C++ 编译模型的关键。

    声明（Declaration）：告诉编译器"有这么个东西"
    int Add(int a, int b); // 只有签名，没有实现

    定义（Definition）：给出具体实现
    int Add(int a, int b) { return a + b; }

    为什么必须分离：
    · .h 头文件放声明——被多个 .cpp 包含
    · .cpp 源文件放定义——只编译一次
    · 如果定义放在头文件里，每个包含它的 .cpp 都会有一份→ 重复定义错误

    例外：inline 函数和内联成员函数可以放头文件
    因为编译器会把它们"展开"到调用处，不产生独立符号。
    编译错误的三种类型 ① 编译错误（Compile Error）
    单个 .cpp 文件的问题——语法错、类型不匹配、找不到声明
    报错格式：file.cpp(line): error C####: 描述

    ② 链接错误（Link Error）
    所有 .cpp 编译通过后，链接器发现"某个符号找不到"
    典型错误：unresolved external symbol
    常见原因：
    · 声明了但没定义（写了头文件，忘了实现）
    · 忘了把 .cpp 加入项目
    · Unreal 中：忘了在 .Build.cs 里加模块依赖

    ③ 运行时错误（Runtime Error）
    编译链接都过了，运行时崩溃——这是 C++ 最危险的
    因为编译器不检查数组越界、空指针、类型转换等

    二、头文件的写法规范

    四个必须遵守的规则 ① 头文件保护（Include Guard）
    #pragma once 或
    #ifndef MY_HEADER_H / #define MY_HEADER_H / #endif
    防止同一个头文件被重复包含。
    Unreal 用 #pragma once（更简洁）。

    ② 前向声明（Forward Declaration）
    class Monster; // 只声明，不包含头文件
    如果只是用指针或引用，不需要完整的类定义——能显著加快编译。
    这是 Unreal 项目里最重要的编译优化手段。

    ③ 头文件里不要写 using namespace
    会污染所有包含它的文件。
    要在 .cpp 里用。

    ④ 包含顺序
    · 先自己的头文件
    · 再项目内的
    · 再第三方库
    · 最后标准库
    （Unreal 要求自己的头文件必须放第一个）
