11合并编辑器：逐行选择保留谁

冲突时最舒服的解决方式，是让专门的工具帮你逐行挑选保留谁。 TortoiseSVN 自带的 TortoiseMerge 就是干这个的—— 左右两版并排摆开，你只管在中间那份上做决定。

为什么值得用工具，而不是硬啃标记

上一节讲的「手工删标记」当然可行，但冲突一多就会很累： 你要在成百上千行里找到那些 <<<<<<<， 还得记住哪一段是谁的。

TortoiseMerge 把这些工作接了过去：两边的内容并排摆给你看， 差异用颜色标出来，冲突的地方自动跳过去， 你只需要一处一处点「用我的」或「用他的」。

而且它自带语法高亮、行号对齐，比在记事本里对着标记发呆高效得多。

三栏模式：左右对照，中间出结果

冲突时打开的就是三栏模式。它的布局非常直观： 两个来源在两边，结果在中间。你要做的就是照看中间那一栏。

◈TortoiseMerge 三栏模式（点击图可放大）Three-Pane Merge
这个窗口分三栏，每一栏的职责完全不同，认清了就不会乱：

① 左栏 · 我的版本（Mine）——你本地改完的样子，也就是文件里 <<<<<<< .mine 那一段的内容。 这一栏是只读的参照，你在上面点选，决定要不要把某一块搬到中间。

② 右栏 · 别人的版本（Theirs）——服务器上最新的样子， 也就是同事提交过来的内容。同样作为参照摆在右边。
左右两栏的作用是「给你看两个候选」，不要指望在这里改东西。

③ 中栏 · 合并结果——这才是最终会被保存进文件的内容。 它一开始是 SVN 自动拼出来的半成品（两边不冲突的部分已经拼好了，冲突部分留了标记）， 你在这里做决定：每一处冲突到底留谁的。 改完之后保存，写回磁盘的就是这一栏。
记住这个分工：两边看，中间改。

④ 顶部的颜色条——三栏上方各有一条细细的指示条， 上面红色的块标出「哪些行还有问题」。 它能让你一眼看出整个文件一共几处需要决策、以及它们分布在文件的什么位置， 不用滚到底才发现下面还埋着好几处。
点颜色条上的红块，视图会直接跳到那一处，比滚轮快得多。

⑤ 工具栏按钮——最常用的几个是： 跳到上一处 / 下一处冲突（一处一处过，不用自己找）、 选用我的 / 选用别人的（把当前这一块整体替换成某一方， 这是使用频率最高的操作）、 以及 保存。
按钮的具体位置和图标在不同版本里略有差异，但功能就是这几类。
界面区域它是什么你要在这里做什么
左栏 · Mine 我的改动 不需要编辑。对照用：想留自己写法时就往中间搬。
右栏 · Theirs 别人的改动 同样只作对照。想采纳同事的写法时用它。
中栏 · 合并结果 即将保存的内容 唯一需要你动手的地方。冲突处选一边， 或者两边都留、手工调成最终版。
顶部颜色条 问题分布图 看红色块的数量和位置，确认没有漏掉任何一处冲突。
工具栏 跳转与选用 上一处/下一处、选用我的/选用别人的、保存。
三栏模式里最容易搞反的两件事
  • 认「我的」和「别人的」别靠位置靠文字。 左栏是你自己改的，右栏是同事提交的。 分不清的时候，看一眼栏目标题上的 Mine / Theirs。
  • 别在左右两栏里编辑。它们只是参照。 你真正要负责的只有中间那一栏——左右栏改了不会生效，会白白浪费时间。

双栏模式：单纯比对两个文件

如果不是冲突，只是想知道两个文件到底哪里不一样， 打开的就是双栏模式。它没有中间那一栏，只是左右对照。

◈TortoiseMerge 双栏模式Two-Pane Diff
双栏模式把两个文件并排铺开，中间有连接线把对应的行牵起来，一眼就能看出哪里被增删了。

它什么时候出现：
• 右键文件选 TortoiseSVN → Diff with previous version 时（看这个文件比上一版改了什么）
• 在 Show log 里双击某个文件时
• 用 Diff 类功能做「设置 TortoiseMerge 为默认比对工具」之后的各种比对场景

它和冲突处理的关系：双栏只看不改，是「读」的工具； 三栏是要产出结果的，是「写」的工具。 冲突解决用三栏，日常比对用双栏，不要混着用——在双栏里改是改不出合并结果的。

和图片比对的区别：如果要比的是 PSD、PNG 这类图片， TortoiseSVN 会自动改用 TortoiseIDiff， 左右两张图并排显示、同步缩放，专门用来比对美术资源。

用 TortoiseMerge 解决冲突的完整步骤

MERGE从打开到标记已解决
在冲突文件上右键，选择编辑冲突 已经处于冲突状态的文件，右键菜单里都能找到打开合并工具的入口 （Edit conflicts 这类选项）。
也可以先看 Show log 弄清对方那次提交的意图，再动手——先读后改，少返工。
工具打开，先别急着点，扫一遍顶部颜色条 数一数红色块大概有几处。心里有数了再开始， 能避免「以为改完了、结果往下滚还有一堆」。冲突少就是几分钟的事，冲突多要有心理准备。
用「下一处冲突」逐处跳过去 不用自己拿滚轮找。点一次跳一处， 每一处都会把「我的」和「别人的」并排展示给你看。 一处处理完，它自动带你去下一处。
每一处决定：用我的、用别人的，还是自己合 大多数情况点一下就完事。但也有些情况两边都不能直接要—— 比如你的改动和新逻辑得一起进来，这时候就在中栏手工编辑， 把它调成最终正确的样子。
判断依据是「业务上哪个对」，不是「谁先提交的」。
保存 点工具栏的保存按钮，中栏的内容写回文件。 这一步不做，前面全白忙——工具里改的东西只存在内存里。
关掉工具，回到资源管理器右键 Resolved 保存只是把文件内容改好了，SVN 还不知道你已经处理完。 对着文件右键 → TortoiseSVN → Resolved， 角标才会从黄底红叹号变回绿色对勾。
提交，说明里写清怎么合的 在 Message 里写明白哪一处留了谁、为什么。 比如 解决登录校验冲突：沿用对方的新接口，保留本地的参数校验。 这样以后别人查这一版，能看懂你当时的取舍。

颜色含义：看一眼就知道这段属于什么

颜色代表什么怎么处理
黄色 冲突块 两边在这段打架了，必须由你决定留谁。 这是唯一你必须动脑子的部分。
绿色 新增 这段内容是相对另一侧多出来的（新加的行/块）。 通常直接采纳，但要留意它会不会和别处重复。
红色 删除 这段内容在另一侧被删掉了。 要判断是「真的该删」还是「误删」——这是最容易被忽略的一类。
正常色 两边一致 没有任何差异。完全不用管，工具已经自动处理好了。
「红色 = 删除」这两类的判断不能偷懒

新增（绿）一般不用纠结：多出来的东西留着多半没坏处。 但删除（红）要当心：

  • 如果同事删除的是废弃代码，那删得对，采纳。
  • 如果同事删除的是你还要用的东西（比如他重构时顺手删掉的一个分支）， 采纳就会悄悄丢掉功能——编译能过、运行到那条路才报错，这是最难查的一类问题。

看到红色的整块删除时，停下来读一眼，别一路点「下一处」冲过去。

什么时候用三栏，什么时候干脆手工改

两种方式不是对立的，按冲突量选就行：

  • 冲突只有一两处——用三栏最快。 打开、跳过去、点两下、保存，一分钟搞定，而且不容易漏掉标记。
  • 冲突特别多、遍布整个文件——直接在文本编辑器里手工改反而更快。 几十处冲突在工具里一处处点，光是等待和切换就很累； 这时候把文件整个打开，用编辑器的查找功能直接搜 <<<<<<< 这个符号，一处一处往下跳着改， 反而更顺手、更有全局感。
  • 改动是「重写式」的（这一版基本推翻上一版）——三栏的意义不大， 直接确定用哪一版更省事。

核心原则：工具是为了省力，不是为了好看。 哪个方式让你更快、更不容易出错，就用哪个。

两种方式怎么选

✗ 手工编辑冲突文件

优点：只要有文本编辑器就能干，不用切换窗口； 对文件全局改动有整体感，改大段内容时更顺。

缺点：要自己找标记行，容易漏掉藏在文件深处的某一处； 一旦忘了删掉标记，编译直接失败；看不出哪些是新增、哪些是删除， 只能靠读代码判断。

适合：冲突特别多、而且改动是重写式的场景； 或者你手上的编辑器有很强的版本对比插件。

最大风险：漏删标记、漏改某处 — 提交后才发现，损失更大。

✓ 用 TortoiseMerge

优点：两边并排看得一清二楚，不用自己找标记； 顶部颜色条把问题点全标出来，漏不了； 保存后标记清理得干干净净。

缺点：冲突几十处时要一处处点，比较费耐心； 初次打开这种工具需要一点适应时间。

适合：日常绝大部分冲突场景 — 尤其是冲突集中在几个位置、你想快速处理掉的情况。

最佳组合：三栏过一遍确保不遗漏， 遇到需要大改的段落切回编辑器细调，最后再回来存一次。

把冲突处理变轻松的几条习惯
  • 动手前先看日志。弄清对方那次提交想干什么， 再决定留谁。这一步花两分钟，能省掉后面反复返工。
  • 一次只处理一个文件。冲突文件多的时候， 一个一个来，处理完一个就右键 Resolved 一个，别攒着一起做。
  • 处理完通读一遍。工具帮你解决了差异，但 「合起来语法对不对、逻辑通不通」只有你能判断。
  • 拿不准就问人。冲突的本质是两个人对同一处代码有不同理解， 这时候最快的方式是直接沟通，而不是猜。
  • 提交前再更新一次。你解决冲突的这段时间里， 别人可能又提交了——再更新一次，避免马上又撞一次。
