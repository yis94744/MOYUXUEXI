25图形操作速查表

前面二十四节讲的都是「为什么」和「怎么做」。这一节把它们压成几张表： 遇到事情不用翻前文，看一眼「我要做什么」那一栏，照着右边的菜单路径点就行。 建议把这一节单独打印出来贴在工位旁边——用熟了之后，你会发现常用的其实就那么七八个操作。

怎么读下面这些表
  • 菜单路径一律写成这种形式：TortoiseSVN → Commit...，意思是右键 → 展开 TortoiseSVN 子菜单 → 点 Commit...。
  • 路径开头的「文件夹上右键」和「文件上右键」不一样，选错对象菜单会对不上，表里都标了。
  • 顶层菜单里带 SVN 前缀的那几个（SVN Update、SVN Commit...、SVN Check for modifications）不用展开子菜单，右键就能直接点。
  • 第三列「注意事项」比第一列的路径更重要——那些都是踩过坑才写下来的。

核心操作速查

我要做什么右键菜单路径注意事项
检出代码空文件夹上右键 SVN Checkout...选一个专门的空文件夹，别和已有的东西混在一起。地址从服务器管理员那里要（第 19 节）。
更新代码
每天开工第一件事		工作副本上右键 SVN Update动手改代码之前先更新，能省掉大部分冲突。提交前建议再更新一次。
提交改动工作副本上右键 SVN Commit...勾选要提交的文件，Message 一定要写（写清改了什么、为什么）。别把调试用的临时改动一起提交。
查看自己改了什么
提交前必做		工作副本上右键 SVN Check for modifications这个列表就是本次提交将要包含的内容。看完再提交，能避免误提交。
看某文件的改动历史文件上右键 TortoiseSVN → Show log上方选某个版本，下方列出它改了哪些文件；双击文件看差异。只关心这一个文件时，日志窗口里可以只看它的历史。
比对两个版本右键 TortoiseSVN → Show log → 选中两个版本 → 右键 Compare revisions会打开比对工具左右并排显示。按 Ctrl 或 Shift 可多选版本，选两个再比。
新增文件新文件上右键 Add角标从灰色问号变成蓝色加号才算登记成功。提交时别漏了它所在的文件夹，否则可能提交不上去。
删除文件文件上右键 TortoiseSVN → Delete用这个菜单项删，不要直接在资源管理器里按 Delete。直接删只是本地少了个文件，SVN 那边还留着记录。
重命名文件文件上右键 TortoiseSVN → Rename千万不要用 F2 改名。那样 SVN 会以为「删了一个旧文件 + 加了一个新文件」，历史就断了。用菜单里的重命名才能保住历史。
移动文件按住右键拖动文件到目标位置，松手后选 SVN Move versioned files here一定要用右键拖、不要用左键拖，拖完在弹出的菜单里选带 SVN 字样那一项，才能保住历史。
撤销本地改动
不可逆		文件上右键 TortoiseSVN → Revert...Revert 不可逆，本地未提交的修改会直接消失（第 9 节）。动手前想清楚，大改动之前先提交一次。
撤销已提交的改动右键 TortoiseSVN → Show log → 选中那次提交 → 右键 Revert changes from this revision → 再提交SVN 里历史不能真的抹掉，做法是「做一次反向修改再提交」。提交说明里写清「回退第 N 版」。已经发给别人的版本别这么干。
拉回历史版本
回看旧代码		右键 TortoiseSVN → Update to revision...这是临时让本地回到某一版，看完记得再更新回最新。想永久回到旧版并留下记录，用上一行的做法。
创建分支工作副本上右键 TortoiseSVN → Branch/tag...在 To path 里填分支路径（如 /branches/dev-xxx）。版本一般保持默认的最新即可（第 12 节）。
切换分支工作副本上右键 TortoiseSVN → Switch...切换前先把当前分支的改动提交掉，否则容易带过去或冲突。切换后确认一下日志里的地址对不对（第 13 节）。
合并分支目标分支的工作副本上右键 TortoiseSVN → Merge...先用 Test merge 预览一遍再真合并。合并完要提交才算完成（第 14 节）。
创建标签
发版留底		工作副本上右键 TortoiseSVN → Branch/tag...和建分支是同一个对话框，只是路径填到 /tags/v1.0。标签目录通常设成只读，打完就别再改。
查看版本图
理清分叉关系		工作副本上右键 TortoiseSVN → Revision graph图上能看清分支从哪分出去、在哪合回来。看不明白先调设置里的分类模式（第 15、23 节）。
忽略文件
编译产物别再烦我		未版本控制的文件/文件夹上右键 TortoiseSVN → Add to ignore list忽略规则是按后缀或按名字设的，加完记得提交，否则只在你本机生效（第 16 节）。
查看/设置属性文件/文件夹上右键 TortoiseSVN → Properties能设换行风格、关键字替换、二进制文件类型等。属性改动也要提交才对别人生效（第 17 节）。
加锁 / 解锁文件上右键 TortoiseSVN → Get lock / TortoiseSVN → Release lock用在不方便合并的二进制文件上（PSD、Excel）。收工就释放，别长期占着（第 18 节）。
导出干净副本
不含版本控制		任意文件夹上右键 TortoiseSVN → Export...导出来的是没有 .svn 的干净代码，给客户、打包发布用它。别在导出目录里开发（第 22 节）。
创建补丁改动所在的文件夹上右键 TortoiseSVN → Create patch...勾选要包含的改动，存成 .patch。适合还没有提交权限或需要先给同事评审的场景。
应用补丁目标文件夹上右键 TortoiseSVN → Apply patch...先 Update 再应用，失败率低很多。应用前逐项预览差异，别闭着眼睛点确定。
清理工作副本
万能修复		工作副本上右键 TortoiseSVN → Clean up「已锁定」「角标不对」「状态混乱」都先做它。不改文件内容，放心点（第 24 节）。
清除认证数据
换账号必备		右键 TortoiseSVN → Settings → Saved Data → 认证数据那一行点 Clear改了密码却一直认证失败的第一解法。只清本机缓存，不动服务器、不动代码。
浏览服务器仓库
不用检出就能看		任意位置右键 TortoiseSVN → Repo-browser直接看仓库里的目录和文件，也能在里面下载文件、建目录、看历史。查一个文件、确认一个地址时最方便。
看某一行是谁改的文件上右键 TortoiseSVN → Blame每行前面标出改它的版本号和作者。排查「这行代码什么时候变坏的」非常好用。
把整批文件传上仓库本地文件夹上右键 TortoiseSVN → Import...传完本地文件夹不会变成工作副本，还要另外检出一次才能继续开发（第 22 节）。

图标角标速查

角标是最省事的状态提示：不用打开任何窗口，扫一眼文件夹就知道有没有活儿没干完。

图标含义该做什么
绿色对勾 Normal和服务器完全一致什么都不用做。看到一片绿勾说明本地干净。
红色叹号 Modified本地改过、还没提交这是最常见的状态。改完、确认无误后提交它。
蓝色加号 Added新增文件，已登记待提交提交之后会变成绿色对勾。别只在本地加不上传。
灰色问号 UnversionedSVN 完全不认识它要么右键 Add 纳入版本控制，要么 Add to ignore list 忽略掉。提交时它会被跳过。
红色叉号 Deleted已标记删除，还没提交提交后服务器上也会删掉。如果是误删，右键 Revert 就能恢复。
黄色小锁 Locked文件被加了独占锁是你加的——改完提交后释放；是别人加的——先沟通，别硬来。
黄底红叹号 Conflicted冲突，必须人工处理按第 10、11 节解决，处理完右键 Resolved，再提交。这是唯一必须先解决才能提交的状态。
无角标 Ignored / 空目录被忽略的文件，或空文件夹正常现象，不用管。如果该有角标却没有，见第 24 节「角标不显示」。
只读图标 ReadOnly文件被设成了只读属性常见于设了「必须先加锁才能改」的文件。先加锁再编辑（第 18 节）。

对话框速查

对话框名什么时候会用到它
Checkout 检出第一次从服务器把代码拉下来；换机器重建环境；拉一个新分支到本地。
Commit 提交把本地改动上传到服务器。用得最多的一个对话框。
Show log 日志看历史、看某次提交改了哪些文件、比对两个版本、回退某次提交。
Repo-browser 仓库浏览器不检出就看仓库内容；确认目录结构；在服务器端建目录、传文件。
Revision graph 版本图理清分支从哪来、合到哪去；给人解释版本是怎么走的。
Revert 撤销放弃本地未提交的改动。不可逆，会列清楚要丢掉哪些文件。
TortoiseMerge 合并工具冲突处理；比对两个文件的差异（三栏解决冲突、双栏纯比对）。
Branch/tag 分支/标签开一条新的开发线；给已发布的版本打一个标签留底。
Switch 切换同一个工作副本换成另一个分支，不用重新检出。
Merge 合并把分支上的改动并回主干，或把主干的改动同步到分支。
Clean up 清理状态乱了、锁残留了、角标不对了——万能修复。
Export 导出要一份不带版本控制的干净代码：交付、发布、部署、归档。
Import 导入把一批现成文件一次性放上仓库，不需要先检出。
Create patch / Apply patch 补丁没有提交权限时交付改动；接收别人发来的改动。
Properties 属性设置换行风格、关键字替换、忽略规则、二进制文件类型。
Get lock 加锁二进制文件独占编辑，防止两人同时改同一个 PSD、Excel。
Settings 设置精简右键菜单、调角标、清除认证数据、更换比对工具。

每天做什么，每周做什么

每天必做
  • 开工先更新。右键 SVN Update，把别人昨天的改动拉下来。这一步省掉后面大部分冲突。
  • 改完先自查。SVN Check for modifications，看清自己到底动了哪些文件。
  • 收工前提交。右键 SVN Commit...，Message 写清楚。别把没提交的活儿留在机器上过夜。
  • 提交前再更新一次。顺序是「更新 → 有冲突先解决 → 提交」，反过来会让你反复撞同一个错。
  • 看到红色叹号就处理掉。攒着一堆未提交的改动，风险只会越滚越大。
每周建议
  • 清一遍工作副本。右键 TortoiseSVN → Clean up，把状态理顺、顺手收缩一下缓存。项目大的话能省出可观空间。
  • 检查有没有长期占用的锁。同事加了锁没释放，会一直卡着别人。
  • 清理不用的工作副本。试探性检出、demo 分支用完就删掉。
  • 整理忽略规则。新出现的编译产物加进忽略列表，别让灰色问号越堆越多。
  • 看一眼仓库的历史。翻翻最近几十条提交，了解团队在做什么、有没有人提交信息写得太随意。
三条人人都该记住的红线
  • 改名和移动一律用 SVN 菜单，不要用 F2、不要用左键拖。保住历史比省一次点击重要得多。
  • 提交前一定先更新。「先提后更」是最常见的自找麻烦。
  • Revert 之前想清楚。它没有撤销键，丢掉的改动找不回来。大改动之前先提交一次做保险。
团队协作约定模板（可以直接抄给团队）

一、提交信息怎么写

  • 格式：【模块】一句话说清做了什么，必要时再加一行补充原因。
  • 好的例子：【登录】修复验证码过期后无法重新获取的问题。
  • 坏的例子：改了、更新、123、一整片空白。这种提交等于没写，半年后谁也不知道当时干了什么。
  • 一次提交只说一件事。不要为了「一起提交」把三个不相关的改动捆在一起，回退时会很痛苦。

二、目录怎么用

  • trunk：所有人共用的主线，只放随时能跑的代码。
  • branches：需要长期开发或改动较大的事，开分支做，做完合并回主干。
  • tags：每个发布的版本打一个标签，只读，谁也不许改。

三、分支怎么命名

  • 开发分支：branches/dev-功能名-姓名缩写，例如 dev-login-zhangs。
  • 修复分支：branches/fix-问题简述，例如 fix-excel-export。
  • 发布标签：tags/v版本号，例如 v1.2.0，和发布单上的号对齐。
  • 用英文小写加连字符，别用中文、空格和特殊符号。

四、什么时候提交

  • 做完一个能讲清楚的小事，就提交一次。一提交就是一张快照，粒度小才好回退。
  • 下班前把能提交的都提交掉。留在本机的改动没有任何保护。
  • 不要提交跑不起来的代码到主干。做一半的功能请放到分支里。
  • 不要提交编译产物、本地配置、密码和大文件。用忽略规则挡掉。
  • 提交前先更新，有冲突当场解决，不要等到第二天。

五、出问题找谁

  • 状态类问题（锁定、角标、认证）自己先走万能三步（第 24 节）。
  • 权限问题找服务器管理员（第 20 节）。
  • 不确定的改动先做补丁、先沟通，不要赌一把直接提交主干。

这份约定不用一次背下来。把它发到团队群里、贴在项目文档里，新同学入职时看一眼，能省掉后面几个月的来回解释。

到这里，整套流程你都能用鼠标走完了

二十五节走下来，从检出、日常提交、看历史、处理冲突、开分支合并，到服务端建仓库、配权限、做备份， 再到补丁、导出、设置和排错——所有这些操作都能在资源管理器右键和对话框里完成。

剩下的事情只有一个：用起来。把这一节打印出来贴在旁边，前两周偶尔查一下，之后就是肌肉记忆了。
