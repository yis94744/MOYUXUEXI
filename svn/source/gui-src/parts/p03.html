3看懂图标角标与右键菜单

这一节是「认路」——把 TortoiseSVN 的界面元素全部认一遍。 认全之后，后面每一节你都能立刻知道该点哪里。

文件夹的右键菜单（已版本控制）

这是你最常打交道的菜单。项目已经检出、正常工作中，就对着这个菜单操作。

◈工作副本文件夹的完整右键菜单Context Menu · Directory
菜单分三层：顶层常用命令（带 SVN 前缀）+ TortoiseSVN 子菜单（全功能）+ 系统右键项（下面的 Shell 部分）。 下面把每一项按用途分组讲清。
顶层三个（最常用，少点一次）
  • SVN Update —— 拉取别人的改动。每天开工第一件事。
  • SVN Commit... —— 提交你自己的改动。干完活收尾。
  • SVN Check for modifications —— 看看自己改了哪些文件，提交前自查用。
TortoiseSVN 子菜单 · 查看类
  • Show log —— 提交历史。查「这行代码谁写的」。
  • Repo-browser —— 直接浏览服务器上的内容，不用检出。
  • Revision graph —— 分支走向图，直观看出谁从哪分出去的。
  • Properties —— 属性对话框（忽略规则、换行符、锁等）。
TortoiseSVN 子菜单 · 修改类
  • Add... —— 把新文件纳入版本控制。
  • Delete —— 删除文件（走 SVN，保留历史记录）。
  • Rename... —— 重命名（保留历史，别用系统的 F2）。
  • Revert... —— 撤销本地改动，恢复原样。
  • Clean up —— 工作副本卡住时的「万能修复」。
TortoiseSVN 子菜单 · 分支与合并
  • Branch/tag... —— 创建分支或标签。
  • Switch... —— 切换工作副本对应的分支。
  • Merge... —— 把分支改动合并回来。
  • Update to revision... —— 更新到指定版本（回看历史用）。
  • Export... —— 导出干净副本（不含 .svn）。
菜单太长？把它变短

如果你觉得右键菜单太啰嗦，可以让顶层那三个 SVN 项也收进子菜单：

TortoiseSVN → Settings → 左侧选 Context Menu → 在列表里取消勾选不想在顶层显示的项。

反过来，如果你想把某个子菜单项提到顶层，也在同一页设置（勾选即可）。

文件上的右键菜单

对着单个文件右键和对着文件夹右键，菜单略有不同。文件上多了一些文件专属的操作。

◈已版本控制文件的右键菜单Context Menu · File
和文件夹菜单的差异主要在：
• 多了 Blame...（逐行追责，看每行是谁改的）
• 多了 Get lock（给这个文件加锁）
• 少了 Branch/tag、Switch、Merge、Clean up 等只对目录有意义的命令

原则：分支、合并、清理这类操作对文件夹做；比对、追责、加锁对文件做。
◈未加入版本控制的文件（灰色问号角标）Unversioned File
未版本控制的文件，TortoiseSVN 几乎不管它，菜单里只有几个选项。其中最有用的两项是：
• Add... —— 把它纳入版本控制（提交时才会带上它）
• Add to ignore list —— 忽略它（以后不再出现在待提交列表里，编译产物就靠这个）

记住这个规律：文件还没被 SVN 管，就先 Add 或者 Ignore，二选一。

拖动文件的特殊菜单

还有一个不常被发现的技巧：用鼠标右键拖动文件到别的位置， 松手时会弹出一个菜单，里面多了 SVN 的专属选项。

◈右键拖动松手后的菜单Right-drag Menu
用右键把文件拖到另一个文件夹，松手就会看到这个菜单。 里面的 SVN Move versioned files here 才是正确的「移动」方式—— 它会告诉 SVN「这是同一个文件换了位置」，历史记录不会断。

如果用普通的拖放（左键拖或系统剪切粘贴），SVN 会以为是「删了一个文件 + 加了一个新文件」， 查历史时就断了。
两条铁律：重命名和删除都要走 SVN
✗ 错误做法

按 F2 直接重命名文件

按 Delete 直接删文件

用 Ctrl+X / Ctrl+V 剪切粘贴

左键拖拽移动文件

→ SVN 会当成「删一个+加一个」，历史断掉， 查不到这个文件以前的样子

✓ 正确做法

TortoiseSVN → Rename...

TortoiseSVN → Delete

TortoiseSVN → Cut 后到目标位置 Paste

右键拖拽 → SVN Move versioned files here

→ 历史完整保留，随时能查出这个文件的前世今生

工作副本里的隐藏文件夹

检出之后，你的项目文件夹里会多出一个隐藏的 .svn 文件夹 （每个子文件夹里也有）。 这是 SVN 的「大脑」——它记录着每个文件的原始版本、你改了哪些、哪些加了锁。

千万别做
  • 手动删除 .svn 文件夹——工作副本立刻失效，只能重新检出
  • 把整个项目文件夹压缩发给同事——他解压后 .svn 里的信息是错的，提交会出乱子
  • 把 .svn 加进版本控制——它是本地元数据，不该提交
  • 用「复制粘贴」把项目文件夹复制一份当第二个副本用
要做的事
  • 想让同事拿到代码 → 给他仓库地址，让他自己 Checkout
  • 想要第二份副本 → 再 Checkout 一次到别的文件夹
  • 文件夹看起来坏了 → 先试 TortoiseSVN → Clean up
  • 实在修不好 → 删掉整个文件夹，重新 Checkout（代码在服务器上，不会丢）
