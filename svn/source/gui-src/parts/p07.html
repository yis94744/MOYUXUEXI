7新增、删除、重命名文件

前面几节讲的都是「改文件内容」。这一节讲动文件本身：新建、删除、改名、挪位置。 这些操作有一个共同点——必须让 SVN 知道，不能像平时用 Windows 那样随手一按就完事。

为什么「动文件」比「改内容」更需要小心

改内容的时候，文件还是那个文件，SVN 只要记下「这一版和上一版不一样」就够了。但删除、重命名、移动会改变文件在仓库里的存在方式，而 SVN 的历史是跟着「这个文件」走的。

  • 你用资源管理器改个名字，SVN 看到的是「老名字的文件不见了，多了个新名字的文件」——等于一刀两断，从此新名字的文件历史从零开始。
  • 你用 SVN 的菜单改名字，SVN 记录的是「这个文件被改名为某某」——历史是连续的，往前翻能看到它改名之前的每一次修改。

差别就在日常里：半年后你想查「这个文件当初为什么这么写」，走对路的人一查到底，走错路的人查到一个「新建文件」就断了。

新增（Add）：让 SVN 认识新文件

你在项目里新建了一个文件、或者拷进来一份新资料——此时 SVN 完全不知道它的存在。它在你本地的角标是灰色问号，也不会出现在提交列表里。必须显式地告诉 SVN 一声，这个动作叫 Add（新增 / 加入版本控制）。

◈未版本控制文件的右键菜单（灰问号）Unversioned File
未版本控制的文件，右键菜单很短——TortoiseSVN 几乎不管它。这里面最有用的就是两项：
Add...：把它纳入版本控制，这是本次操作的第一步；
Add to ignore list：把它忽略掉，以后不再出现在待提交列表里——编译产物、日志、本机配置就走这条路（第 16 节）。

记住这个二选一：新文件要么 Add，要么 Ignore，不要让它长期挂着灰问号。否则每次提交你都得重新判断一遍「这个要不要交」。
ADD把新文件纳入版本控制
先确认这文件确实该进仓库问自己一句：同事检出项目后，需要这个文件吗？需要就 Add；不需要（编译中间产物、本地数据库、临时导出）就 Ignore。这一秒的判断，决定了几百兆的仓库体积。
对着新文件点右键图标上是灰色问号，说明它还没被 SVN 管起来。如果右键菜单里根本看不到 TortoiseSVN 那一组，说明这个位置不在工作副本里——检查一下是不是放错文件夹了。
鼠标移到 TortoiseSVN 子菜单上展开后面的子菜单，找到 Add...。注意带不带省略号的区别：带 ... 的那项会弹出对话框让你挑文件；不带的那项按当前选择直接处理。
在弹出的 Add 对话框里勾选要加入的文件对话框会列出当前文件夹里所有还没被版本控制的文件，每项前面有勾选框。这是一次加入多个文件的入口——新写了一整个模块？在这里全部勾上，一次搞定，不用一个个右键。
点 OK 确认被选中的文件角标立刻从灰色问号变成蓝色加号。注意：变蓝只代表「已标记要加入」，文件还在你本地，仓库里还没有它。
提交一次，新文件才真正进仓库回项目文件夹右键 → SVN Commit...，在列表里确认这些新文件已勾选（它们的状态是 added），写好提交说明，点 OK。这一步做完，同事更新后才能看到你的新文件。
忘了 Add 会怎样？提交列表里根本不会出现这个文件，你会以为「提交成功了」，同事更新完却发现少东西。提交前用第 5 节的检查对话框扫一眼，就能提前发现漏网的文件。
提交时顺手 Add，少走一趟

懒得先右键 Add 再右键提交？在 SVN Commit... 对话框里勾上 Show unversioned files，那些还没纳入版本控制的新文件就会出现在列表里。在列表里勾选它们，再点 OK——提交和新增一次完成。文件多、新建了好几个的时候，这样最省事。

删除（Delete）：删文件也要走 SVN

这是新手最容易犯错的地方。在资源管理器里选中文件按 Delete，文件确实消失了——但对 SVN 来说，这只是「文件莫名其妙不见了」，它不会记录「有人删除了它」这件事。

✗ 按键盘 Delete 键删

文件从磁盘上消失了。SVN 那边显示的状态是 missing（文件不见了），不是「已删除」。

提交时它不会正常地作为「删除」提交，反而可能报错让你先处理；历史里查不到「谁在什么时候删的它」。

→ 等于偷偷摸摸扔掉一份档案，没人记录

✓ 用 TortoiseSVN → Delete

文件角标变成红色叉，SVN 明确知道「这个文件被标记删除了」。

提交后仓库里它才真正消失，并留下一条完整的删除记录（谁删的、什么时候、什么说明）；以后想找回，随时能从历史版本里翻出来。

→ 走的是正规流程，有据可查

DELETE干净地删除一个文件
对着要删的文件（或文件夹）点右键确认这个文件的角标是绿色对勾或红色叹号——说明它在版本控制里，这样删才有意义。
选 TortoiseSVN → Delete在子菜单里找 Delete。别和系统菜单里的项搞混了——认准在 TortoiseSVN 那一组里的那个。
确认对话框它会列出即将删除的文件清单。一次删多个文件时，在这里核对一遍是不是真的都要删。
提交，删除才真正生效此时文件在磁盘上已经不见了，但仓库里还在。必须提交一次，服务器上的这个文件才会消失，同事更新后才会跟着删掉。
删错了怎么办还没提交：对着包含它的文件夹右键 → TortoiseSVN → Revert...，文件会从仓库里恢复回来。
已经提交了：去 Show log 找到删除之前那个版本，看看能不能从历史里恢复（第 8、9 节）。所以删除类操作，提交前多想三秒是值得的。
关于「提交后还能不能找回」

能。这正是走 SVN 删除的价值所在——文件虽然在最新版本里没了，但它留在历史里。以后翻到删除之前的那个版本，还能看到它完整的内容。

反过来，用键盘 Delete 直接删、并且已经提交过的文件，虽然也可能在历史里找到，但那次「删除」在历史记录里是混乱的，别人查起来会一头雾水。

重命名（Rename）：千万别按 F2

和删除一样，重命名也有一个正确入口。用系统的方式改名，看结果好像「文件还是那个文件，只是名字变了」，但 SVN 看到的是两件事：一个旧文件被删了 + 一个新文件出现了。

RENAME正确地给文件改名
对着文件点右键 → TortoiseSVN → Rename...在子菜单里找 Rename...。不要按 F2，也不要用右键菜单里的系统「重命名」项。
在弹出的输入框里改名字改完确认。此时文件的旧名字消失、新名字上位，角标变成蓝色加号（表示这个新名字等着被加入）。
提交提交之后，仓库里才是真的改名完成。同事更新时，SVN 会知道「这是同一个文件改了名」而不是「删了一个加了一个」。
提交说明里写清楚为什么改改名尤其要写：「把 UserDao 改名为 UserRepository，因为拆分出接口」。同事在日志里只看到「文件没了、又多了个文件」，一句说明能救他半小时。已经用 F2 改错了怎么办？只要还没提交，用 TortoiseSVN → Revert... 把名字改回去，再用正确的方式重来一次就行。
系统 F2 改名 vs SVN Rename：事后查历史的真实差距

假设把 UserDao.java 改名为 UserRepository.java，半年后你查它的历史：

✗ 用 F2 改的名

历史里会看到两条互不相关的记录：

· UserDao.java —— 在某个版本被删除，之后一片空白

· UserRepository.java —— 在同一时间被新增，之前的历史是空的

→ 想知道「这个类以前长什么样」，你得先自己猜出它以前叫 UserDao，再去找那个已经被删掉的文件——如果对方改过三次名，基本就找不回来了

✓ 用 SVN Rename 改的名

历史是一条连续的线：

· UserRepository.java 的历史里，直接包含它叫 UserDao.java 时的那几十次提交

· 一眼能看出「在版本 20500 改名为现在这个名字」

· 用 TortoiseSVN → Blame... 逐行追责时，改名之前的每一行也照样能追到人

→ 一次改名换来的是「历史不断」，这就是全部区别

移动文件：用右键拖动

把文件从一个目录挪到另一个目录，是「删除 + 新增」的组合动作——同样有正确姿势。而且这个姿势藏在右键拖动里，很多人从来不知道。

◈右键拖动松手后的菜单Right-drag Menu
怎么调出这个菜单：用鼠标右键按住文件拖到目标文件夹上，松手时它就会弹出来。注意必须用右键拖——左键拖出来的是普通的「复制/移动到这里」菜单，没有 SVN 选项。

前三项才是本次操作的正主：
SVN Move versioned files here —— 移动到这儿（最常用）。
SVN Move and rename versioned files here —— 移动并改名。
SVN Copy versioned files here —— 复制一份到这儿（原文件保留）。

下面还有 SVN Add files to this WC（把文件加进这个工作副本）、SVN Export to here / SVN Export all to here（导出成不含版本信息的干净副本）。图片最下面那几项是 Windows 系统自己的菜单，不要点——用系统的方式挪文件，历史就断了，和本节开头说的问题一模一样。
MOVE把文件挪到别的目录
选中要移动的文件，用右键拖到目标文件夹上按住鼠标右键不放，把文件拖到目标文件夹图标上方再松开。拖的时候会有提示光标，松手就会弹菜单。
点 SVN Move versioned files here这是移动——原位置的文件会消失，目标位置出现。如果只是想留一份副本，选 SVN Copy versioned files here。
检查两边的状态，然后提交原位置应显示为已删除状态，目标位置应显示为已添加状态——但这两件事属于同一次「移动」操作，提交时会一起记进去。提交后移动才真正生效；移动大批文件时，先在提交对话框里核对一遍清单，确认没漏也没多。

操作正确菜单路径做错了会怎样
新增文件TortoiseSVN → Add...
或在提交对话框勾 Show unversioned files 后一起提交		不 Add 就提交：文件根本不会出现在提交列表里，你以为交上去了，同事更新后却找不到它
删除文件TortoiseSVN → Delete按键盘 Delete：状态变成 missing 而不是「已删除」，提交不干净，历史里也查不到「谁删的它」
重命名TortoiseSVN → Rename...按 F2 或右键系统「重命名」：SVN 记成「删一个 + 加一个」，历史从现在开始断掉，之前的修改记录再也追不到这个新名字上
移动文件右键拖动文件到目标文件夹 → SVN Move versioned files here用左键拖、或 Ctrl+X 剪切粘贴：同样被记成「删一个 + 加一个」，历史断裂，这个文件「以前长什么样」查不到
复制文件右键拖动文件到目标文件夹 → SVN Copy versioned files here用 Ctrl+C / Ctrl+V 粘贴：新文件是未版本控制的灰问号，得再走一次 Add，多一步不说，还容易漏
整个目录改名对着文件夹右键 → TortoiseSVN → Rename...用系统方式改目录名：目录里所有文件的历史一起断掉，影响面比改单个文件大得多

一眼认出「做错了」的信号
  • 提交列表里，同一个文件一个显示「已删除」、另一个显示「新增」，而你只是想给它改个名 → 说明用了系统方式
  • 状态列出现 missing → 用了键盘 Delete；文件角标长期是灰色问号 → 忘了 Add
  • 同事说「你交的东西我这儿没有」→ 八成有文件没 Add 就提交了
养成这几个习惯
  • 动文件（增、删、改名、挪位置）一律先右键看有没有 TortoiseSVN 那一组，有就走它，没有说明位置不对
  • 记住两条口诀：重命名走 Rename，删文件走 Delete
  • 移动、复制文件的唯一正确姿势是右键拖动
  • 这些操作做完都要提交——不提交等于没做（对同事而言）
最后一步永远是：提交

Add、Delete、Rename、Move 这四个操作都只是在本地打了个标记，它们改变的是「你打算对仓库做什么」，而不是仓库本身。

只有提交（SVN Commit）之后，这些改动才会真正生效。在此之前，你完全可以反悔：对着文件夹右键 → TortoiseSVN → Revert... 就能把这些标记全部撤掉，回到原样。

也正因为如此，一气呵成地做完「操作 + 提交」是好习惯：改完名字就提交，删完文件就提交，别攒着。攒到最后一起提交，一旦中途发现问题，你就分不清哪一处改动是干什么的了。

这一节的三句话

1. 新文件先 Add，不然提交列表里根本没它。

2. 删文件用 Delete、改名用 Rename，按下键盘的那一刻历史就断了。

3. 移动和复制，用右键拖。
