18svnserve 部署实战

第一步：创建仓库

bash建仓库
# 推荐目录规划
# /var/svn/            仓库根目录（svnserve -r 指向这里）
# /var/svn/repo        项目仓库
# /var/svn/backup      备份目录

sudo mkdir -p /var/svn
sudo svnadmin create /var/svn/repo

# 初始化标准结构（用 file:// 本地协议，无需服务）
svn mkdir file:///var/svn/repo/trunk \
          file:///var/svn/repo/branches \
          file:///var/svn/repo/tags \
          -m "建立标准目录结构"

# 权限：svnserve 通常以特定用户运行
sudo chown -R svn:svn /var/svn
sudo chmod -R 770 /var/svn

第二步：配置 svnserve.conf

最常见的坑：配置项前面有空格 → 整个仓库无法访问（实测确认）

svnserve.conf 的 ini 格式对前导空格极其敏感。 模板文件里所有配置项都是 # 注释 开头、前面带一个空格。 如果你只删掉 # 却留下了那个空格，配置解析会直接失败。

实测结果比「被忽略」更严重：svnserve 进程能正常启动、端口也处于监听状态， 但客户端一连接就报解析错误，整个仓库彻底无法访问：

实测报错
$ svn list svn://127.0.0.1/repo/trunk
svn: E170013: Unable to connect to a repository at URL 'svn://127.0.0.1/repo/trunk'
svn: E200002: Error while parsing config file: /var/svn/repo/conf/svnserve.conf:
svn: E200002: line 1: Option expected
↑ "Option expected" 就是「这一行不是合法的配置项」
  排查时看到这个错误，第一件事就是检查行首有没有多余空格
✗ 错误：行首有空格
 anon-access = none
 ↑ 前面有一个空格

svn: E200002: line 1: Option expected
→ 整个仓库无法访问
✓ 正确：顶格写
anon-access = none
 ↑ 从第 1 列开始，不留空格

配置生效，服务正常

快速自检命令： grep -n "^[[:space:]]\+[a-z-]\+ *=" conf/svnserve.conf —— 能匹配到任何行，就说明有配置项前面带了空格。

ini/var/svn/repo/conf/svnserve.conf
[general]
### 匿名用户权限：none / read / write
### 生产环境一律用 none，强制登录
anon-access = none

### 已认证用户的权限：read / write
auth-access = write

### 账号密码文件（相对 conf 目录，或写绝对路径）
password-db = passwd

### 权限控制文件（不写这行 = 所有登录用户都有全部权限！）
authz-db = authz

### 认证域名称，会出现在客户端的密码缓存里
### 不同仓库应设不同 realm，否则凭据会串用
realm = SVN Demo Repository

### 其他可选配置
# 强制要求客户端提供日志
# force-username-case = none
# 密码存储方式（默认明文，可用 sasl 加密）
# use-sasl = false

第三步：配置账号密码

ini/var/svn/repo/conf/passwd
[users]
# 格式：用户名 = 密码（明文）
alice = alice123
bob   = bob123
carol = carol123

### 注意：passwd 是明文的，必须保护好文件权限
### sudo chmod 600 /var/svn/repo/conf/passwd
### 且不要放在 Web 可访问的目录下

第四步：启动服务

bash启动与测试
# ---- 前台调试启动（第一次部署强烈建议这样）----
svnserve --foreground --root /var/svn --listen-port 3690
# 另开一个终端测试，有问题立刻能在这里看到报错

# ---- 后台守护进程（生产环境）----
svnserve --daemon --root /var/svn --listen-port 3690 \
         --log-file /var/log/svnserve.log \
         --pid-file /var/run/svnserve.pid

# ---- 指定监听地址（默认监听所有网卡 0.0.0.0）----
svnserve --daemon --root /var/svn --listen-host 192.168.1.10 --listen-port 3690

# ---- 测试连接 ----
svn list svn://127.0.0.1/repo --username alice --password alice123

# ---- 检查端口 ----
ss -tlnp | grep 3690
netstat -ano | findstr 3690          # Windows

# ---- 停止服务 ----
kill $(cat /var/run/svnserve.pid)
pkill svnserve                        # 简单粗暴
实测输出：启动并验证认证
PowerShell
# 启动（Windows 上--daemon 需要简写 -d）
$ svnserve -d -r E:\svn-demo --listen-port 3690

# 确认进程与端口
$ Get-Process svnserve | Select Id,ProcessName
  Id ProcessName
  -- -----------
27744 svnserve

$ netstat -ano | Select-String ':3690'
  TCP    0.0.0.0:3690    0.0.0.0:0    LISTENING    27744

# ---- 匿名访问：被拒绝（anon-access = none）----
$ svn list --non-interactive --no-auth-cache svn://127.0.0.1/repo
svn: E170001: Can't get password
↑ 服务器要求认证，但客户端没提供凭据

# ---- alice 认证：成功 ----
$ svn list --username alice --password alice123 --no-auth-cache svn://127.0.0.1/repo
branches/
tags/
trunk/

# ---- 错误密码：明确报错 ----
$ svn list --username alice --password WRONG --non-interactive svn://127.0.0.1/repo
svn: E170001: Authentication error from server: Password incorrect

第五步：注册为系统服务（生产环境必需）

Linux：systemd
ini/etc/systemd/system/svnserve.service
[Unit]
Description=Subversion protocol daemon
After=network.target

[Service]
Type=forking
# -d 守护模式, -r 仓库根目录
ExecStart=/usr/bin/svnserve --daemon \
  --root /var/svn \
  --pid-file /run/svnserve.pid
ExecStop=/bin/kill -TERM $MAINPID
Restart=on-failure
User=svn
Group=svn

[Install]
WantedBy=multi-user.target
bash启用
sudo systemctl daemon-reload
sudo systemctl enable svnserve
sudo systemctl start svnserve
sudo systemctl status svnserve
Windows：sc 注册服务
cmd注册为 Windows 服务
:: 注册（注意 daemon 模式在 Windows 上要加引号）
sc create svnserve binPath= "\"C:\Program Files\Subversion\bin\svnserve.exe\" --service -r E:\svn" displayname= "Subversion Server" depend= Tcpip start= auto

:: 启动
sc start svnserve

:: 查看状态
sc query svnserve

:: 删除服务
sc delete svnserve
注意 sc 的参数格式

sc 命令要求等号后面紧跟一个空格再跟值： binPath= "..." 正确，binPath="..." 会失败。

防火墙记得放行 3690
bash放行端口
# Linux (firewalld)
sudo firewall-cmd --permanent --add-port=3690/tcp
sudo firewall-cmd --reload

# Linux (ufw)
sudo ufw allow 3690/tcp

# Windows PowerShell（管理员）
New-NetFirewallRule -DisplayName "SVN Server" -Direction Inbound -Protocol TCP -LocalPort 3690 -Action Allow
