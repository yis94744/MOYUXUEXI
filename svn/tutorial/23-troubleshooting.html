23故障排查速查

这一节收录的都是实测踩过的真实错误，包含错误原文、根本原因和修复步骤。 遇到问题先在这里搜错误码。

◈图 23-1　错误码速查：错误码前缀决定排查方向Error Codes

工作副本类错误

错误原文原因修复
E155004
...is already locked
Run 'svn cleanup'		 工作副本被锁。常见于：上次操作被强制中断、进程崩溃、磁盘满 svn cleanup　—— 实测有效，一条命令解决。
如果 cleanup 也报错，检查是否还有 svn 进程在跑（Get-Process svn / ps aux | grep svn），杀掉后重试
E155015
Aborting commit:
'xxx' remains in conflict		 文件处于冲突状态（C），未调用 svn resolve 解决冲突内容后：
svn resolve --accept working 文件名
然后提交
E155010
The node 'xxx' was not found		 操作了不存在的路径。常见于 propset 一个已被忽略/不存在的目录 先用 svn status 确认路径真实存在；
被忽略的目录需先 svn add --no-ignore
E195020
Cannot merge into
mixed-revision working copy		 工作副本里不同节点处于不同版本（混合版本状态），merge 拒绝执行 svn update　—— 实测这一步就能解决，然后再 merge
E195006
'xxx' has local modifications --
commit or revert them first		 对已修改的文件执行 svn delete / switch 等操作 先 svn commit 或 svn revert；
确需强制操作加 --force
E155007
'xxx' is not a
working copy		 在非工作副本目录里执行了需要工作副本的命令 确认你在正确的目录（有 .svn 的地方）；
或用 URL 形式执行命令
E200009
Some targets are
inaccessible		 提交时某些文件不可访问（权限、被占用、路径过长） 检查文件是否被其他程序独占（比如 IDE、Excel 打开着）；
Windows 路径超 260 字符也可能触发
E155036
The working copy is too old
(format N; need at least M)		 工作副本格式比当前 SVN 客户端版本旧（比如从很老的 SVN 升级上来） 重新 svn checkout（最简单）；
或 svn upgrade（1.7+ 的旧工作副本可原地升级）
实测：E155004 与 E195020 的完整现场
PowerShell
# ===== E155004：工作副本被锁 =====
$ svn patch E:\my.patch
svn: E155004: 'E:\svn-demo\wc' is already locked.
svn: E155004: Run 'svn cleanup' to remove locks (type 'svn help cleanup' for details)

$ svn cleanup
<无输出 = 成功>
$ svn patch E:\my.patch
U         src\main.cs          ← 恢复正常

# ===== E195020：混合版本不能 merge =====
$ svn merge file:///E:/repo/branches/feature-login
svn: E195020: Cannot merge into mixed-revision working copy [6:7];
              try updating first
↑ 报错本身已经给出了解决方法："try updating first"

$ svn update
Updating '.':
At revision 7.                    ← 拉平成单一版本

$ svn merge file:///E:/repo/branches/feature-login
--- Merging r5 through r7 into '.':   ← 成功执行

服务端与钩子类错误

错误原文原因修复
E165001
Commit blocked by
pre-commit hook (exit code 1)		 钩子主动拒绝了本次提交。这是预期行为，不是故障 看错误信息里钩子输出的原因（with output: 后面的内容），按提示修改提交内容或日志
E165002
Failed to start
'xxx/pre-commit' hook		 钩子文件存在但无法执行 检查三点：① Linux 上是否有 chmod +x 执行权限； ② 首行 shebang 是否正确（#!/bin/sh）； ③ Windows 上是否是 .bat/.cmd 且为 ASCII 无 BOM 编码
E720005
Can't set process
'...' stdio pipes		 钩子进程无法建立标准输入输出管道。常见于受限环境（安全软件拦截、容器权限不足、Windows 上的权限策略） 本教程实测时就遇到了这个：Windows 沙箱阻止了子进程管道创建。 解决：给 svnserve / 钩子进程足够权限，或把 svnserve 换成 Windows 服务方式运行
E165006
Repository has not been
enabled to accept
revision propchanges		 尝试修改提交日志，但没有 pre-revprop-change 钩子 这是 SVN 的安全默认值。要允许修改就创建该钩子并 exit 0； 要禁止篡改就创建并 exit 1（见第 20 节）
E140001
Malformed dumpfile header		 dump 文件格式错误。PowerShell 重定向写成 UTF-16 是实测高发原因 改用 svnadmin dump --file xxx.dump；
核对文件头前几字节应为 53 56 4E 2D（"SVN-"）
E160013
File not found:
revision N, path '/x'		 在指定版本里该路径不存在。常见于 peg revision 用错 用 svn log -v 确认路径在不同版本下的实际名字（重命名前后）；
peg 语法：URL@PEG 配合 -r OP_REV
E160020
File already exists		 提交的路径已存在（比如建目录时名字重复） svn list 确认当前结构；换个名字或先删除已有路径
E200030
Transaction is out of date		 提交时事务已过期（你提交期间别人先提交了同一文件） svn update 后重新提交。这就是「先 update 再 commit」习惯的由来

网络与权限类错误

错误原文原因修复
E170001
Authentication error from
server: Password incorrect
或 Can't get password		 认证失败。后半句不同含义不同：
Password incorrect = 密码错；
Can't get password = 客户端没提供凭据（且不能交互）		 加 --username xxx --password xxx；
脚本里必须加 --non-interactive，否则会卡住等输入
E170001
Authorization failed		 认证通过了，但权限不足（authz 里没给你这个路径的权限） 用 svnauthz access --username X --path /y authz 查实际权限；
检查 authz 里 [path] 的路径基准是否写对（相对仓库根）
E220004
Access denied		 写操作被 authz 拒绝（比如往只读的 /tags 提交） 这是权限设计生效了。需要写权限就找管理员在 authz 里加对应组
E170013
Unable to connect to a
repository at URL		 连不上服务器。通常是网络/服务未启动/端口不通 逐步排查：
① 服务在跑吗 ps aux | grep svnserve；
② 端口通吗 telnet host 3690；
③ 防火墙放行了吗；
④ URL 拼写对吗（svn://host/repo，注意仓库名）
E730061
Can't connect to host		 TCP 层连接被拒绝（服务没监听、端口错、防火墙拦截） 同上一行。常见坑：svnserve 只监听了 127.0.0.1，外部连不上——用 --listen-host 0.0.0.0
E175002
HTTP 相关错误		 Apache 配置问题、SSL 证书问题、代理拦截 检查 Apache 的 error.log；确认 mod_dav_svn 已加载；
自签名证书需配置信任或加 --trust-server-cert
实测：认证与权限错误的精确区分
PowerShell
# ---- 1. 密码错误 ----
$ svn list --username alice --password WRONG --non-interactive svn://127.0.0.1/repo
svn: E170001: Authentication error from server: Password incorrect
↑ 关键字 "Password incorrect" —— 是密码问题，不是权限问题

# ---- 2. 没提供凭据（非交互模式）----
$ svn list --non-interactive --no-auth-cache svn://127.0.0.1/repo
svn: E170001: Can't get password
↑ 关键字 "Can't get password" —— 客户端没有凭据可用

# ---- 3. 权限不足（认证过了但没权限）----
$ svn list --username bob --password bob123 --non-interactive svn://127.0.0.1/repo
svn: E170001: Authorization failed
↑ 关键字 "Authorization failed" —— 是 authz 权限问题

# ---- 4. 写操作被拒 ----
$ svn mkdir --username bob --password bob123 svn://127.0.0.1/repo/tags/v2.0 -m "test"
svn: E220004: Access denied
↑ bob 对 /tags 只有读权限，写被拒

# ---- 5. 连不上服务 ----
$ svn list svn://127.0.0.1/repo
svn: E170013: Unable to connect to a repository at URL 'svn://127.0.0.1/repo'
svn: E730061: Can't connect to host '127.0.0.1': 由于目标计算机积极拒绝，无法连接。
↑ "积极拒绝" = 服务没在监听这个端口
「先 cleanup，再 update」—— 两条命令解决大部分问题

这不是玄学。绝大多数工作副本异常都是因为上一次操作被中断，留下了未清理的锁和中间状态。

bash万能恢复三步
# 第 1 步：清理锁和中间状态
svn cleanup

# 如果 cleanup 报错「还有进程在用」，先杀掉残留进程
# Linux:
pkill svn
# Windows:
Get-Process svn -ErrorAction SilentlyContinue | Stop-Process -Force
taskkill /F /IM TortoiseProc.exe     # 关掉卡住的 TortoiseSVN 对话框

# 第 2 步：重新同步
svn update

# 第 3 步：看状态是否正常
svn status
svn info

# ---- 如果还是不行，最后手段（会丢失本地未提交改动！）----
svn revert -R .                      # 撤销所有本地修改
svn cleanup
svn update
# 或者：删掉工作副本重新检出（最彻底）
svn checkout "$(svn info --show-item url)" wc-fresh
重新检出前，先抢救未提交的改动

删掉工作副本是不可逆的。执行前务必： ① svn status 看有没有未提交内容； ② svn diff --file rescue.patch 把改动存成补丁； ③ 把新文件（? 状态）复制到工作副本外面。

重新检出后再用 svn patch rescue.patch 把改动应用回来。
