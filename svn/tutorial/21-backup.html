21备份、恢复与仓库维护

版本库是团队的全部历史资产。备份没做好，一次磁盘故障就能让几个月的工作归零。 SVN 提供了三种备份方式，各有适用场景——用错方式比不备份更危险。

◈图 21-1　三种备份方式的差异与选型Backup
最危险的错误：用 cp / 复制粘贴「备份」正在使用的仓库

直接 cp -r /var/svn/repo /backup/ 或复制文件夹， 在仓库正被访问时可能复制到不一致的中间状态—— db/ 里的 rev 文件和 db/current 对不上， 恢复后仓库无法使用，修复代价极高。

唯一安全的手工复制方式是停服务后复制，或者用 svnadmin hotcopy （它会正确处理并发访问）。

方式一：hotcopy 完整热备

bashhotcopy 用法与自动备份脚本
# ---- 基础用法 ----
svnadmin hotcopy /var/svn/repo /backup/svn-repo-20261008

# ---- 如果目标已存在（重复备份同一个位置）----
svnadmin hotcopy /var/svn/repo /backup/repo --clean-logs

# ---- 自动备份脚本 ----
cat > /usr/local/bin/svn-backup.sh <<'EOF'
#!/bin/bash
set -euo pipefail

SVN_ROOT="/var/svn"
BACKUP_ROOT="/backup/svn"
KEEP_DAYS=30
DATE=$(date +%Y%m%d-%H%M%S)

mkdir -p "$BACKUP_ROOT"

for repo in "$SVN_ROOT"/*/; do
  name=$(basename "$repo")
  # 跳过非仓库目录
  [ -f "$repo/format" ] || continue

  dest="$BACKUP_ROOT/${name}-${DATE}"
  echo "[$(date -Iseconds)] backing up $name -> $dest"

  # hotcopy 热备
  svnadmin hotcopy "$repo" "$dest" --clean-logs

  # 打包压缩省空间
  tar czf "${dest}.tar.gz" -C "$BACKUP_ROOT" "$(basename "$dest")"
  rm -rf "$dest"

  echo "[$(date -Iseconds)] done: ${dest}.tar.gz ($(du -h "${dest}.tar.gz" | cut -f1))"
done

# 清理过期备份
find "$BACKUP_ROOT" -name "*.tar.gz" -mtime +${KEEP_DAYS} -delete
echo "[$(date -Iseconds)] cleanup: removed backups older than ${KEEP_DAYS} days"
EOF

chmod +x /usr/local/bin/svn-backup.sh

# ---- 加到 crontab，每天凌晨 2 点执行 ----
( crontab -l 2>/dev/null; echo "0 2 * * * /usr/local/bin/svn-backup.sh >> /var/log/svn-backup.log 2>&1" ) | crontab -

方式二：dump / load 逻辑备份（推荐）

实测踩坑：PowerShell 重定向会生成 UTF-16 文件导致 dump 损坏

在 PowerShell 里执行 svnadmin dump repo > backup.dump， PowerShell 会用 UTF-16 LE 编码写文件，文件头变成 FF FE FF FE 53 00...（BOM + 宽字符）， 结果 load 时报错：svnadmin: E140001: Malformed dumpfile header。

正确做法（任选其一）：

  • 用 svnadmin 内置参数：svnadmin dump repo --file backup.dump　← 推荐，跨平台一致
  • 用 cmd 的输入输出重定向：cmd /c "svnadmin dump repo > backup.dump"
  • 改用 Git Bash / WSL
实测：正确的 dump 与文件头核对
PowerShell
# ✗ 错误：PowerShell 的 > 重定向（会写成 UTF-16）
$ svnadmin dump E:\repo -r 1:3 --incremental > E:\inc.dump
$ cmd /c "svnadmin load E:\repo-restored < E:\inc.dump"
svnadmin: E140001: Malformed dumpfile header '?\FF?\FES'
↑ 文件头是 FF FE（UTF-16 BOM），SVN 解析不了

# ✓ 正确：用 --file 参数
$ svnadmin dump E:\repo -r 1:3 --incremental --file E:\inc.dump
* Dumped revision 1.
* Dumped revision 2.
* Dumped revision 3.

# 核对文件头（应该是 ASCII，不是 FF FE）
$ $bytes = [System.IO.File]::ReadAllBytes("E:\inc.dump")[0..7]
$ ($bytes | % { $_.ToString('X2') }) -join ' '
53 56 4E 2D 66 73 2D 64
↑ 53 56 4E 2D = "SVN-" 的 ASCII 编码，正确！

# 恢复到全新仓库
$ svnadmin create E:\repo-restored
$ cmd /c "svnadmin load E:\repo-restored < E:\inc.dump"
------- Committed revision 1 >>>
------- Committed revision 2 >>>
------- Committed revision 3 >>>

# 验证恢复结果
$ svn list -R file:///E:/repo-restored
branches/
tags/
trunk/
trunk/README.md
trunk/src/
trunk/src/main.cs
↑ 文件结构完整恢复
bashdump / load 完整操作集
# ============ 全量备份 ============
svnadmin dump /var/svn/repo --file /backup/full.dump
svnadmin dump /var/svn/repo --file /backup/full.dump --deltas   # 更小但恢复慢

# ============ 增量备份（推荐策略）============
# 第一次全量
svnadmin dump /var/svn/repo -r 1:1000 --incremental --file /backup/inc-0001-1000.dump

# 之后每次只备份新增部分（假设上次到 r1000）
svnadmin dump /var/svn/repo -r 1001:HEAD --incremental --file /backup/inc-1001-$(svnlook youngest /var/svn/repo).dump

# ============ 恢复：全量 ============
svnadmin create /var/svn/repo-new
svnadmin load /var/svn/repo-new --file /backup/full.dump

# ============ 恢复：全量 + 多个增量（必须按顺序！）============
svnadmin create /var/svn/repo-new
svnadmin load /var/svn/repo-new --file /backup/full.dump
for f in /backup/inc-*.dump; do
  echo "loading $f"
  svnadmin load /var/svn/repo-new --file "$f"
done

# ============ 恢复到指定版本 ============
svnadmin load /var/svn/repo-new --file /backup/full.dump \
  --revision 500:1000        # 只加载 r500-r1000

# ============ 过滤历史（去掉敏感文件）============
svnadmin dump /var/svn/repo --file /backup/filtered.dump
# 用 svndumpfilter 去掉某个目录的全部历史
svndumpfilter exclude /trunk/secret < /backup/full.dump > /backup/no-secret.dump
svndumpfilter include /trunk/src < /backup/full.dump > /backup/only-src.dump

# ============ 远程备份（无需登录服务器）============
svnrdump dump https://svn.example.com/repo --file /backup/remote.dump \
  --username backup-bot --password "$SVN_PASS"
svnrdump dump https://svn.example.com/repo -r 1001:HEAD --incremental \
  --file /backup/remote-inc.dump

# ============ 恢复时保留或改变 UUID ============
svnadmin load /var/svn/repo-new --file full.dump              # 默认保留原 UUID
svnadmin load /var/svn/repo-new --file full.dump --ignore-uuid  # 生成新 UUID
svnadmin setuuid /var/svn/repo-new <新uuid>                    # 事后改
备份策略建议（3-2-1 原则）
层次做法频率保留
本地热备hotcopy 到另一块磁盘每天7 天
逻辑备份dump --incremental 压缩后存储每天增量 + 每周全量30 天
异地备份备份文件同步到异地/云存储每周1 年

最重要的规则：备份必须做恢复演练。 没验证过能恢复的备份，等于没有备份。建议每季度做一次完整的恢复演练， 记录耗时，确认 RTO（恢复时间目标）能满足业务要求。

仓库维护与健康检查

bashsvnadmin 维护命令
# ---- 完整性与健康检查（定期跑，能提前发现磁盘问题）----
svnadmin verify /var/svn/repo
# 输出：* Verified revision 1.  * Verified revision 2.  ...

# 检查指定范围（大仓库全量太久时）
svnadmin verify /var/svn/repo -r 1000:HEAD

# ---- 查看仓库信息 ----
svnadmin info /var/svn/repo
# Path / UUID / Revisions / Repository Format
# Compatible With Version / Filesystem Type / FSFS Sharded

# ---- 查看某个版本占用的磁盘空间（找大版本）----
svnadmin rev-size /var/svn/repo -r 520
# 输出形如：   1542 bytes in revision 520
# 注意：-r 只接受【单个版本号】，不支持 1:HEAD 这样的区间

# 想扫描全部版本就得自己循环（配合 youngest 取最新版本号）
LAST=$(svnlook youngest /var/svn/repo)
for r in $(seq 1 $LAST); do
  printf "r%-6s %s\n" "$r" "$(svnadmin rev-size /var/svn/repo -r $r)"
done | sort -t' ' -k3 -rn | head -10
# 上面这段会列出占用空间最大的 10 个版本

# ---- 修改提交日志（需要 pre-revprop-change 钩子配合）----
svnadmin setlog /var/svn/repo -r 520 /path/to/newlog.txt
# 位置参数是【文件】，不是 -m 消息；想绕过钩子检查加 --bypass-hooks
svnadmin setlog --bypass-hooks /var/svn/repo -r 520 /path/to/newlog.txt

# ---- 整理仓库：删除无用数据、合并 rev 文件（大仓库定期做）----
svnadmin pack /var/svn/repo
# FSFS 会把多个小版本合并成一个大文件，减少文件数

# ---- 冻结仓库（打包迁移用，冻结期间不可写）----
svnadmin freeze /var/svn/repo -- tar czf /backup/frozen.tar.gz
svnadmin freeze /var/svn/repo -- rsync -av /var/svn/repo/ /backup/repo/

# ---- 查看未完成的事务（钩子崩溃后可能残留）----
svnadmin lstxns /var/svn/repo
svnadmin rmtxns /var/svn/repo "1-abc"          # 清理单个
svnadmin rmtxns /var/svn/repo $(svnadmin lstxns /var/svn/repo)  # 清理全部（小心！）

# ---- 灾难恢复：仓库损坏后尝试修复 ----
svnadmin recover /var/svn/repo
# 注意：recover 需要排他访问，建议先停服务

# ---- 升级仓库格式（换成新版 SVN 后）----
svnadmin upgrade /var/svn/repo

# ---- 查看 revision 属性的历史变更 ----
svnadmin dump-revprops /var/svn/repo --file revprops.dump
svnadmin list-dblogs /var/svn/repo        # 列出 Berkeley DB 日志（仅 bdb）
svnadmin list-unused-dblogs /var/svn/repo # 可安全删除的日志
