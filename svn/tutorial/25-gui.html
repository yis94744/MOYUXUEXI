25图形客户端与 IDE 集成

TortoiseSVN：Windows 上事实标准

TortoiseSVN 把 SVN 操作集成到资源管理器的右键菜单和图标覆盖上。 对不习惯命令行的用户，这是最友好的选择。

◈图 25-1　TortoiseSVN 图标覆盖与右键菜单对照GUI Mapping
对照表：左边每个图标颜色都对应第 7 节的 status 状态码。 学会看图标，就能在资源管理器里一眼扫出哪些文件需要处理，而不必打开命令行。
Windows
  • TortoiseSVN　右键集成，事实标准
  • VisualSVN（商业）　VS 插件
  • AnkhSVN　Visual Studio 开源插件
  • RapidSVN　跨平台独立客户端
macOS
  • Cornerstone（商业）　功能最全
  • Versions（商业）　界面简洁
  • SnailSVN　仿 TortoiseSVN 的 Finder 扩展
  • SmartSVN　跨平台，有免费版
Linux / 跨平台
  • RabbitVCS　Nautilus/Thunar 集成
  • SmartSVN　商业，跨三平台
  • kdesvn　KDE 环境
  • TortoiseGit 风格插件　IDE 内置

IDE 内置集成

IDESVN 支持方式说明
Visual Studio AnkhSVN / VisualSVN 插件
或 TortoiseSVN 右键		 AnkhSVN 开源免费，在解决方案资源管理器里直接显示状态图标。VisualSVN 是商业版，集成度更高。也可以完全不用插件，用 TortoiseSVN 的右键菜单操作。
IntelliJ IDEA
PyCharm / WebStorm		 内置（无需插件） JetBrains 全家桶原生支持 SVN。在 Settings → Version Control 里加 SVN 映射即可。 提交界面、diff、冲突解决工具都是内置的，体验很好。快捷键 Ctrl+K 提交、Ctrl+T 更新。
Eclipse Subclipse / Subversive 两个都是老牌插件。Subclipse 由 SVN 社区维护，Subversive 是 Eclipse 官方项目。现在 Eclipse 用户少了，但企业里仍有存量。
VS Code SVN 插件（第三方） 比如 johnstoncode.svn-scm。功能相对基础（状态显示、diff、提交），复杂操作还是得回命令行。 注意：VS Code 的插件用的是系统安装的 svn 命令，所以必须先装好命令行客户端。
Unity / Unreal 编辑器内置版本控制面板 Unity 的 Version Control 设置里选 Subversion 模式，能显示资源状态。 但真正提交还是建议用 TortoiseSVN 或命令行——编辑器面板容易漏提交 .meta、.asset 这类文件。
GUI 与命令行混用的一个注意事项

GUI 客户端和命令行操作的是同一个 .svn 工作副本，可以随意混用，不会冲突。 但要注意两点：

  • 不要在 GUI 操作进行中同时跑命令行—— 比如 TortoiseSVN 正在提交时，你在命令行执行 svn commit，会导致工作副本锁冲突（E155004）。 遇到就 svn cleanup。
  • GUI 的「刷新」不会自动—— 命令行改完后，TortoiseSVN 的图标覆盖可能还是旧状态，按 F5 或右键 → Refresh 才更新。
推荐的工具组合
Windows 开发团队
  • 命令行：SlikSVN（纯净，不进 PATH 干扰）
  • GUI：TortoiseSVN（勾选 command line tools）
  • IDE：IDEA / VS + AnkhSVN
  • 服务端：VisualSVN Server
Linux 开发团队
  • 命令行：apt install subversion
  • GUI：RabbitVCS 或 SmartSVN
  • IDE：IDEA（原生支持）
  • 服务端：svnserve + systemd
最后：一套完整团队协作约定（可直接抄）

把前面所有内容浓缩成一份可落地的团队规范。

项目约定
目录结构/trunk 主干 · /branches/<功能名> 功能分支 · /tags/v1.2.3 发布标签
分支命名feature-登录 / bugfix-1024 / hotfix-crash / release-2.0，一眼看出用途
提交日志[模块] 做了什么 + 为什么，至少 10 字；关联任务号写 [PROJ-123]
提交粒度一个完整的小功能一提交，别攒一整天；提交前必 svn update
分支生命功能分支 ≤ 2 周；每周至少一次 svn merge ^/trunk 反向同步
Tags 保护authz 里 [/tags] * = r，只有 admins 能写
忽略规则编译产物（bin obj node_modules）、IDE 配置（.vs .idea）、日志一律进 svn:ignore
二进制文件美术源文件（psd/max/fbx）设 svn:needs-lock，改前先 svn lock
换行符源码统一 svn:eol-style native，用 auto-props 自动设置
提交前检查① svn status 确认范围 ② svn diff 核对内容 ③ grep -rn "^<<<<<<<" . 确认无冲突标记
钩子强制pre-commit 检查日志规范 + 拦截编译产物；pre-revprop-change 保护历史不可篡改
备份策略每日 hotcopy + 每周增量 dump；每季度做一次恢复演练
